# 统一生产引擎接线验收草案

本阶段提交主干复审。生产入口、共享捕获接缝和支持域见 [API 草案](ENGINE_INTEGRATION_API_DRAFT.md)。验收对象 I 是待实现的统一生产会话，B 是用同一已验收组件和同一部署参数直接手工编排的薄基线。V+A、BC、VG、AO 和 TD 沿用各自已验收实现。S 维持精确 TD 展示。预登记的 B/B 计量资格在下一查询段超出 5%，正式协议冻结有待主干决议。

## 预先固定的单场景闭环

每例用一份 Blender scene、一份 view layer、同一移动对象和参考对象、显式遮挡网格清单，以及由该场景实采并拥有的 moving 世界米制参考。参考捕获单列冷成本，之后在正式前观察前复位到规定状态。主测都使用同一场景的同一对象 pair 完成以下次序。

1. 前观察从当前依赖图采集每个必要对象，原生 BC 求全局见证，TD 相对固定参考生成完整原值及精确 Top-K，VG 真实出图，返回前 AO bytes 和内存 PNG。
2. 调用者给出固定命令。生产路径仅预测该命令，按定义应用真实 Blender 写入，刷新两目标和受影响上下文，BC 重新求实际全局距离。用此回读直接生成后 TD、VG、联合 AO 及实测 Outcome。禁止为发布后观察另调用 `observe`。前后观察的 Blender frame 可相同，观察 ID 独立。
3. 对 L/R，实际消费者独立评分该次实际前、后 PNG，并在结果返回后提交与观察、附件及呈现方向绑定的反馈。L 的 A 从实际 Outcome 更新一次。基线与候选分别用自己的会话状态和实际输出。反馈后再发一个有新 ID 的下一查询，观察同一宿主场景真实状态并为预定后续命令预测，主序列不执行第二条命令。下一查询应可见更新的权重/库。

主案例的默认序列为 **before → predict → execute/after → feedback → next observe/predict**。独立预检可额外执行固定后续命令确认状态和标签。前、后、下一查询的确切帧、mode、命令及 ID 由夹具和运行清单事前给定。主场景的三次观察均使用该例已分配的 mode，正间隙 SECTION 保持正间隙。零距控制使用 NATURAL，另测请求 SECTION 时显式无图的策略，已达目标和空面无动作计划。

## 场景、分层和公开答案

主清单以 [夹具代码](../verification/integration_fixtures.py) 的族优先顺序固定，共 24 例。六个场景族为开阔尖端、单挡板、交错双翼、开槽鼓、内外双鼓和随动屏。每族四个固定变体，包含 NATURAL 正向平移、SECTION 正向相对 key、SECTION 反向平移和 NATURAL 反向相对 key。尺度为 .012/.035/.080/.150 m，初始 gap/尺度为 .004/.009/.015/.025，RNA 米/BU 规格为 1/.001/.001/1。平移用指定世界向量。shape 变体使用静态父级非均匀尺度、子级旋转及非均匀尺度形成一般 evaluated 世界线性矩阵。随动屏在同一真实动作后变化，参加前、后同次上下文采集。夹具的网格坐标、拓扑、父矩阵、作用幅度、Goal 和解析间隙均由代码固定。全部主样本进入报告，遮挡或成像困难不作为删样理由。

预登记清单逐例列出对象映射、代号、捕获掩码、动作和 Goal、三个观察的 frame/mode/ID、米制容差、部署及反馈来源。便携和原生控制独立列出运行规格与状态。第二轮完成了真非 Basis 相对 key、参考替换、静态/随动上下文、禁图、显式 `NONE`、上下文拓扑换代、单位变化以及计划和票据的生命周期检查。待运行的控制包括参考跟随、物理同尺度的单位重编码、目标三角行重排、零距打开间隙、零距 SECTION 无图、部署格式等价和完整的双会话交错学习/释放后重开。目标拓扑重排使用新会话、代号和匹配参考。同一位置的原三角行号按新索引重新核对。预检只取主序号 0/1/20 和固定控制，正式样本仍为全部 24 例。 [预登记清单](../artifacts/integration/preflight_002/manifest.json)

公开消费者只读 schema、AO bytes、PNG 附件和本题命令/Goal。应独立恢复目标身份、帧/代、真实 witness 原面及米制坐标、TD 范围和原始 Top-K、前后控制回读、预测和实测 delta、图像/相机/剖切及关联关系。PNG 通过现有公开读法及独立 RGBA/相机/几何证据校验。没有图片时 `image=null` 与公开状态一致。评估消费者可以有审计几何 oracle，实际消费入口只靠公开结果和附件。程序走过测试私有对象不代替生产入口可达。独立后台 Blender 示例必须以显式场景、对象、参考、部署和命令跑完一条实际链，再由公开消费者读取返回。

## B 的公平性和 I 的等价门

B 用既有 `BlenderControl` 的唯一 bridge/index 走原生目标捕获和实际写入。验证侧薄覆盖把非目标网格加入同一 graph，并在动作真实目标回读后直接发布。I 可采用冻结后的最小共享捕获接缝，B 可继续采用等价的薄覆盖。下面每项在两臂承担相同责任。 [手工基线](../verification/integration_reference.py)

| 责任 | B 和 I 的计费工作 |
| --- | --- |
| 捕获和换代 | 每阶段按清单显式提供全对象的 `NONE` 或变更掩码。同一 graph 中先采移动和参考目标，再按稳定顺序采上下文。上下文 `TOPOLOGY` 与新代号成对，成功捕获该对象时生效。预测及反馈阶段没有采集。 |
| 观察和图像 | 产出同样的米制见证、完整 TD 原值与精确 Top-K、AO bytes 和按 mode 需要的 PNG。禁图和无可用图像返回同一公开状态。 |
| 命令和所有权 | 相同准备、真实 setter、目标回读与失败边界。可同样预建静态 relative basis，独立计入参考捕获。复用已有前 PNG，只保留联合发布必需的一份前 moving 世界米制坐标。 |
| 计划和学习 | 生成并校验相同作用域和生命周期的计划、V/A 一次性票据。使用相同模型、特征、绑定、反馈输入、参数/库更新及发布责任。下一查询用同一臂实际更新后的活动模型。 |

F/G、R/G 与部署组合 L 分别报告质量。F 是 active 固定访问次序，G 是当前见证三角对的真实有限动作几何预测。性能主对照两侧都使用部署组合 L，视角用 L，显式平移用 G，shape key 用学习 A，按实际责任更新对应经验。

I/B 的必须相等项目如下。

- 每个前观察、动作后真实 readback、下一观察的目标与上下文 RB 采集次数和图状态。对预定变更轨迹，一个目标每次采集至多一次，无第二份目标 bridge/index。主闭环的 BC 查询分别为前观察、动作实际回读、下一次明确观察各一次。VG 为相机取 graph 独立计数，不能借它重复采集网格。
- 公开对象 ID/顺序、拓扑代、参考/采样/位置帧、见证原三角行、世界米制事实、原始 TD/Top-K、明确命令、实际前后 q 或世界平移、实测与预测 delta 及 Goal 结果。原始参考及前 AO bytes 在下一状态后仍正确。真值使用独立 RNA 矩阵/网格读取及解析/独立几何计算。解析夹具以生成器的 `host_tolerance_m=64 eps32×L` 核对世界米尺度。完全相同评估网格的 BC 数值使用既有 `tau(P)`，delta 用前后预算之和。TD 沿既有 `rtol=atol=1e-11` 回归口径。公开事实由同一算术形成时比较精确数值与字节，数值预算只用于独立真值对照。
- 规范候选访问次序、逐调用 ray、选中方向、实际渲染绑定与剖切。相同硬件与场景配置要求 PNG 逐字节一致。VG 资源内部自动相机名称可在私有 metadata 中不同，该字段不属于公开 AO。若目标平台已确认仅 PNG 无损编码字节不同，主干须在正式测量前固定例外和独立 RGBA 比较；预设默认仍是字节一致。B 成功例不丢失，所有主案例均报告实际像素质量。遮挡、零距和空面有独立 oracle 控制。
- 导入既有模型的数据、初始训练统计/库、每次推理输入、实际更新前后权重、写入计数、环槽、方向 mask 与 A 残差。R 保持未观测方向为 unknown，实际方向、ray 计数和动作标签不得从预测伪造。冷加载模型的参数由离线导出器逐字段核对。两个实例同源启动时初始相等，交错学习后各自独立。释放后无旧索引、相机、GPU 和会话引用残留。

## 成本与统计建议

同一机器上依次启动三个独立 Blender 进程。每进程显式加载三个原冻结部署中的一个，使用相同软件、设备、1 个 Blender 线程与 1 个 BLAS/OMP 线程。每例 5 次 B/I 成对预热，再做 31 次 B/I 配对。臂次序按 `(process_index + case_ordinal + repeat_index) % 2` 轮换。重复间在计时外还原宿主真实通道、参考和试验模型初值。平移夹具恢复原始 Blender `location`、`rotation_euler`、`scale`，shape 恢复实际初始 key 值。验证侧用固定 240 行快照恢复权重、库与游标，实际采集和依赖图求值进入计时。一次闭环中的反馈更新本臂活动模型，下一查询立刻读取同一状态。重复测量不增加样本数。

每次连续区间记录以下边界，所有必要结果物化和真实 I/O 操作计入。

| 边界 | 包含 |
| --- | --- |
| `t0→t1` 前观察 | 当前宿主求值及 RB/BC/TD、CF、VG GPU 同步读回和 PNG、AO bytes、附件与 V 票据 |
| `t1→t2` 动作 | 当前控制 q/有限基读取和预测、计划校验及消费、必要 before 所有权复制、真实宿主写入/求值/回读、后 TD/VG/PNG、联合 AO 和动作票据 |
| `t2→t3` 反馈 | 实际可用的两张 V 票据及适用时的 A 票据的校验、消费和更新，参数/库写入及必要复制 |
| `t3→t4` 下一查询 | 下一次原生公开观察和明确后续命令预测，使用更新状态 |
| `t0→t4` 完整服务 | 上述四段的同一次连续区间，不能用多个统计量相加 |

正式服务计时通过已经独立评分、且绑定相同 PNG bytes、观察及方向的真实标签做确定性复放。预取归档标签和核对 PNG、方向、规范候选、ray 等身份在区间外。票据入口的检查、消费、真实参数和经验库更新在区间内。真实消费者闭环另计外部读档、评分和等待，报告从实际前观察到真实反馈后下一查询结束的全段及分项。GPU 同步读回、画面压缩和 AO 物化属于两者的实际成本。审计图读回、独立 oracle 和归档写盘另列。

每例每臂取 31 次中位，对每进程 24 个主案例中位求 `linear` p95，I/B 的前观察、动作、反馈、下一查询和完整服务逐进程各 **≤1.05**。保留三进程原始时序、重复次序、逐例差、绝对 p95、p95 差和配对差 p95。另报告 pooled、各族和最差例。现有门按进程汇总。

### 计量资格和资源观测

B/B 探针先用两个独立 B 会话跑预登记的开阔尖端 0/1 和随动屏 0，只用 seed 20261105。两臂按同一规则交替，沿相同五段测量。在正式门的统计口径下，每段 `max(p95_a/p95_b, p95_b/p95_a)` 都须 ≤1.05 才通过该探针。记录单调时钟实现、分辨率及空测量，原始计时保持实测值。资格失败后任何补测、设备配置或统计方法变更都先交主干事前登记。

资源拟分为托管内存及 OS/驱动两个独立实验，B/I 每臂每 seed 分别用新进程，固定设备及相同案例顺序。核对导入后冷点、模型加载、参考建立及替换、同样输出仍被调用者持有的完整热态闭环、票据消费且输出释放后、关闭及重开。异常释放和拓扑重建另外记录。

- 托管实验在导入后、创建模型与会话前开始 `tracemalloc`，记录分点 current 和重置 peak 后的热段峰值。遍历 bridge/index、参考、模型库、渲染资源、临时值和调用者持有的输出，沿 NumPy `.base` 与 `.obj` 找实际 owner，按归属去重记录 buffer 数和字节。两个臂均计前 moving 快照。owner 字节用于归因，和托管跟踪值分别报告以避免重计。建议热态常驻差 ≤256 KiB，额外峰值 ≤1 MiB。
- OS/驱动实验拟用同进程 Win32 `WorkingSetSize` 与 DXGI `QueryVideoMemoryInfo` 的 LOCAL/NON_LOCAL `CurrentUsage`，固定适配器 LUID 和 node。进程级 `PeakWorkingSetSize` 用于诊断。正式峰值拟使用带实际时间戳的同窗采样和阶段读数，先验证约 2 ms 采样可达性并记录最大间隔。若当前采样无法覆盖短峰，需由主干事前固定采样峰定义或批准 PID/LUID 可归因的 ETW VidMm 方案。资源探针只证明分点可读取。建议额外 RSS 和 GPU 分别 ≤8 MiB，LOCAL 与 NON_LOCAL 分开列出并在冻结前固定 GPU 上限的比较对象。 [Win32 进程读数](https://learn.microsoft.com/en-us/windows/win32/api/psapi/nf-psapi-getprocessmemoryinfo) · [DXGI 查询](https://learn.microsoft.com/en-us/windows/win32/api/dxgi1_4/nf-dxgi1_4-idxgiadapter3-queryvideomemoryinfo) · [DXGI 读数字段](https://learn.microsoft.com/en-us/windows/win32/api/dxgi1_4/ns-dxgi1_4-dxgi_query_video_memory_info)

## 既有 CF 质量和成本回归

用现有三个封存部署与原始 V/A 清单做重放，选模及标签来源仍使用已归档数据。V 重放原 60 场景×3 seed 的原 F/R/L 方向、原生计数及真实 PNG。A 重放原 60 场景×3 seed 的合法当前命令、C/G 对照及实际 Outcome。原 L 射线比、逐例 PNG 保留、逐族成功率及 A 米制 MAE 继续适用。R 首 seed 既有失败应如实复现。单场景主试验中的新遮挡/动作族不替代该回归，也不算新未见收益证据。

按原 CF 计时边界另测同一进程内的 V 任务接独立 A 任务，仍按各 seed V、A 和原 total 的 **≤1.10** 判定。动作成本参考仍为冻结 G。保留原配对原样本及机制，本次同场景 1.05 门是另外的同功能编排成本对照。不得把旧两个场景的 58 ms 和当前同一场景的结果当成可直接比较的提速。控制器、生产入口和普通数组包导入按实际修改范围进行接口回归，依赖模块旧优化无需重做。

## 冻结、异常与交付

主干冻结前核对逐阶段清单、实际部署快照、参考捕获与所有权、故障和图像状态、已知 B 负样本、B/B 资格及资源门。每次进程留存实际命令和环境、逐输入 SHA-256、包含验证侧脏文件和未跟踪模块的源码字节归档、实际加载模块回执、设备/线程、原始公开结果及计时。附输入清单按阶段指向冻结的依赖档案和旧评分记录。启动前后核对输入和源码，实际加载路径及摘要与归档对账。失败保留当时源码与原数据。涉及冻结输入、范围、统计或计量的补测，先报告精确影响，由主干事前固定。 [预检证据索引](../artifacts/integration/preflight_002/README.md)
