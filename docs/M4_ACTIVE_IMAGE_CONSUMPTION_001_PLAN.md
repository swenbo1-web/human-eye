## 最小实现

复用已跑通的CLI启动、MCP协议、预授权配置和事件归档；新批只改必需的图像处理与真实计量。旧连续消费driver在 `verification/m4_surface_scan_continuous_consumption_002/runtime/driver.py`；实际actor与transport来自 `verification/m4_surface_scan_continuity_001_fix1/runtime/`，当前强制零图/拒图，不能原样宣称具备图像能力。

用一个公共函数读PNG并构造标准 `image` content block（正确MIME、base64实际字节）。原生路径使用普通读取已有图片的入口，插件路径使用主动观察实验适配器的图片出口；两路最后调用同一函数。保留原生Python工具已有语义，不偷偷把text工具改成另一个专用求解器。若需要增加通用read-image helper，两路都可使用并明确列在schema中。不要重做评测平台或新增调度、权限、缓存层。

现有 `stdio_attach.py` 的JSON透传和TX/RX归档可复用。产品多图路径目前有384像素约束，本批512图片用最小实验helper原字节传递，不为资格修改产品上限或导入整个router。若本批不启动Blender，就不挂一个实际缺少bpy却名为execute_blender_code的假入口；可保留已有通用Python读取能力，并准确标明接口。

本批仅回放两张封存图片来验证交付，不调用003覆盖runtime，不把适配器说成默认插件已安装的新能力。公开schema/示例与封装源码一并冻结，之后正式扫视消费才可复用。
