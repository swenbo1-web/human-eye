# M4-ACTIVE-OBSERVATION-PATCH-OWNERSHIP-001

目标：让主动观察识别同一网格里的多个平面矩形区域，并正确处理同对象的遮挡与像素归属。用户得到的是可以实际观察的面片，而不再要求每个对象本身就是一张矩形。

固定基线 `cdd2b11693a2586cfea07528c6bca27b93d02499`。实施沿现有 `codex/architecture-arm-correction`，交付目录 `verification/m4_active_observation_patch_ownership_001/`。brief 批已独立通过，不继续压短字段。

## 已证缺口与本批范围

当前 `active_observation.py::regions_from_objects` 只检查整个对象；`build_index_from_parsed` 跳过同对象全部三角形；`active_observation_images.py::_pixel_rows` 以整个对象的可见像素给 ROI 记功。在旧场景中 28 个对象只有 6 个成为 ROI，22 个箱形对象只参与遮挡。只放开多 ROI 会让同物体另一面的像素错误证明被挡面已观察。

本批只解决这一整对象假设。范围包括发现、遮挡、同一次栅格的面片归属、现有 Host/brief 交付及相应范围说明。继续使用现有六个 512px 正交视角与 16/4/24 像素准则；不扩曲面拟合、容差吸附、纹理缺陷、任意多边形、相机搜索、专家模型或写操作。

## 单一实现方向

1. **一次建立面邻接并提取最大平面连通片。** 利用已有完整解析的 vertices/faces，按共享边建立邻接，在精确共面条件下分组，再复用矩形边界、绕序和面积证明。保留原 object/triangle 索引。优先 O(T+E) 的邻接遍历和按组复用平面量，避免三角形两两比较、每个候选重复解析全网格。不能把错绕序拆开后当两个合法片，或把孔、非矩形、非流形部分补成矩形。
2. **遮挡跳过 ROI 自身三角形。** 同对象的其他面仍是遮挡者。沿用全场景投影、包围框和精确阴影判断，不为同对象另造一套求解器。区域 ID 继续来源于规范几何；对象名、枚举顺序和合法重三角化不应改变同一面片的几何身份。场景分组或来源改变仍改变对应来源绑定。
3. **同一 depth winner 附带区域归属。** 优先用按稳定 ROI 顺序的 patch-owner 与 face→patch 映射，在现有深度更新点同步写入，保留原 object owner 接口。不增加第二次光栅、不改 RGB/深度计算、不用换色标记伪造可读边界。需要时的一张 int32 面缓冲在 512px 下约 1 MiB，实际数组、缓存和 NPZ 成本照计。保存/加载帧绑定区域顺序和映射版本。现有几何/mesh-order 身份忽略面序，不能用会随面序变化的 triangle-owner 而继续无条件复用旧缓冲；如果实现选择 primitive 标识，必须额外绑定实际面映射。
4. **每帧一次聚合。** 由真实获胜面映射到 ROI，统一计算区域表面像素和对比边界，再生成每个 ROI 的行。使用共享边界图、整型映射/直方图等直接数组算法，避免每个 ROI 重新扫描整张图片。同对象不同面可能形成真实明暗边界；同一平面内部三角缝不能凭不同 triangle ID 获得可读性。背景和不支持面仍参与遮挡。
5. **交付部分支持范围。** 对象有一个合法面不等于整个对象已支持。现有 brief/full 应可表达每个部分支持对象的支持/未支持三角形数量及原因/范围，所有计数有完整几何分母；零 ROI 对象保留。必要时扩展版本化 brief 合同，不能因为 scope 新字段触发整项回退 full 而悄悄失去刚取得的交付收益。模型不需要读取逐三角形清单，完整映射保留在内部/full 证据。

具体数据结构由实施者在上述目标下选择最小实现，避免新增通用框架或服务层。已有来源、图片计费和真实执行状态接口直接复用。

## 冻结一个有区分力的场景对照

沿用上一 Host 批可精确表示的完整复杂遮挡场景，保留原世界几何、三角形和相机生成规则，构造 **分对象** 与 **合为同一网格** 两种表示。这是夹具表示变化，用户任务是发现可观察面和遮挡，不能把合并操作本身算成任务收益。只允许在自有临时 QA 副本构造。

首次候选执行前冻结两份输入、来源、预期平面片/三角形映射和相机政策。至少固定三个有解析答案的检查点：一个能读的前面、同一物体中被前面以正深度差完全挡住的前向后面、因背向或有限视角池而仍不可读的面。前者须有自身像素，完全遮挡的后者须为零；不选等深度争用作为证据。预期来自构造几何/独立求交，不由候选 ROI 列表反推；不把 ROI ID、答案或可见矩阵送给产品。

如果原场景没有部分支持余量，可在冻结前一次性增加一个明确非矩形组件，原场景全部保留，两种表示同样加入。使 joined 对象同时有合法片和不支持余量，并在真实入口验证后者仍公开为 unknown、参与遮挡。不得在候选执行后反复调整几何寻找通过样本。

两种表示保持世界顶点、三角形绕序及绘制顺序；相同视角下 RGB/depth 应保持，owner 的对象编号可变，区域归属应按规范面几何一致。若重组使源绑定变化，这是正确行为，不能复用旧场景回执。新增可观察面数量在冻结时由夹具几何预登记，不看运行结果改题。

另用小型纯几何/既有缓冲用例覆盖部分支持余量、孔/非矩形、错绕序、退化、非共面、对象与三角形重排、合法细分。域外部分保留 unknown，不因此拒绝独立合法片，也不能把局部支持说成全物体覆盖。无需为这些用例新增光栅。

## 验收顺序与优化停止条件

1. **旧缺口与新能力。** 固定旧版对合并网格缺失 ROI 的源码/定向结果；新版两种表示的规范区域集合、区域三角形集合、每视角几何遮挡判断保持一致。检查同对象遮挡实际进入判断。解析参考只评判注册范围，不拿有限池结论声称任意视角无解。
2. **像素独立核对。** 对实际新帧的 RGB/depth/primitive owner，独立脚本从保存的原件求区域计数及边界；对预登记检查点用独立几何求交/解析可见性复核。必须证明可见的同物体前面不会给被挡后面贡献像素，合法细分不增加假边界。保留完整负面行以及有限池 unknown。
3. **一次明确优化核对。** 优化候选直接采用共享聚合结构；用简单逐 ROI 的正确参考只处理相同已存缓冲。固定五次配对计时与逐项相等比较，记录中位数、总量、尾部和每次原值；参考及优化调用数分列，不新增光栅。这是满足本模块至少一次算法优化的验证，不再开第二轮参数搜索。未形成净收益则如实列出原因，不延长采样刷过。
4. **实际安装入口。** 固定同一源码/wheel/依赖，隔离安装后通过真实独占 Blender capture→现有 service→MCP stdio→本地消费者完成两种表示。每种表示一次冷观察、一次同源热请求；另对一次当前缓存请求 full 核诊断，不额外渲染。记录完整 TX/RX、brief 原文、图片、来源、缓存与构造计数。默认 brief 必须仍可直接读取，不能只在纯函数测试通过。
5. **受影响回归。** 旧单矩形发现、已有所有对象遮挡、帧保存后回读、旧 owner 调用兼容、默认/brief/full、无支持区域和图片编码失败保留成本。复用已有 mock/历史原件；不重跑无关全仓矩阵，不把旧版只有 6 个 ROI 的场景输出要求为新版仍只有 6 个。

正式新光栅计划两种表示各最多六张，共 ≤12 张；同源/full 请求复用，不产生新图。全批硬上限 14 次真实新光栅尝试（包括定向测试和失败），预留 2 次可恢复接线故障；每次尝试即入账。若资源不足以完成原验收，回报实际缺口，不降低尺寸、阈值、scope 或删除失败。提前通过无光栅连接/路径检查解决可预测 harness 错误。

记录新增面缓冲内存、内部数组与缓存、交付文本/图片、完整调用次数、capture/parse/partition/index/raster/aggregate/publish/stdio 至消费者时界及安装准备成本。阶段嵌套不相加，未测 RSS、模型 tokens/费用留未测。新版多处理的面需要单列，不能拿更小旧能力作虚假同质量性能对比。
