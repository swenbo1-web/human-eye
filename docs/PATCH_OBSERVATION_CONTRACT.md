# M1-03 问题区域观察：来源与参考验收合同

2026-10-31 首批为来源核验、独立视觉参考和候选预算登记，**没有实现或安装新的自动取景能力**。运行源码保持九类结构候选 `bff353a36c499effc00d7c056a6270017bacf9962a78d7a67126d456074cecb2`，正式安装仍为22fb。排期以[唯一主计划](PRODUCT_ROADMAP.md)为准。

## 1. 要解决的任务

输入应是M1-02产生的来源绑定问题区域，不是物体中心。第一批图像任务选择静态网格中的有限边界组件，目标是补充该区域的自然外观证据，不从合法开口推断裂口损伤。重复位置、重复面等结构事实不一定能从自然图片分辨，不应为了覆盖九个类别而固定加图。

原始诊断、全场景渲染来源、自然可见、实际图片有用是四个不同条件；其中一个通过不代表其余通过。首批仅证明XY正交、固定不透明Workbench场景中的机会，不宣布任意视角/材质或真实复杂资产通过。

## 2. 实际来源边界

39个已冻结结构夹具在新factory Blender中分别只有目标、再加入参考网格读取；没有为生产接口伪造参考对象。

| 检查 | 实测结果 | 对新入口的影响 |
| --- | --- | --- |
| raw结构读取 | 39/39可读，partial按既有语义保留 | 文字事实继续可用 |
| 只有目标的原生采集 | 34/39可读 | 底层部分来源已可复用 |
| 单对象进入现有图像consumer | 0/39接受；34个可读来源被至少2对象约束拒绝 | 需要独立单对象协议，不能填一个假reference |
| 加入真实参考网格后的consumer | 34/39接受 | 说明部分阻断在接口，而非所有原始网格无法渲染 |
| 空网格/纯顶点等5个来源 | 无有效求值三角形而拒绝自然图 | 不删对象或修补几何来换通过；保留文字及图片不可用原因 |
| 非均匀变换、曲线遮挡物、空背景网格 | raw目标可读，但旧原生链拒绝 | 初版图片域取当前可靠交集，不能放宽刚体执行准入 |
| 遮挡物`hide_render`切换 | 现有capture/native revision均未变化 | 新图片来源必须另绑定渲染可见性，几何摘要不足以证明显示状态一致 |

最后一项是当前几何版本的范围限制，不代表此前的几何身份或全部图片都无效。新入口需同时绑定对象/数据块世代、raw摘要、完整原生几何与渲染可见性/固定显示策略；只读场景锁内核对前后状态。未知遮挡物不能被静默省略。

## 3. 独立图像真值

6个固定解析场景使用带偏心矩形孔的开放蓝色平面环；内边界是原始4条边组成的完整组件，外边界单独成组。孔不是算法凭空标注的图形。12个内边界采样点按四条边的1/4、1/2、3/4位置固定；前景不透明矩形的投影包含关系给出可见性真值，不使用候选射线结果自评。

像素门在渲染前冻结：孔较小投影宽度≥16像素，至少8/12个边界两侧采样对有明确蓝色/非蓝色对比；采样距边界各3像素。该颜色规则只适用于受控蓝色资产，不能推广为通用分割或模型理解率。全景已经满足时，不因局部图更大就认定需要加图。

3个新进程、每进程6场景；真实旧只读原生入口及consumer照常执行，再单独用oracle指定局部相机作参考。参考窗口**不由新算法自动选择**；负例强制渲染只为检验无收益，不是产品应增加图片。

| 场景 | 旧入口图片数 | 参考局部边界对 | 未来应加图 |
| --- | ---: | ---: | --- |
| 小孔无遮挡 | 2 | 12/12 | 是 |
| 物体中心被挡，问题可见 | 1 | 12/12 | 是，防漏掉机会 |
| 问题中心被挡，边缘可见 | 2 | 10/12 | 是，不能只看中心 |
| 物体可见，问题被挡 | 2 | 0/12 | 否，防无效加图 |
| 完全遮挡 | 1 | 0/12 | 否 |
| 全景已经可读 | 1 | 12/12 | 否 |

三个小孔正例，全景孔宽约0.12像素；有旧局部图时约1.92像素；oracle问题窗口约48像素。问题中心遮挡时仍有10组边界对可读。两个遮挡负例即使放大至48像素，仍是0组；“包围框变大”不等于证据增加。18次场景重复均符合预登记期待；尚未测试新自动选择器。

## 4. 冷/热成本与工作预算

旧路径包含全景和可选物体局部图、消费验证，参考路径只包含新鲜采集、固定参考窗口、单帧渲染及PNG清理；禁止直接用二者耗时比宣传加速。初始参考位于旧渲染之后，属于热态。另登记6个独立进程，每场景先渲染参考窗口，再重复两次，分开保留首次与热态，未覆盖原记录。

每场景1次首次、5次热态样本，仅为预算起点：首次约280.7–292.0毫秒，热态中位约19.1–21.7毫秒。按预登记公式，局部帧分段初值为参考经验p95＋max(20毫秒，参考p95的50%)；首次约421.1–438.1毫秒、热态约40.8–42.9毫秒。样本少，不能称为稳定尾延迟，也不含进程启动、结构诊断、自动候选搜索、完整传输和模型成本；完整观察及冷/热验收仍待对应入口实现。

候选明确上限：场景4096顶点/2048三角形/64对象，patch64成员，最多4个窗口候选，生产者与独立消费者**合计**8192次射线三角形检查；每调用最多2张384×384、PNG总计16MiB、原期限30秒。上述来源上限不保证每个输入都有足够射线预算；不足时必须明确未完成，不能让双方各花8192。旧V3的4096次门保持原样，新额度只适用于独立patch能力。

共有10个owned进程、63张原生图（旧路径27、参考18、补充冷/热18），全部正常退出。补充18张图与对应参考RGBA一致；观察前后几何和已声明渲染状态恢复。无用户GUI操作，无付费provider调用或正式模型试次。

## 5. 下一批实现合同

1. 新增独立单对象patch只读入口，不伪装为旧对象对query或V3计划。初版只接受新鲜诊断返回的完整有限边界patch：对象/数据块世代、raw摘要、类别、源索引及成员摘要全部核对。缺失/过期/被省略的组件不能伪造定位。
2. 独立绑定完整渲染来源和显示状态。初版采用已验静态表面与不透明默认显示域；隐藏、x-ray、show-in-front、不可读遮挡物等未验情况明确拒绝图片，文字事实保留。不得由图片准入改变写入权限。
3. 用问题区域构造有限候选并检查分布在边缘的见证点；中心射线、物体颜色面积或AABB尺寸都不能单独通过收益门。候选仍须记录实际检查范围、未知及原工作/时间预算。
4. 只选择能补充任务证据的窗口；采用前后核对实际RNA相机、来源、PNG及状态恢复，消费者独立验证。不得把本批oracle指定窗口直接包装成自动算法已过门。
