## P2：新geometry被公开到实际不支持的查询分支

`live_spatial_mcp.py` 将geometry放入通用 `_QUERY_SCHEMA.properties`，但未将其限制到具有target/candidates的task-set。以下请求按公布schema被允许，而真实 `validate_query` 及 `human_eye_scene_observe` 参数校验会拒绝：

```json
{"query":{"mode":"overview","geometry":{"objects":[{"id":"a"}]}},"include_image":false}
```

```json
{"query":{"mode":"task","objects":[{"id":"a"}],"requested_facts":["aabb"],"geometry":{"objects":[{"id":"a"}]}},"include_image":false}
```

合法task target/candidates及两项必需关系事实的控制请求，schema和runtime均接受。旧基线没有geometry属性，会拒绝上述两个不受支持请求；问题由本次新增字段引入。精简关系工具的正常路径不受影响，没有错误几何结论，但模型按公开协议构造参数会遭到拒单，应修正。

本环境未安装第三方jsonschema。本次用保存的真实schema明确求值三个输入实际经过的JSON Schema规则，未知关键词不静默跳过；runtime侧实际调用原校验函数。完整schema、逐案例结果和可复核脚本均已保存，未将自制定向规则求值器冒称完整标准验证器。

唯一修复范围：在通用schema增加“若有geometry，必须mode=task并含target/candidates”的条件，利用既有分支继续约束事实/objects。只修新字段，不扩大到所有历史宽schema，不增加运行时校验层或几何代码。
