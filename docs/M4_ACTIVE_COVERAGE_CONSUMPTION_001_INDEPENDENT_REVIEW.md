CLI把owner的 `content + isError=true` 表达为工具 `status=failed` 与 `content + structured_content=null`。内容并未损坏。现有matcher只接受成功，准备检查又把错误owner结果原样复制成CLI结果，没有覆盖真实投影及archive调用链。

还有同一边界的旁路：archive先接受result完全相等，再调用成功matcher。仅增加一个错误matcher的OR分支仍可能放过“正文相等但status与isError矛盾”。下一项应统一核业务状态、已知包络和完整content，成功与工具错误共用一处判断；不能通过丢弃isError或忽略所有failed来消除误判。

普通Python错误应保留为失败的工具调用，允许模型自行恢复；它与协议损坏、顶层流错误、动作状态不明是不同状态。此次不修改顶层重连策略或原正式门。
