# 045 独立复核　R3 更早找到最近点，却在证明结果时耗尽额度

**保留 032 作为默认内核。** 在一件通过普通 Blender 入口的合成网格上，032 能给出正确距离，原 R3 与 043 局部修正版均返回未知。G60 的正常业务与进程存活时间均通过事前性能门。两项结论分别成立。

## 普通入口的覆盖差异

两件网格各有 129 个三角形。对所有 16,641 对进行有理数核对，唯一最近的源面为 `[128,128]`，距离平方为 `3/32768 m²`，距离约为 9.568319 毫米。写文件与重新打开的 Blender 进程不同。三版收到相同请求，各做一次新查询。

| 实际普通入口 | 返回 | 三角对精算 | 投影排除 | 总工作 |
|---|---|---:|---:|---:|
| 032（A） | 精确距离与两见证点 | 1,918 | 14,723 | 406,421 |
| 原 R3（B） | 未知 | 16,384 | 0 | 862,254 |
| 043 局部修正版（C） | 未知 | 16,384 | 0 | 862,622 |

B、C 在需要第 16,385 次精算时触发 `surface_pair_budget`。两份真实回包都保留了拓扑，省略了距离与见证。两个版本在同一例上失去覆盖。043 的局部排序修正会改变队列顺序，但这项覆盖损失在原 R3 中已经存在。样本来自预算边界，真实资产发生率尚未测量。

## 独立找到的修复线索

从 B、C 的原始精算序列取前两对源面 `[127,128]` 和 `[128,128]`。对每对顶点从两侧验证支持平面条件，分别得到方向 `(3,1,-4)`、`(1,1,-2)`（已去掉共同正比例因子）。第二次精算已经得到最终最近点。查询在后续必须继续证明是否存在更近或规范顺序更早的等距面。

用已得到的最短距离作相同上界，对每个三角形的三个真实顶点求投影区间。若两区间间隔的平方严格大于“方向长度平方 × 当前距离平方”，则该对不可能成为答案。独立逐对计算的结果如下。

| 本案实际出现的方向 | 严格排除 | 投影下界恰等于已知上界 |
|---|---:|---:|
| 第二次精算的方向 | 0 / 16,641 | 129 |
| 第一次精算的方向 | 16,640 / 16,641 | 0 |

原 R3 的快整数路径随更好见证重置投影，构造时需至少 16 次已完成精算和足够的已结算信用。两条真实 R3 账本都只构造了一个方向。此时第一条斜向信息已被舍弃。最后一条方向能量出两最近点的间距，却看不到许多三角形在平面内彼此错开。032 到最后一次精算才找到该最近点，此前的投影实际排除了 14,723 对。

表中的 16,640 是离线证明能力，计算使用已取得的前一见证和当前真实上界。它没有扣生产检查、整数运算及缓存开销，也不预测实际会做多少次精算。值得验证的单项变更是有界地保留前一条有效见证方向，继续在当前上界下使用，并把产生的工作按原规则计费。
