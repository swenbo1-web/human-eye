# 新旧插件与原生三组实测复核 — COMPLEX-004

2026-11-10。本报告是规划/复核聊天的独立结果，作者执行日志位于实施工作树的 `verification/native_plugin_complex_004`。所有结果来自同一冻结批次，未替换失败样本。

**装配题上，新版相对原生保留了约一半的完整时间收益，但相对旧版没有体现明显提升。48 对象全场题暴露了更直接的问题：模型没有成功调用全场查询入口，优化过的求解路径没有参与答题。**

对照版本：N 为普通 Blender Python；O 为优化前 `d01d49bc0ec82583b24a8faf22e622e6f6ea8c5d` / `a50e34c9…7589b`；C 为当前已安装新版 `df016079b0265ee327f884c90dd4815c392016b6` / `3fc2651e…193bd`。两版同为 137 源文件，唯一运行源码变化是 `surface_proximity.py` 的整数快速路径，工具定义相同。

**实际失败链**

全场题的六个插件组会话中，五个尝试调用观察工具，五次均被参数校验拒绝；另一个直接使用原生工具。实际请求全部选了 `mode=task`，没有一次有效 `mode=surface_nearest` 调用。三个请求把 47 个候选放入最多支持三个显式候选的集合接口，另外两个使用了不符合 task 合同的参数。它们随后转向原生代码，没有获得插件几何结论。

独立目录核查确认，全场 `surface_nearest` 已公开且无模型预检能够正确使用它。问题不能描述成“功能隐藏”或“引擎只能处理三个对象”。同一工具定义承载八种模式；全局事实枚举、新集合分支和旧双对象分支存在不同组合规则。`nearest_witness` 是旧分支的合法请求项，也是新结果中的输出字段，却不是新集合分支可请求的事实。这与实际误请求相符，但尚未通过接口消融证明具体模型选择的因果。

全场九份原生计算中，七份首次完整计算产生伪交点。代码把极小非零行列式直接作为非平行条件，在病态除法后把伪参数接受为线段与三角形相交并返回零距离。四份通过后续重心坐标、残差或奇异矩阵检查发现问题，修正并重新计算全部 47 个候选；三份直接交付错误答案，恰好落在旧版组。

错误对象 `Near_017` 的独立冻结距离区间为 `[0.02599999995581631, 0.025999999955816387] m`，并不相交。真实全局最近对象是 `Peer_000`，区间为 `[0.0030000059049561864, 0.0030000059049562497] m`。错误不是候选遗漏，而是数值计算失效。新版组本轮全对不能归功于未执行的新版引擎；旧版组全错也不是旧版引擎返回了错误结果。

**测量与证据**

固定准备提交为 `fde3c2f2f21d4b7b454c8cd76e0a28de70ddb796`。两题为 4 个网格的旋转带孔装配和 48 个网格、2,880 个三角面的全场查询；同一题的几何、提示、场景对象目录、预算相同，三组顺序按预登记轮换。三组共用相同原生工具；O/C 额外暴露同一插件工具。模型统一请求 `gpt-6.1-sol` / `medium`，使用现有 ChatGPT 登录。图像预算为零，比较范围是文字与真实三维几何读取，不含视觉识别。每次模型期限 450 秒、最多 32 工具尝试、单次 30 秒、响应预算 1 MiB，无消费者补跑。

18 个会话均交付最终答案，独立几何验收为 15/18。评分先看匿名原文，再看匿名实际代码与返回，分别封存后揭盲。方法措辞仍可能暴露原生/插件路线，不能称为完美双盲。所有 62 次工具尝试、10 次工具错误和修正过程都入账；模型会话数不等于提供商实际请求数。

根复核另写小型后处理脚本，直接从 18 份原始 CONSUMER、事件流和公开 TX/RX 帧重算时间、usage、调用数与字节，与作者统计一致。共 98 个带 ID 的公开请求均有响应、18 个通知；实际公共发送 156,753 B、接收 322,127 B，其中工具响应 183,671 B、控制/目录响应 138,456 B。工具文本内容为 173,082 B。内部 Blender/插件 RPC、拟交付成本和这些公开帧分别记录，不能相加后称为模型输入 token。

装配 N/O/C 工具区间并集的中位耗时分别约 0.172/0.302/0.187 s；全场分别约 0.653/0.527/0.753 s。这些区间已包含在完整时间中，不再相加；也不是纯算法 CPU 基准。剩余时间含模型生成、服务等待、网络、CLI 等，现有证据无法把它们全部标成“模型推理时间”。

每格完整时间包含其准备和清理；一次性无模型预检单列为 40.195 s。安装、准备失败恢复、规划、评分和协调的累计时间/token/费用未完整计量，不把每格成本冒充整个研发试验的净成本。18 会话实际输入加输出总计 757,454 token；缓存输入及推理输出按子集另列。美元费用、提供商内部请求次数、服务实际解析出的 reasoning effort 未暴露，均为未测；未调用 Google API。CLI 的共同模型 metadata fallback 提示保留在原始记录中。

18 个 thin bridge 没有 graceful EXIT 收据；这与公开请求完整回应、受控后端正常关闭及已知进程清理是不同字段。保留这一记录限制，不把缺收据写成优雅退出，也不把它变成几何答案错误。原场景只读的判断依据实际代码审查、初终态与来源绑定，不仅依据清理回执。

**下一项建议**

优先简化“任务意图到有效工具请求”的入口，重点是全场最近表面任务，以及新集合与旧事实枚举的混合。把一次正确查询的参数组合变得直接、短小，错误时给出可执行的正确查询形式；无需继续增加检查层或调整几何容差。之后用同样不告知答案的任务验证：模型是否实际进入正确路径、是否减少错误和回退、完整任务是否更省。当前批次保持封存，不改提示或补跑来覆盖这次失败。

本次只各三次、两个固定场景，结论限于这些任务；尚未证明更大场景、视觉观察或任意资产上的稳定收益。

最终原件绑定复核通过：422 原件、19 发布件和 39 冻结文件哈希全部匹配；18 匿名 final 与实际交付及 CONSUMER 逐字节一致；62 尝试、47 代码调用、10 错误和 369 项脱敏与原件对应。18 初终态及原资产一致，两套各 137 源与实际 12 个插件 serve 来源匹配，18 owner 正常关闭，记录的 116 个 PID 在独立进程快照中均不再运行。此核查未重跑模型、Blender、产品或作者分析脚本。
