# M1-04 首批：有界单对象诊断任务与MCP消费合同

2026-11-01实现前登记。基线为M1-03候选`3bd0e45ed080b6bb2d7c58b62c2386fbd5b21142f1bca803fbce6e5850d894b4`，正式安装仍为22fb。本文件限定接口与验收，[唯一主计划](PRODUCT_ROADMAP.md)决定顺序。

## 任务来源与边界

原`task_context`/`session_id`仅为调用方标签，不能创建预算。首批由受信本地入口显式登记一个对象、九类支持事实的子集、任务期限及上限；MCP只能消费已登记任务。登记使用配置内单独账本路径、配置摘要、随机任务世代。没有登记就明确不可用，不自动创建。创建函数不是公开工具；本批尚无真实用户消息到登记的Hook链。

每任务固定最多6次实际观察请求、2张原生图、16MiB PNG、512KiB诊断JSON、16个patch引用，期限最多180秒；单次诊断JSON最多96KiB，宿主单次仍最多30秒。账本在调宿主前持久预留，再确认实际构造的输出。发送成功与模型读取不等同；丢失回执不退还已消耗额度。图片调用发生后结果未知时保留最坏预留，不能据异常猜测没有渲染。

进程间使用固定侧锁及原原子写入（flush/fsync/replace），不降低持久化等级。首次消费绑定一个服务实例；并发实例、重新创建服务或重启不会续期/重置，需受信入口新登记。原登记文件不覆盖；新任务由宿主选择新账本/配置。此为接口与本地状态完整性约束，不防拥有同等本地文件权限的代码直接改账本。

## 请求与输出

沿用`human_eye_scene_observe`，不新增第五个工具。新查询模式`mesh_structure`只接收`operation`、`request_id`和可选`patch_ref`；不能附加模型指定的预算、截止时间、原始patch或对象对条件。

1. `operation=diagnose`且`include_image=false`：新鲜读取任务对象，返回结构事实、partial/unknown、未检查项、展示省略及至多16个来源绑定引用。对象名/自然语言不是修改已绑定对象的依据。
2. `operation=patch`及已返回引用：重新读取并核对来源/世代/成员；文字回查默认要求显式`include_image=false`，显式图片请求才尝试M1-03有限原生图。过期引用不能返回旧数据充当当前事实。
3. 同一请求ID及相同有效参数重试只返回历史收据，无图片、无当前事实、无宿主重跑；同ID不同参数拒绝。收据不是新的观察。更换session或相关标签不能避开任务额度。

图片准入失败、图片额度不足等不得吞掉已经成功取得的文字事实；输出分别标记诊断状态与图片状态。全场景来源/恢复失效时图片不交付。工具返回原生图片块，JSON文字不重复base64；不声称该结构任务提供动作权限或对象对间隙证据。

引用仅在已登记任务、对应完整raw来源和对象/网格世代内有效；来源改变后新诊断替换引用，旧引用明确失效。只登记实际交付的完整组件；未提供引用的组件数量显式记录，不构造截断patch。无图像支持的事实仍可回查文字。

## 成本与验收

先测现有同质量私有工作流（新鲜结构诊断→同一patch观察→原生内容构造）作为来源基线；禁止用仅全景或少核验的弱对手。分别记录宿主启动、诊断、patch、编码/传输及完整调用，不以20–26毫秒局部帧代替任务时长。新账本有明确可靠性工作，新增持久化必须计入。

首次入口验收以固定原期限/工作/字节硬上限和功能正确为门，分阶段计时建立完整入口基线；没有配对稳定样本时不宣布性能提升或完整性能发布通过。后续性能优化须先依据完整入口数据登记数值门。本轮不重复优化已冻结的大网格失败，不用本批小资产通过覆盖旧失败。

必须验证：无登记/错配置/错对象、重复ID与换标签、并发/重启、预留后崩溃、完成后回执丢失、到期、次数/图数/字节边界、过期与超额引用、图片失败保留事实；四工具兼容、正常/异常/partial/未知诊断内容及独立像素门。使用独立owned Blender及真实stdio MCP消息，TCP固定模板另行核验；这不代替当前聊天插件安装或真实消息自动Hook验收。正式模型收益试次为0。

## 第二批实现前冻结：本机任务生命周期

现有Hook从stdin读取JSON，当前实现未提供不可重放的宿主任务签发证明，不能用event中的turn/session或模型文字自动领取新额度。本批选择显式本机CLI，登记/结束不作为MCP工具暴露。可选配置`structure_task_control_file`启用稳定控制文件；旧`structure_task_file`单任务方式兼容。控制模式的查询必须带`task_ref`，它只是选择受信入口已经登记且当前活动的任务，不创建、切换、续期或恢复任务。

本机入口提供begin/status/close。begin要求操作者提供registration_id及对象ID；登记ID仅保存摘要。同ID同参数返回原登记状态，同ID不同参数拒绝，关闭后的同ID不能重开。每个控制文件最多16次登记，不淘汰旧ID；到上限显式拒绝，避免无界历史或遗忘去重。活动任务必须先显式关闭才能新建，失败/到期不自动领取下一份预算。close保留原账本和未决预留，不能撤销已花费额度。

控制文件固定侧锁贯穿一次实际观察，锁顺序为service→control→task；begin/close使用control→task，避免任务在观察中被切换。每个任务使用控制文件旁专属子目录内的随机世代账本。先持久保留登记ID，再写新账本，最后发布活动引用；任何中间失败保留pending，不自动重做或重置。状态读取不领取owner、不读Blender，也不把旧事实当当前观察；公开查询缺少/错/关闭/旧task_ref时调宿主前拒绝。新世代可由同一MCP进程消费，重启仍不能接管已经领取的旧世代。

验收冻结：16/17上限、同ID重试/参数冲突/关闭后重试、活动冲突、错/旧/缺任务引用、真实双进程登记竞争、登记/关闭各发布点故障、原预算及重启、同一stdio进程跨两任务消费、零几何改动与原生像素质量。成本本轮只记录控制入口及完整调用，不新增无依据的性能通过宣称。正式安装、真实用户消息自动登记和正式模型试次仍单独待验。

### 第二批用法与结果

候选源码环境中，稳定配置同时保留`structure_task_file`并增加`structure_task_control_file`（例如`structure-control.json`）；控制模式不使用旧单任务文件创建预算。每个控制文件有独立的`.tasks`子目录，保存已关闭任务的原账本。以下命令由本机操作者执行，配置和对象ID以已核验值为准：

```text
python -m human_eye_plugin.structure_task_control --config <config.json> begin --registration-id <unique-local-id> --object-id <verified-object-id>
python -m human_eye_plugin.structure_task_control --config <config.json> status
python -m human_eye_plugin.structure_task_control --config <config.json> close --task-ref <returned-task-ref>
```

begin返回的query和include_image可作为Codex交接；其中request_id是一次观察的幂等键，后续新的观察使用新的request_id。控制模式每次诊断及patch查询都须带相同活动task_ref。引用不是权限凭据，模型不能据此新建任务；重启不能接管已消费的旧任务。关闭和status只报告任务状态，不认证当前场景。

最终85运行源构建`307f6ed15e66bffd533bd858321dbb00563fef0fec2b462387dfe736dc350bdc`通过3轮真实本机CLI＋stdio，每轮同一配置和服务连续消费两项任务，旧task_ref/patch_ref不能转用新任务。12条TCP命令/轮、12张原生图合计、6张局部图均12/12边缘对可读；前后原生状态保持。全量1657项运行、1654通过、3项既有跳过，新增15项生命周期测试含跨进程互斥和各持久发布点失败。

本机begin包含进程启动约267–309毫秒，close约261–284毫秒；首次两图完整RPC约457–669毫秒，同宿主第二任务约185–204毫秒，保留全部三轮和首次高值。这些仍是观察值，不能与不同入口的旧私有基线直接算收益，也不构成完整任务性能发布门。当前安装、真实消息自动登记、当前Codex文字消费、代表资产及同口径完整成本仍待后续验收。16次容量和pending需人工核查是本批明确边界，不自动删除旧记录或创建新控制文件绕过。

## 第三批实现前冻结：文字简报与代表形状

沿用response_detail=brief，为结构任务增加结果内字典引用，保留完整值，禁止删掉来源、位置、分类、未知/省略/未检查、图像状态或原预算。引用只指向同一结果中先出现的字典，不是网络或跨请求引用；展开后须与full元数据逐值一致。已有引用、未知协议/算法、矛盾状态或不安全结构保持full。现有节省门不改：至少减少256字节且不超过完整文字90%；否则回退完整结果。图片块、实际观察次数和保守全文额度不变。

实现前登记程序化代表形状：16×8闭合三角环体（九类已知簇均0）、移除一个单元的环体（1个边界簇）、16×2弯曲三角条带（1个边界簇），其余八类均0；另有非平面四边形（边界1、退化检查unknown），不得转写正常。自交/损伤等继续not_checked，不从拓扑正常推断无自交。三个非平面边界不要求出图，域外原生图拒绝应保留新鲜文字。原平面小孔的两图和12/12像素门作回归。它们是程序化几何代表，不是外部真实资产或通用复杂模型证据。

同一宿主、同一任务中full与brief交错请求，核对稳定事实（新鲜capture/request/deadline等本就变化的关联项另列），在同一原始响应上展开简报严格等于full。记录从宿主启动、MCP初始化、登记、诊断、编码传输到关闭的完整脚本总时长、各RPC及进程内存采样，首次与热态分别报告；不跨冷/热或不同入口宣传加速。简报本地投影用同一元数据配对60轮，新增中位成本≤2毫秒、p95≤5毫秒；这是96KiB内可选表示成本门，不是完整任务SLA。失败则保留记录并关闭该可选投影，不继续无限抠性能。当前Codex通过实际候选stdio返回读取文字，只记手动消费，不算当前安装MCP或真实消息自动Hook，更不算正式模型收益试次。

### 第三批结果

85运行源构建`e61046c846a4ee9b5b4e9498720715050dd87e7003594c59a925c44d145fc1d2`：3轮共15个owned场景通过，132项已知类别计数与3项预登记未知保持。简报文字减少11.3%–16.2%，所有同结果展开与full逐值一致；未减少原全文计费额度，不将字节收益换算为模型token或费用。30组实际/约92KiB边界元数据各60轮交错配对，最大新增中位0.625毫秒、最大p95 0.883毫秒，门限通过。

三类非平面边界的图片明确unavailable并保留新鲜事实，平面小孔三轮6张图片、3张局部图均12/12边缘对可读，full/brief的原生图片块一致。15个Blender及MCP进程正常退出，几何/显示/动作状态保持。当前Codex通过本地工具读取实际MCP简报存档，记录为手动、非盲消费；当前安装与真实消息自动Hook未验，正式模型试次0。97模块1664项运行、1661通过、3项既有跳过。

完整脚本从新宿主启动到可信close约1.06–2.26秒，含初始化/登记/工具发现/诊断/校验/传输/可选图片与间隔，排除微基准和退出；本机登记为进程内函数，不能与上批另起CLI进程的耗时直接计算加速。真实worker的单进程OS峰值工作集约81.4–82.2MiB，Blender约187.3–361.0MiB，读取时点在关闭前；记录启动器和实际worker，不将多个不同时刻峰值相加成进程树峰值。不宣称硬内存上限或完整性能发布。

程序化代表形状是有限来源/计数/拒绝证据，不替代外部真实资产与通用复杂场景。M1-04功能收口后冻结候选，M1-05继续数值成本、固定包、隔离安装与真实资产代表性；旧大网格成本失败、16次登记容量、pending核查及有限XY图片域均保留。
