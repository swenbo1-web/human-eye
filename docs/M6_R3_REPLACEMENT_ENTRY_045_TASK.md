# M6-045　R3 替代 032 的覆盖与普通入口成本验收

沿用三套已核验的安装。A 为 `6c93f237` 的 032，B 为 `119327bb` 的原 R3，C 为 043 单点修正（源码摘要 `b8c8bcd770a17f422789d3034bef608f4ada7aba90293397b83e3524b5a9402e`）。从实施提交 `126f7fe0f77a4220fc639055caa3c959fffb1c26` 接续。本批给出两项独立结论，一项回答旧版能答的查询是否仍可答，一项回答 G60 的完整普通入口是否更快。保留 043、044 各自原分母，正式配置、Hook 信任、原始资产和三版算法均不修改。

## 一　唯一的 129 面边界输入

- 在 044 经核验的生成器 `freeze_pressure.py`（SHA-256 `e92a6a5c3b0d79c147d6c49067b0fc7897b9ee75264c2b8217094823fb5dc112`）只将每侧面数取 `isqrt(16384)+1 = 129`，共 258 面，16,641 个可能的三角对。其余几何规则、面序、版本和预算不动。只取这一点，无新校准或调参。先验证并封存世界坐标、来源、解析下界、唯一最近点与规范源面，再读 A/B/C 的结果。保留 125 正例，区分“可能的配对数”和“实际产生的精算数”。
- 以真实私有 Blender 副本保存、独立重开，走原普通生产 stdio `human_eye_scene_observe` 的表面距离事实，只读、无缓存首答。三个安装使用相同请求来源、普通完整账本及原截止。从真实回包取已知/未知，从原生几何和独立答案核对距离、点、面与覆盖。从审计取叶对／精算、实际投影排除、工作与信用、具体拒绝原因、是否有伪造或部分距离。普通回包没有的源面信息单列其来源。若出现版本状态差，只允许同一件在另行诊断中追到原预算种类与第一次分歧；保留原普通回执，不补报成功。
- 逐对记录 A→B、A→C、B→C 的差异。任何 032 可精确回答而候选新增未知的普通实例，都是该候选默认替代前的明确功能缺口。两臂同时未知不构成覆盖等价证明。出现错误已知单列为正确性失败。该夹具是合成边界案例，真实资产上的发生比例未测，不能按这一次结果估算。不同结论不互相抵消。

## 二　G60 启动、答复、真实退出与归档

沿用 043 的原 G60 资产和普通 add-on、同一解释器与选项、三条业务查询、源与答案。固定 043 方案 SHA-256 `ca14c4f0147da180d330e947689cd411ac56310e5e860d1c197e78e9ab5f585e`。六个独立隔离 GUI，各做一个 A/B/C 排列，六种顺序各一次，每格新服务。事前锁定三臂源码/执行身份、资产、顺序、计时边界、采样及正常退出判据。原业务与普通生产服务均不插桩，只允许试验客户端加对称的轻量计时；额外时间戳存在内存中，结束后写出。保留 043 原流程的证据制作顺序及完整窗口，不能靠搬出工作来制造加速。

保留同一个原始墙钟，并记录以下实际边界。

| 窗口 | 核验要求 |
|---|---|
| 客户端开始、创建服务、发送 initialize、收到 initialize 与工具目录、第一条业务请求 | 核对实际解释器、启动包装器和各自 PID。分开标记客户端在此期间读取/核验/写入实验收据的时间 |
| 从概览写入到最后一条扫描解码 | 三份完整真实回复，同绑定、最近对象、点对与覆盖；核对三条查询各自耗时和缓存 |
| 最后答复、关闭 stdin、实际解释器退出、包装器退出、读线程结束 | 优先用持有的 Windows 进程句柄取得创建/退出时间，分别记录，确认 PID 所有权和正常退出。单一时间源内作差。使用父进程单调钟观测时，记录等待与观测语义，不能把写入 CLOSE.json 当作进程退出 |
| 归档原始收发字节与完成客户端收尾 | 记录真实写入区间、文件数及字节数。043 的收尾还包含读线程及线包写盘，须给出同口径完整窗口及“直到进程真正退出”的结果。窗口可嵌套，只给真实非重叠顺序，不能将分项中位数相加 |

冻结一个可比较的**服务进程存活窗口**，即从该格已绑定启动进程的操作系统创建时间到启动器及真实服务解释器均已退出。保留客户端从创建前到全部收尾以及完整 GUI 生命周期。这些口径对应不同问题，分栏对三组版本作同组差值后取中位数，保留六个原轮、单轮逆向和失效项。服务进程若在等客户端写实验材料，须说明；已退出后发生的归档不计入进程存活。无进程来源或时钟未经核对的样本标未测。用一次无 Blender 几何业务的私有子进程预飞核清计时、退出、归档次序和追踪开销后即可开始；正式样本不补跑，不需系统级提权或 ETW。

沿用原 G60 业务判据，C 对 032 的配对降幅中位至少 10%、至少 5/6 更快，C 对原 R3 的配对中位增幅不超过 5%。对新测进程存活窗口，本批预先选择“C 对 032 有净收益，C 对 B 增幅不超过 5%”作为替代评估尺度，报告所有绝对值和配对方向。另给 B 对 032 的数值。若仅归档出现长尾，按实测定位；若真实进程窗口也有增幅，标明其发生在初始化、业务、收尾或尚不可分辨的区间，不能仅以窗口相邻认定因果。独立报告来源及精度、CPU、能实测的内存范围、全部 owned 进程退出和端口释放。
