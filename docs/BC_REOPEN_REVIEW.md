# BC 搜索优化重开审查

本轮按用户要求继续对BC搜索做实际优化，以实施达标版A为直接对照。原v6/v7拒绝记录保留；第一轮相对全对穷举的倍数，与本轮相对已优化BVH的倍数不混用。运行时只有最终被采用的一份实现，不加双路径守卫、回退链或旧答案缓存。

## 为什么场景差异大

BVH的工作量由包围盒重叠、最初上界、下界松紧和访问次序共同决定，不仅由面数决定。斜面在三个世界坐标轴上的盒子可能重叠，但沿双方见证连线方向的投影区间仍明显分离。查询级统一投影使这些节点可提前排除；初始上界更好还会让后续整批窄相消失。另一方面，原本只检查少数面对的小场景会更敏感于投影表、排序及seed精算的固定成本。密集等距平面可能所有界都贴着真实最小值，算法仍须保留大量面对，最坏复杂度没有消失。

A/A诊断两个独立实例使用同一源码，仅4个指定状态。整体耗时比0.9978；某个进程/状态的p95比仍为1.279。该证据说明尾分位有环境波动，不证明旧v7的54%差全由噪声造成。Windows调用线程CPU计时实测15.625ms量化，不能将单次读数0解释为零成本；验收使用wall，CPU仅作辅助。

## 本轮结构变化

1. 保持驻留拓扑BVH；当前顶点完整update后，查询从真实seed见证得到公共原点和归一化方向。当前几何沿该方向投影，逐面区间自底向上归并；节点和面对下界均取max(AABB下界, 一维区间间隔/轴长)，不能把投影当第四个坐标平方相加。
2. seed下降保留4个便宜节点候选，最终只对其中AABB下界最小的16面对做精算。它只提供一个真实上界；正式搜索重新从两个根开始，没有Top-K截断全局求距。当前叶大小4保证双方都是根叶时最多16面对，原早返回仍完整。
3. 大而不等界的面对批次按下界排序，先32对，再128/512/2048对；每块使用最新上界重筛。只有排序后整块下界都超出当前上界时，才停止该叶批次，外层栈继续。小批次和等界批次直接计算，属于单一搜索算法的工作量安排。
4. 对正交投影已在非退化三角内的源顶点，不再重复算到三条边的距离。仅压缩outside顶点，保留反向点面、边边、穿面和退化边路径；原始面对ID和见证映回一致。

浮点误差外扩是下界正确性的一部分。独立Decimal测试覆盖1e-150到1e150和大平移，但不是全IEEE证明；通用helper在最小subnormal、未按最大分量归一化的轴上存在一ULP外扩不足的探针。实际搜索归一化轴未复现该探针的错误，未发现实际查询反例，不能据此声称极端下溢范围已获全覆盖。

## 保留的探索与失败

旧两种子16状态pilot：projected_order整体比0.7252，compact为0.7037，beam为0.5019；上一v7同口径pilot为0.7450。它们是不同运行窗口的小样本探索，不能替代正式门或称为新旧候选的严格配对正式排名。

formal_beam_001在原32状态上整体比0.5023，3进程均约0.50，质量通过；但4状态中位数同时超过1.10倍及+.25ms，因此未采用。真实Blender4测试与24个VG场景通过，24对PNG解码RGBA一致；这不抵扣性能局部门。第一次native脚本因读取GPU信息前未初始化而退出，修正测试初始化后以新目录重跑，不是候选几何修复。

seed16只缩小初始精算成本，旧种子pilot整体比0.5001，小场景最大比1.082。正式候选冻结ffc494bf309bb9010854d88007edb54533c9fa9d7fad68905fe0d75663692aeb，提交5aaf037。原32状态及门值不变，另加两个新种子16状态单独盲测，48状态不能重加权替代原32的门。原始记录和源码均保留。

## 正式32状态与独立16状态

seed16正式原32状态：A的sum-state-medians为323.3044ms，R为157.9270ms，比例0.48848，降低51.15%。三个独立进程比例0.49163/0.49270/0.48514；几何均值比0.58905，26状态快、6状态有代价。整体差值95%配对分层重采样区间为[-166.169,-164.325]ms。新增314159/271828组比0.47735；后追加141421/161803独立16状态组比0.48511，16状态均快。48状态仅作披露比0.48721，不能替代原32主门。该“整体”是指定工作负载，不是生产频率加权或整引擎。

密集正距与相交中位数比分别0.99568/1.00491，小四面体两状态中位数均略快。全部48状态中位局部门通过；原正式32中79463/128near/phase1尾门首次1.26671超过1.25，原formal审计保持FAIL，不能改写成首测全过。

按事前补测规则，唯一固定3新进程×256对同输入复核：该状态补测384样本p95比1.09545；首测96加补测384共480样本p95比1.14502。中位数比分别1.07598/1.07312，仍有约0.32/0.31ms稳定局部成本，按ratio≤1.10一支过原OR门。另一状态补测/合并p95比0.82455/0.83684亦通过。没有剔除首测尖峰、改变其他状态权重或重复试到通过；只能结论为尖峰未稳定复现，不能推断唯一噪声来源。

固定旧16状态的非计时插桩记录显示：20261105/128分离phase1由2795面对降至72；同种子512近接触phase0由3526降至114；79463/128near/phase1反而由463增至500。最后一例与其约7%局部成本方向一致，但面对提交数不等于每面对的点面/边边特征操作数，不能从计数直接推导时延。compact与order提交数相同仍可能减少边计算。所有版本输出距离与A一致，独立oracle另行验证。

## 正式结论

**ACCEPT：采用seed16，生产BC源码SHA256为ffc494bf309bb9010854d88007edb54533c9fa9d7fad68905fe0d75663692aeb。** 冻结A及每个失败/探索候选均保留。formal首测仍记为局部p95 FAIL；按已冻结单次补测规则完成完整审计后，解除该局部疑点，其他门保持原口径通过。

独立正式审计核对5440对质量记录，补测审计1008对，来源/输入/输出/顺序/统计无错误。生产替换后31项核心、独立oracle、投影性质及穷举早停公平性测试通过；4项真实Blender接线/单位/资源测试通过，24对VG PNG解码RGBA完全相同。实际GPU为报告中记录的RTX3060/OpenGL。只更新未来VG基准的BC依赖pin，历史VG证据不重新标记为新BC测量。
