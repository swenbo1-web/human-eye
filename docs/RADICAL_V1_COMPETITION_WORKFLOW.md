# Radical V1：独立竞争、六模块推进与收益验收

日期：2026-11-05。用户最新决定：**两端各自实现完整引擎，独立竞争，不采用架构端/算法端互补分工，不计划跨端代码合并。** 本文件取代旧方案中的两端分工、A+B集成及排期条款。三大功能分区仍见[整体架构](RADICAL_V1_INTEGRATION_PLAN.md)，工程实施按用户原始规格的六个源码模块组织。

我方竞争分支为 `codex/aggressive-v1`；另一端自行保存其完整实现。可以共享用户需求、公开测试输入与评分口径，不能将另一端实现算作我方交付。尚无另一端同口径结果时不宣布竞争胜出。

## 1. 主对话与实施对话的职责

主对话负责模块范围、事前收益标准、实施派工、独立复验、接受或返工和后续派工。用户已授权创建一个或多个实施对话、向其发送任务，并由实施对话反馈结果。

实施对话按固定范围实现，提交代码路径、测试命令、原始样本、基线、数值差异、收益结论及未运行项。实施者的“完成/通过”仅是交付申请；主对话至少执行一次独立验收，不能直接引用作者结论作为放行。

同一模块的循环为：**冻结范围与标准 → 实施 → 作者交付 → 主对话独立验收 → 通过后推进依赖模块；未达标回原实施对话返工。** 若环境使必要项无法运行，记录“待验”，不冒充通过。指标不得在看过结果后悄悄降低；需求变化需另立修订并保留旧结果。

允许多个我方实施对话并行，但必须文件责任不冲突、依赖满足。它们都是同一竞争端的工作对话。当前可并行 RB-A 数组桥与 TD 形变模块；两者直接消费公开数组，TD不依赖Blender桥。依赖真实宿主的视觉和整链验收继续等待RB-B。

同一checkout并行时：主对话独占Git提交/推送、入口文档、`.gitignore`、包导出及共享接线；实施对话只写各自列明文件，不切分支、不stage/commit、不改其他对话成果。交付后在本对话统一保存版本。不是通过跨竞争端合并来完成引擎。

## 3. 通用收益验收协议

正确性与收益同时达标才通过。新增能力可采用“质量提高且成本有界”或“同质量成本下降”，不能以测试数、代码行数、删除检查数量替代收益。

- 基线使用冻结提交或随基准提供的合理直接实现。错误的附件距离核不能作质量oracle；每次重建所有状态不能作常驻更新的唯一性能基线。
- 输入、单位、输出字段、索引、设备、线程配置和计时范围相同；数据生成、断言、日志、JSON写盘在计时外。算法必需的索引选择、复制与变换在计时内。
- 吞吐验收至少3个独立进程，每进程预热5次、交错测量31次，保留每次原始样本。每进程中位数都满足主收益门，汇总p95满足退化门。主对话至少独立启动一次同样的3进程复跑。
- 内存使用同一工具/边界，明确“额外数组分配峰值”与RSS不同；输入已存在时两边均排除输入准备。内存测量不混入时间样本。
- 没有真实Blender/GPU/消费者的项目保持未验。可移植通过不会自动获得宿主通过；通过某个子项只放行明确依赖该子项的工作。
- 根本失败保留原记录，主对话写明返工原因；实现可改、基准可以修复错误，但必须披露前后定义，不挑最好一次掩盖失败。

## 4. 事前模块收益标准 v1

这些是本端开工前的目标，不是已达成数字。另一端要直接排名时也需采用同一输入/质量/计量边界；其机器不同则分别报告设备，不直接把时延当纯算法优势。

| 模块 | 正确性与能力要求 | 收益门与不退化门 |
| --- | --- | --- |
| **RB-A 数组桥** | 多对象身份、局部米制→世界米制、刚体/非均匀变换、1%dirty/full/无变更/拓扑替换均与直接计算一致；自有缓存不受调用方静默修改影响 | 见下一节的冻结小范围：两档连通网格上1%dirty相对合理常驻全量刷新中位数≥2×；full中位数和p95≤基线1.20×；无变化无顶点/拓扑拷贝 |
| **RB-B 原生采集** | 真实Blender连续对象求值、单位、拓扑/外观更新；数组值与原生直接读取一致 | 相同变化序列下捕获+准备总中位数至少下降20%；全变化序列p95不恶化超过20%。公开实际复制量；不称端到端零拷贝 |
| **BC 距离核** | 解析边边、点面、接触、共面/穿插和嵌套表面；小规模独立穷举oracle无错误，见证落在对应面 | 128/512面双网格的正确穷举基线上，512面典型分离/近接触类中位数≥2×；128面p95≤1.20×；另列密集重叠最坏样例成本，不用固定Top32隐藏漏解 |
| **TD 跨帧形变** | 与独立QR/SVD及面积/法向/位移解析结果一致；包含等面积拉伸、刚体旋转、塌缩和退化、同分Top-K | 第一批采用内存收益门：16帧、20k/100k连通面，相同完整摘要下额外分配峰值≤合理全张量基线50%；中位数/p95≤1.25×。已有单帧主伸长能力保留 |

## 5. 首批RB-A固定任务

文件责任：`human_eye_fast/resident_bridge.py`、`verification/test_resident_bridge.py`、`verification/benchmark_resident_bridge.py`、`docs/RB_A_IMPLEMENTATION.md`，原始样本放 `artifacts/rb_a/`。只做该模块，测试不得依赖Blender；RB-B有独立状态。

输入为可信的连续float64局部米制顶点、整型三角索引、世界变换（平移已经是米）、外观。会话首次入库持有自己的数组；后续显式full/dirty/transform/appearance更新；无变更直接借用缓存。局部→世界用完整矩阵，面索引保持对应，拓扑替换显式重建本对象。支持对象删除/会话释放。

基准采用两个对象，每对象共享顶点的二维网格：边长100和300，分别10,000和90,000顶点。两对象均使用非平凡变换，输入不在计时内生成。1% dirty索引固定随机种子、非连续分布，交替两个真实不同的坐标状态，确保不是反复写同一值。

合理基线：同样常驻local/world/topology缓冲，`np.copyto(local,incoming)`全量刷新，`np.matmul(..., out=world)`再原位加平移；拓扑不重拷贝，不建FastSession、不算形变。只比较相同的桥接工作。候选dirty路径允许仅处理已声明变更；这是明确的增量收益。

计时列出：初次入库、全量顶点变化、1%dirty、仅变换、无变化读取。主要收益门只针对dirty；full同时通过不退化门。变换/无变化给成本与真实复制量，不拿O(1)句柄读取去比较另一边强制物化所有顶点。

正确性逐状态比较完整world数组、topology和局部所有权；容差`rtol=1e-12, atol=1e-12`用于本基准量级。额外案例测试scale_length语义由调用端预处理、非均匀变换、大平移、单对象更新不改变另一对象、外部输入修改、替换/释放。完整矩阵变换为独立预期，不重用候选函数生成答案。

## 6. 并行首批TD固定任务

文件责任：`human_eye_fast/tensor_deform.py`、`verification/test_tensor_deform.py`、`verification/benchmark_tensor_deform.py`、`docs/TD_IMPLEMENTATION.md`，样本放 `artifacts/td/`。复用现有kernels，不改engine/kernels公共实现；主对话负责后续入口。

输出每面跨帧最大/最小主伸长、面积应变、最大法向转角、最大质心位移以及Top-K原始面ID，位移排序需按参考尺度归一化。法向变化按名称返回，不冒充翻转；相同分数按面ID稳定选择。处理参考退化/当前塌缩、空输入、top_k=0，以及给定参考与首帧不同的场景。

基线为语义正确的全张量实现，双方使用同一主伸长核逐帧求值，法向/面积/位移基线以全T×F数组批量计算；不能用附件错误语义换取优势。输入在计量外，候选以流式归约降低额外分配峰值。小规模独立QR/SVD和解析值检查数值，20k/100k面近似规模的连通网格、16帧测性能并报告实际面数。

计量采用tracemalloc额外分配峰值（明确不等于进程RSS），两边新建同样输出、使用预先存在输入，计量前collect并重新start；时间另跑3进程×31样本，不包含tracemalloc。峰值与时延双门同时通过才通过TD。

## 7. 验收记录和后续派工

每次主验收记录：模块/子项、基线提交、候选文件摘要、测试命令、独立原始样本、质量结果、各门实际值、PASS/REWORK/PENDING、未验项和下一步允许范围。记录放 `docs/RADICAL_V1_ACCEPTANCE_LOG.md`，该文件由主对话维护。

RB-A通过记为数组子项通过；RB整体仍需RB-B，BC正式推进须等RB整模块通过。TD可独立通过，不能替代距离或真实视觉。VG/AO/CF按依赖获得实际数据后派工。主对话读取实施对话反馈并复验，至少完成一次实际验收后向用户报告；后续失败继续返工，不自动推进依赖项。

整体竞争最终比较质量、冷/热端到端耗时、p95、内存、工具/模型轮次和输出成本。附件的<12ms是目标，必须固定输入规模和是否包含GPU读回才能声称达到。六个模块分别通过也不自动证明整链通过，最终必须做真实观察—动作—回读—学习验收。
