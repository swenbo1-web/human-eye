# M4 双资产正式评分预飞

装配对照已经跨资产复现了首包闭环。先把评分器的全路径预飞接进冻结，让同一类证据能够在正式消耗前检查完整。固定现有产品 e8006670 的两批封存输出。

## 实施

以装配证据 4bc6b7d6 的评分入口为基线，在独立验证分支做窄修。把旧 `matrix64_regions` 访问限定到真正使用它的判定分支，在已验证的同槽生产记录路径边界使用 `Path`。沿用原 17 条事实标准、数值容差、同帧采样、同槽真实路径和关闭校验。保留清晰的实际代码调用关系。修复应由候选评分入口直接执行。

新增同一正式评分入口的只读预飞。用实际封存的原答、机器转录、入出线包、原图、NPZ、初末场景及关闭收据，在独立冷进程中跑完整评分。用两批原有数据。装配 N1/P1 来自 4bc6b7d6，Yanyite N1/P1 来自 75f75b92。只写新的评分证据目录。评分程序与传递导入依赖、实际预飞入口、输入清单和结果均绑定到冻结收据。任何一次完整预飞失败时，冻结门能够据实拦截。

## 验收

- 装配旧评分入口以同一批原件如实复现 N1 7/17 和 P1 路径加载异常，候选整链路各 17/17，原通过项逐项相等。
- Yanyite 两臂完整 17/17，保持原有事实判定和绑定。同一评分入口确实覆盖原生与插件分支。
- 错方向、错图路径、错源像素、跨槽同字节、失效捕获或错摘要均沿正式验证路径拒绝，重复或不全的必选项不能取得完整通过。原始封存文件散列与历史原判保持。
- 封存每次实际入口、独立进程关闭、逐项评分与耗时。使用新证据分支，校核远端后回传 `M4-SOURCE-REGION-SCORE-ADMISSION-001_READY`。

本轮模型、Blender、构图、产品改动或构建安装、默认设置修改、原资产及旧原件写入、额外 API 和费用均为零。赛题性能沿两次既有配对留档。待预飞通过再决定下一次真实留出范围。
