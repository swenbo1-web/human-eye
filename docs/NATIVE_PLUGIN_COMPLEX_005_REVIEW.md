# 实际旧安装版、新版与原生：重新测试及独立复核

本轮已纠正旧版基线，完成18个全新模型会话。新版在指定候选的装配诊断中有明确收益；全场最近对象查询仍未实现稳定的插件收益。两个任务必须分开判断。

两题、三组、每组每题三次，全部重新运行，顺序平衡。相同题干、原生能力、请求模型 `gpt-6.1-sol`、请求 effort=medium、预算和固定场景；插件使用各自实际的 scene/status 接口，没有给H套上新能力。模型实际选择工具，不强迫走插件。使用现有Pro登录，未恢复Google/API付费试验。

装配题含一个旋转的通孔环体和三个候选，72顶点、132三角形；要求实体关系、所有穿插件、两个真实表面间隙和最近分离件。全场题是48网格、1536顶点、2880三角形，47个候选的AABB均与目标重叠，要求全局最小表面距离。这是中等规模的几何歧义题，不代表大规模生产场景验收。

## 结果

时间为每组3次的完整单次任务生命周期中位数，包含启动、模型调用、所有工具/失败/回退、退出和后端关闭；未删除失败格。计时截止于后端关闭完成，之后的CONSUMER结果文件持久化及归档不包含在内。token为CLI实际返回的 input+output，input包含cached input，子集不重复相加。

| 任务及指标 | 原生N | 实际旧版H | 当前新版C |
| --- | ---: | ---: | ---: |
| 装配题完整正确 | 3/3 | 3/3 | 3/3 |
| 装配题完整耗时 | 96.07 s | 84.38 s | **55.75 s** |
| 装配题总token中位数 | 48,787 | 38,759 | **31,446** |
| 全场题完整正确 | 3/3 | 3/3 | **2/3** |
| 全场题完整耗时，含错误格 | 103.50 s | 91.41 s | 78.04 s |
| 全场题总token中位数，含错误格 | 57,879 | 24,854 | 31,021 |

装配题新版完整时间比原生低 **41.97%**、比旧版低 **33.93%**；总token中位数分别低 **35.54%**、**18.87%**。三个新版会话都实际拿到了正确插件几何结果。一次只调用插件即完成，另外两次先因不支持的 `nearest_witness` 事实组合被拒绝，纠正后成功，另有只读元数据查询。所有失败成本均计入上述数字。

全场题新版组的完整时间中位数低于原生24.60%、低于旧版14.63%，但其正确率下降，因此不能验收为质量保持的净收益；总token中位数还比旧版高24.81%。每格仅三次，不据此推断稳定的总体优劣或尾部性能。

## 实际调用说明了什么

| 任务/组 | 原生调用 | 插件观察尝试 | 插件观察成功 | 工具错误 |
| --- | ---: | ---: | ---: | ---: |
| 装配N | 12 | 0 | 0 | 0 |
| 装配H | 9 | 0 | 0 | 0 |
| 装配C | 2 | 5 | 3 | 2 |
| 全场N | 13 | 0 | 0 | 0 |
| 全场H | 10 | 0 | 0 | 0 |
| 全场C | 7 | 1 | 0 | 1 |

实际旧版H的六个会话完全走原生求解。因此H组比N组快的部分不能归因于旧插件几何引擎；工具目录与模型生成路径不同，现有样本不能拆出其因果贡献。旧版预检确实返回过能力/预算限制，但正式会话没有调用它，不能把预检拒绝写成正式模型遇到的错误。

新版全场题中，两次直接选择原生，一次遗漏 `session_id` 导致 `surface_nearest` 拒绝后转原生。九个全场最终答案均由原生代码生成，没有一次成功消费插件全场几何结果。新版引擎在同题无模型预检中成功，不等于模型会自发正确调用它；此次消费链验收的缺口是工具选择与接口使用。

唯一错误来自新版组第07格，匿名答案 `425c329dbb104cbea457b46656e308b4`。模型自编边—面相交代码只用绝对行列式门限，接受了近平行计算产生的伪交点，最终宣称 `Near_017` 距离为0。真值是 `Peer_000`，距离约0.003000006 m；`Near_017`实际约0.026 m。这个错误不是插件内核返回的结果，但仍是“提供新版插件的整条模型工作流”的失败，不能排除。

全场九次中有五次中间计算出现同类伪交点，四次后来修正并全量重算，一次错误留到最终。独立评分保留中间失败；最终已得到充分正确证据的答案可以通过，无需新增未要求的形式证明或冗余原生核验。

## 成本解释与可观测范围

装配题的提示提交到最终答案中位数：N 90.94 s、H 79.33 s、C 46.54 s；对应工具调用区间合计中位数约1.026、0.211、0.192 s，这是owner包装层计时，不是独立内核CPU时间。收益主要体现为少写求解代码、少走求解轮次及更短的模型交互链，不能将整个几十秒差值称为几何内核提速。模型/提供方/传输剩余时间没有被完整拆开，不能全部标成纯推理时间。

最终答案到消费者退出段中位数，装配C为8.00 s、N为3.72 s；全场C为7.41 s、N为3.95 s。此段已计入完整时间，不从新版成绩中扣掉；不能把整个区间武断归因到插件。

18会话累计CLI记录 input 678,707，其中cached input 460,288；output 46,454，其中reasoning子集4,158。总input+output为725,161，不再把缓存/推理子集加一次。实际美元费用、提供方真实请求次数、实际解析的effort未暴露，保持未测。单格之外的预检、准备、协调和独立审核开销未完整计量，不能声称是0，也不能把单格总时间当成整个研究项目成本。

公共MCP目录/控制/工具字节与内部插件pipe分别记录，不能相加当模型token。原生worker TCP字节和内部峰值缓存占用未完整计量。所有会话保留同一CLI模型metadata fallback诊断，配置一致不意味着提供方实际内部配置已被证明。

## 复核证据与收口

作者提供18个真实会话、原始帧/usage、代码审计和成本统计。根独立工作包括：先盲审全部18最终答案，两个复核者逐项审全部实际工具/代码；再核769冻结文件、438匿名来源原件、19发布件、337脱敏对应；确认12个实际插件入口身份和18初终态；逐件核对成本索引的1752原件；从CONSUMER、模型events和公共TX/RX重算全部18成本。没有新增模型调用、产品或Blender重跑。

18后端关闭证据和116个已知owned PID退出记录通过，原资产/终态一致；**18个thin bridge均缺少正常EXIT回执**。已知请求结果与后端清理通过，客户端优雅退出保持未知；严格包含该收据的协议检查为0/18，不能称为全协议通过。此项与几何答案质量分栏，不临时增加语义评分门槛。误纳入parent_pid的首次清理记录及修订证据均保留。

主要独立原件位于 `verification/fixes/20261110_native_plugin_compare_005/`：`BLIND_QUALITY_SEAL.json`、两份 `BLIND_*_REVIEW.json`、`RAW_PROVENANCE_REVIEW.json`、`ROOT_RECOMPUTED_RESULTS.json`、`ROOT_COST_INPUT_BINDING.json`。实施原件位于独立工作树 `verification/native_plugin_complex_005/`。

本轮不修改产品、不重跑替换错误、不切换默认配置。下一项最有证据的优化方向是简化全场最近查询的入口和必填参数，使模型能直接成功使用现有几何能力；然后以新题和相同完整成本口径验证采用率、正确率及收益。继续压缩内核毫秒耗时，无法解决本轮的主要消费缺口。
