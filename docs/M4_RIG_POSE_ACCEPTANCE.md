## 用户可见行为与边界

读取保存文件的当前帧/子帧、原始rest骨架和求值后的pose矩阵，输出父子关系、局部旋转、沿骨骼Y轴的摆动/扭转及世界端点。骨骼头尾位置不变时仍可发现轴向旋转；父骨骼转动不会直接算作子骨骼自身转动。

没有通用“角度大就是损伤”的规则。只有操作者提供并固定了角色规则，才评价注册的骨骼是否越限；输出逐骨骼 `rule_registered`、有规则与无规则的数量。无规则时只报告事实；有规则的骨骼满足条件不代表整副骨架或蒙皮健康。`damage_classification=not_inferred` 始终保留。

首版至多64根骨骼、512KiB快照、每份简报至多16根骨骼；全部骨骼和规则计数先完整计算，再明确报告省略。只支持静态FK、默认旋转/尺度继承、刚性的rest/pose/basis矩阵、POSE显示；原始/求值骨骼名称与父子关系须完整对应。约束/IK、动画/驱动、对象父级、非默认继承、骨骼缩放/剪切、B-bone和REST显示保留unsupported及未知指标，不输出零角度冒充正常。65根、错帧或错参考明确拒绝，不从验收分母移除。

物体的平移、旋转、反射和非均匀世界变换可以存在，但角度规则始终在骨架局部参考坐标解释；世界端点采用场景声明的米/单位比例，不认证真实尺寸校准或世界角度。没有皮肤形变、自交、解剖合理性、连续动作、多圈绕转或可见性结论。0°和360°、q和−q可以有相同当前姿态；单帧矩阵不能恢复绕转历史。

## 算法、来源和流程

设 `R` 为骨骼的原始armature-space rest矩阵，`P` 为当前求值pose矩阵。根骨骼使用 `R⁻¹P`；子骨骼使用 `(R_parent⁻¹R_child)⁻¹(P_parent⁻¹P_child)`。静态FK域内再核对得到的旋转与原始channel basis一致，避免混淆控制通道与求值结果。

```mermaid
flowchart LR
    A[固定文件与当前帧] --> B[原始rest与求值pose 双读]
    B --> C[来源 层级 矩阵与RNA审计]
    C --> D[扣除父运动和rest关系]
    D --> E[Y轴swing/twist]
    E --> F[固定角色规则或明确未知]
    F --> G[优先问题骨骼的有限简报]
```

四元数采用稳定的最大对角构造并消除q/−q符号差异。矩阵正交检查容差为2e-5，角色判断采用预登记的0.001°守卫带；接近180°摆动的扭转分解、±180°扭转符号及阈值守卫带内的判定保留unknown。该守卫不是物理/解剖误差认证。

每份来源绑定进程内文档epoch、对象/数据实例、名称ID、rest/层级摘要、完整pose来源摘要、当前帧/子帧、单位及世界矩阵。命名重复、父级环、原生端点与矩阵不一致、FK basis不一致、来源摘要错误及跨实例引用不能作为当前事实。角色规则固定rest/层级摘要和作者声明；SHA能证明字节绑定，不能证明作者意图正确。

`rig_pose_worker.py`是独立后台只读reader，仅接受inspect/shutdown，无模型代码执行、frame_set、pose变换、模式切换或保存命令。读取原始输入前后做RNA审计，父进程双读并核对source/audit；整个原30秒包括启动、捕获、验证和诊断，最多16次读取。纯分析、worker和父进程分开，旧刚体宿主不因新增骨架域而放宽网格准入。

