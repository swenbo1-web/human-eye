# M4-SURFACE-SCAN-001-OPT1：只重算受局部变化影响的对象对

2026-11-12。本派单接续初版独立深审，落实批准流程中的一轮实质优化。唯一优化对象是扫描测量缓存随整场 generation 失效；本批不增加新的扫描问题或模型消费者。

## 固定基线与证据

实施交付 `726e88efba548e85eba1eb148b91486470c5d2c1`，初版产品 `c6355a01a4c6ee204a0d676cd9309f02428fe3ba`，138 源摘要 `b3654f6f943c3fb6feff0011397c0a8c20872e41f35973e6baf53e3a5e277314`，隔离版本 `9.7.2+m4.surface.scan.r1`。固定输入提交 `96fce78b98cb749885792112e039a406744d282b`，24 对象、BASE/EDIT 各 276 对真值保持原字节。

根独立复算确认：cold/repeat/edit 新核分别为 112/0/114。EDIT 仅 `Obj_008` 姿态变化，24 个资源版本不变，宿主只变换其 8 点；114 个新求解中 104 个对象对与它无关，且已在 cold 求解过。ReadContext 的全场 generation 改变清除进度，测量缓存的 mesh 快键又含整个 capture/selection，造成这些无关 pair 不命中。

初版完整客户端请求中位为 1776.4201/41.4728/1738.8051 ms。它们是本地普通工具请求时长，尚无本任务模型收益结果。

## 唯一实施假设

让表面测量使用真实的对象几何与姿态依赖，保留未变对象对的结果。目录、候选全集、coverage 和结果绑定仍更新到本次场景；复用发生在测量层，不把旧完整场景报告冒充当前结果。

期望固定 EDIT 的新核从 **114 降到 10**，其余 **104 对复用**；静态重问保持 0 新核。上述是机制验收目标，不按工作量比例预报时延。

## 最小实现路径

1. 沿现有 SceneDeltaDecoder 已验证的资源和变换绑定，将扫描所需依赖保留为内部附带元数据。当前 decoder 会移除 `_scene_resource`，不能直接假定 normalized mesh 已保留版本。
2. 依赖至少覆盖宿主/文档 epoch、对象 incarnation、资源 id/revision、实际姿态和单位尺度；与当前运行算法及其数值参数共同构成有序 pair 测量键。若既有字段已由更强绑定覆盖，可复用该绑定并在报告说明，避免重复拼接全量描述。
3. 复用现有 2 MiB measurements store、计量和淘汰；不新增第二套几何库、独立缓存服务或永久扫描账本。附带元数据按当前对象/既有有界选择保存。
4. 只在已建立内部资源绑定的扫描链使用此快键；plain capture 或缺绑定时回退现有正常键。用户提交的任意场景字段不能自行启用可信版本快键。
5. 保持 ordered pair 与 witness 方向一致；名字只是当前输出标签。阈值改变可复用精确距离再分类，旧排除证明和完整扫描结果不能直接跨阈值复用。
6. 全局 generation 改变时，更新/重建任务覆盖和当前选择，但不丢弃仍有效的 pair 测量。source/runtime/epoch 改变、几何 dirty、资源替换、姿态/尺度变化按实际依赖失效；删除和同名重建不能继承旧对象结果。
7. 不放宽通用 solid/task 缓存的 metadata 合同，不引入新的精度或几何算法。保留当前未完成扫描的续查和未知结果处理。

可按真实代码选择更简单的等价接法。提交需说明每项依赖来自哪里、在哪个既有边界确认、何时变化；不要求增加独立授权层或每 pair 做全量哈希。

## 必要正确性验收

- 固定主输入 BASE、repeat、EDIT 全部 276 对，与既有独立真值逐项一致；公开匹配数 71/71/72，距离、见证和完整状态保持正确。
- EDIT 不得复用含 `Obj_008` 旧世界坐标的 10 对；104 个无关 pair 命中来源可逐对核对。
- 两条实际宿主都完成 cold/repeat/edit 语义验收；Process 路径本轮也覆盖 edit，避免只在一个 decoder 接线生效。
- 定向检查几何变化但面数不变、同名对象替换、rename、删除、单位变化、document epoch/reset、阈值 A/B/A、pair 顺序和 witness、来源/实例域变化、低 cap 续查、无绑定 fallback 及真实缓存淘汰。沿用现有反例数据；仅补与本变更有关的缺口。
- 相关扫描、普通 task/nearest、scene cache/residency/delta 回归通过。旧 nearest g06 基线失败继续分列，保持原期望，不为本批改写历史。

初版披露的传输失败等待可能超过父期限、隐藏来源异常保守退化继续记录，本轮不扩成 transport 改造。若优化引入错误 complete 或陈旧结果，先修该缺陷再测成本。

## 同输入配对测量

完成代码与定向正确性后固定一个候选提交及隔离安装。用初版固定安装和新候选做 **5 组配对序列**，每个版本每序列 fresh owned Blender/产品进程，各执行 cold → repeat → 同一登记 EDIT。版本顺序预定 AB、BA、AB、BA、AB；共 30 次主工具请求，另列 Process 定向序列。保留初版旧 15 次原件，但不将其挑选替代本轮配对基线。

计量边界、机器、资产、依赖、参数、QA 方式保持一致。cold 前不能通过 QA、metadata、启动或准备步骤预填 surface measurement cache，两组使用相同操作与顺序。记录请求原件、完整 client 和 server 时段、启动/退出、host wire、资源读取/变换、所有 pair 工作与缓存命中、编码量、内存。工作集峰值继续注明进程生存期，准备/安装/复核成本单列；失败和未运行留在完整计划分母。

本轮预登记的局部优化门：

1. 正确性全部通过，EDIT 新核 10、无关 104 对复用，repeat 0 新核；cold 无新增几何求解。
2. 令 i 为预定五组配对，EDIT 完整客户端请求满足 `median(new_i / old_i) <= 0.70`。cold、repeat 各满足 `median(new_i - old_i) <= max(0.05 * median(old_i), 2ms)`。令 S_i 为三次业务请求之和，要求 `median(S_new_i / S_old_i) < 1`；完整序列生命周期满足 `median(new_seq_i / old_seq_i) <= 1.05`。所有单格与范围仍披露。
3. 原缓存容量上限和内存计量保持有效，新增元数据有明确界；实际内存变化单列。不能通过无限增缓存容量取得命中。

这组门用于决定是否保留工程候选，不代替后续完整模型任务的 30% 目标。完整生命周期若实际增加但仍在 5% 容许范围内，只能判局部请求优化门通过，不能宣称整个生命周期净收益。五组只是固定输入的工程点估计，不宣称分布尾部或跨场景泛化。

修复测量器已知缺口时在本轮新路径创建版本：先核旧资格承诺，公开距离直接对 oracle；按预定 5×2×3 状态表处理缺失/重复/失败，绑定 actor 传递依赖。旧绑定脚本和旧原件保留。不要再用运行时新采哈希代替旧冻结承诺。
