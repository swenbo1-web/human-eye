## 已成立的机制，以及仍未解决的问题

G三格均自发请求geometry，并正确使用框材/孔洞/杆截面信息；P三格关系查询后都补局部形状，G集合内同类补查为0，P为3。P的一次补查只打印先前程序缓存，但这些形状此前未交付模型，仍计补查。G的一格后来读导轨/双管形状并算中心距离，这是集合外新参照与计算，整次调用成本照计。

实际总调用P9→G7，少了两次往返；对N则同为7。不能宣称所有G格都从三轮降到两轮，也不能把内部零新增采集等同于零模型补查。

G三格的模型可见工具响应合计59,024字节，N为39,476字节，增加49.52%。G同时携带关系事实、局部证书和四对象的56顶点/100三角面，另有新增工具schema。少调用与更大单次交付同时发生。这是可见载荷构成，不是对实际token差的精确因果分摊，原记录没有这样的分段usage。

当前资料不支持“模型不信任插件所以重算”的解释：事实与局部证据被正确采用，同域补读确实消失。剩余问题是完整工作量与交付成本的取舍。原生在这道轴向框架/杆件题上可以从实际面几何做短的解析证明，不必执行通用全三角对算法，因此本题也没有证明插件提供了原生难以达到的解题能力。

G三格owner工具执行合计0.618805秒，完整单格合计201.185718秒，占0.308%。若其他环节保持不变，把这部分全部归零，整批墙钟也只少约0.31%。在本题继续追逐几倍内核提速难以改变结论；剩余墙钟不能全部归为模型推理，包含未细分的服务、传输、生成及收尾。

## 唯一推进决定

本批收口，不再为同题geometry调整字段、提示、阈值或补样本。保留 `00b13060` 为显式可用的工程候选，并清楚标记“自然采用/少补查成立，完整净收益未通过”。不自动默认启用，不用Hook预加载掩盖观察链本身的成本，不因当前失败新增daemon、缓存、求解器或专家模块。

总体架构保持一条路：现有宿主驻留与场景代 → 轻量发现 → 按需选择几何和精确关系 → 简要事实与可追溯局部证据 → 同一结果供MCP或后续Hook交付。现有已验代码复用；不把收益维度变成多层串行流程。

下一次研发只由一个独立真实空间任务启动：先固定用户需要的结果、强原生可用捷径、独立真值与完整成本边界，再定位确实发生的失败或主要成本；仅优化命中的一个接点。若是发现漏目标，修筛选/覆盖；若是确实的高密度精测成本，改当前命中内核的数据复用和剪枝；若是文字证据不足，才做局部视觉。没有该证据前，不从报告的所有P0/P1清单自动派单，也不把题目变复杂直到插件获胜。这一入口是未来工作条件，不是本轮已派新批。

Hook必须等同一观察接口有任务价值后才比较开/关；原生得到同等预取机会，计入提前获取和上下文成本。手臂扭转、面部凹陷等内置专家小模型继续在真实纠错需求下独立验收，不混进当前只读消费结论。
