## 2. 最小实现

在现有 `human_eye_scene_observe` 增加显式 `query.mode="directory"`，使用现有只读 owner、来源绑定与请求边界。新增模式要求无图，不接受 pair、goal、delta 或自然语言目标求解；schema 与真实受理范围一致。旧 overview、自动 pair、图像、task、nearest 和写入口保持原语义。

目录只提供实际需要的事实：对象 ID/名称、紧致 evaluated world bbox、范围中心、单位/坐标系、覆盖状态、当前来源代和独立目录摘要。中心保留，避免把已知便宜计算转交模型。复用既有 ID，不拿对象名冒充身份。

- 冷态从 evaluated 顶点求 min/max；可复用同代已有资源。不得把局部 bbox 八角变换后的外包盒当作紧致世界范围。使用原坐标求值语义；如批量算法改变浮点归约，必须单独证明约定精度，不混成逐位等价主张。
- 目录不调用 `calc_loop_triangles`，不构造或传输插件的 faces/edges 数组，不跨宿主发送完整 vertices。Blender 的 evaluated mesh 本身仍有拓扑，不能宣称其内部没有生成几何。不为目录生成完整客户端网格实体、精测证书或动作账本。
- 复用 `SceneResidency` 的 dirty/pose/context 与既有 captures 容器。可按独立目录 key 缓存同代聚合结果；不另建通用缓存、服务或 daemon，不向完整 mesh resource 填假数据。先完成最薄路径，只有实测热点才做一次简化。
- 返回独立的目录结果和摘要作用域，优先直接使用现有 capture_state。**不得把目录摘要写成原完整 scene_fingerprint/revision，不伪造完整 scene_memory/delta 基底或 capture capability。** 目录中的对象可供后续正常 selected task 重新绑定、采集。
- 对不支持、缺失或失败的对象明确覆盖状态，不能静默删掉后报完整。沿用现有数量、期限及发布机制，不提高网格预算，也不新建安全/审计层。无通知旧 host 采用新鲜读取或明确不支持，不假称热复用。

允许最少量 schema、host dispatch、同服务接线及必要测试修改。若必须迁移整个旧 runtime、增加通用谓词语言或伪造完整捕获才能接通，就停止该设计并交回具体证据。

## 4. 验收与成本边界

正确性与实际入口必须覆盖：

- 全对象 ID/名称、tight bbox/center、单位和覆盖状态；不对称旋转非盒证明外包中心不等价；已有凹形/孤立顶点语义按实际支持范围核对。
- 冷→热→单对象姿态修改、几何修改、单位/帧改变、改名、删除/同名替换、撤销/重做、切场景、重载/重连。复用既有 `arch_resident_001` 后台 fixture，不操作用户 GUI/资产。
- 目录→正常 selected task 的两步总成本，以及目录后尝试 delta 时的真实行为。目录不能充当未取得的完整同步基底；需要完整读时如实执行并计入，不把首步省下的工作藏到第二步。
- schema 合法/不合法参数、旧 overview/task/nearest 控制、来源绑定、请求失败后恢复；同代目录缓存不会污染完整 capture 或动作状态。
- 实际服务和隔离 MCP 请求均走到新分支；不只测 helper。固定候选源码、隔离安装与回归须对应同一份源字节。

分别记录每次请求：宿主 RPC、顶点/面遍历、to_mesh、三角化、构边、缓存命中、宿主桥接字节、模型可见文本字节、完整工具时间、内存峰值及采集/传输/客户端阶段。桥接 request、response 和两者合计分列，按真实 UTF-8 传输记录计数，包含所在消息的封装；首次源码建立成本另列且保留在实际请求总成本中。完整工具时间为同一服务入口收到请求至完整回执；进程启动单列。无法测得的项留未测；不得用机械断言数当场景数。启动/安装/准备及两步后续成本单列，不与嵌套窗口重复求和。
