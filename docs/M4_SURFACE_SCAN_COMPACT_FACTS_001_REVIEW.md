## 改动与目标

唯一运行源码变化在 `human_eye_plugin/live_spatial_mcp.py`。扫描结果缺省和 brief 共用紧凑表，explicit full 保留旧详细结构；其他模式默认行为保持。原完整值先通过严格 JSON 编码，再尝试纯展示投影；不支持的结构或展示异常退回完整文本。原非有限值等错误仍在完整校验处报错。

投影直接从已交付 matches 构造对象端点表、六列事实行和公共/例外元数据，没有新的宿主读取、几何求解或持久缓存。对象表按 ID 关联，名称供阅读；只覆盖匹配端点，不能用其 22 项替代 BASE 场景 24 对象的覆盖计数。原米值保持，毫米为派生展示。逐行字段的缺失、布尔/整数区别及 signed zero 不能通过普通 Python 相等比较混在一起，候选使用严格 JSON 编码比较公共元数据。

顶层状态、unknown、coverage、binding、delivery 原语义保留；已在 reducer 截短的结果不会因表示更短补全。见证坐标留 explicit full，其他逐行状态/原因/方法按公共字段与行例外恢复。

这是有意的默认输出合同变化。旧客户端若按 `matches[i].objects` 解析，须识别 `surface-scan-task-table-v1` 或明确请求 full。full 是新的当前观察，不能当旧 trace 的历史查阅；组合结果比较来源和场景 binding。

## 架构判断和下一项

本候选在已有展示入口内解决确认的 brief 绕过和首响应冗长问题。没有引入额外报告服务、分页、查询工具或新的空间计算层。完整编码后再投影有一小段重复工作，其实际规模应与模型完整任务成本分开看；当前没有必要继续围绕亚毫秒展示开销开优化循环。

独立复核保留两个表示边界：同 ID 端点内容相同但字典键序不同，会回退 full，事实不丢；以真实 envelope 复制后置空 matches 的离线探针，正文从 1,546 B 增到 2,243 B。后者说明本候选并非对所有规模都节省字节，不是实际宿主空场景实验。固定 71 对门没有要求空结果变短，本轮不临时改门或换候选；将“少量/空结果择较短表示”列为已知优化机会，等真实消费成本决定是否投入，不再为格式无限加轮。

10 KiB 门只针对固定 71 对基准，约 77% 字节下降不能推成 token、现金费用或完整任务收益。实际 provider 输入呈现仍未采样。完整事实是否被直接使用、full 补查和原生重算是否减少，交同期消费决定。

工程复核通过后执行 [同期三路方案](M4_SURFACE_SCAN_COMPACT_CONSUMPTION_001_PLAN.md)：原生 N、旧扫描 OPT1 详细 O、新紧凑 C，各三格、轮换顺序、同题与预算，先封质量后解成本。O 明确是旧扫描候选，不是桌面历史主干。原 `C/N <= 0.70` 配对中位数和 token 不高于原生门保持；候选相对旧详细改善另外判定。

本轮根复核不启动 Blender、模型或付费 API，不改作者证据、产品、默认配置、原资产、共享 GUI 或竞争分支。独立产物位于 `verification/fixes/20261113_m4_surface_scan_compact_review/`。

根核验过程也留原失败：来源脚本首次误将生成入口与原模板直接比较、误读保护结果/遥测字段，后按登记模板替换、实际字段和文本换行规则核对；工程脚本初次误期待八条 worker 事件，改为分别核九条及 close unknown。原 attempt 结果未删，未改变作者运行或实验分母。三子 Agent 的 AL assignment 仍为旧归属，依根本轮明确委派完成并如实注明；根任务已在委派前登记，没有借句柄补造归属。
