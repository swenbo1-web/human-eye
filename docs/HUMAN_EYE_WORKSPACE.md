# Human Eye 本机目录

Windows 集中入口为 `D:/HumanEye`。打开 `worktrees/main.lnk` 可进入检出 `main` 的目录。桌面配置仍从 `D:/hefe` 定位已安装插件。手工工作树和实验输出也从集中入口管理。

| 位置 | 内容 |
| --- | --- |
| `D:/HumanEye/worktrees/<short-id>` | 新的手工 Git 工作树。路径用短任务名，便于 Windows 上深层证据目录写入。Codex 管理的工作树由应用登记，用本机目录索引记录。 |
| `D:/HumanEye/runs/<batch-id>` | 每批实验唯一的根目录，集中保存专属输入、安装、运行原件、复核和封存。 |
| `D:/HumanEye/releases/<version>` | 供多个批次复用的固定安装，由实验记录其路径和源码摘要。 |
| `D:/HumanEye/publish/` | 既有发布材料和跨批次共用的发布文件。 |

本机入口内已有主仓库和常用历史工作树的快捷方式。完成的 `b32g-whole-release-001` 发布暂存已归入 `publish/`。早期工作树 `he_m4svc_e`、`he_m4svc_p` 和 `hm1rtfp` 仍由各自封存脚本引用。已绑定的验收原件、虚拟环境及正式桌面发布保存在原路径。历史引用以本机目录索引定位。

## 一批实验一个根

开始前核对[唯一主计划](PRODUCT_ROADMAP.md)和[项目进度](PROGRESS.md)，用短批次名创建 `runs/<batch-id>`。在根内登记基线、工作树、冻结输入、输出路径和验收出口。按需创建以下子目录。

- `preflight/` 保存预检、资格和失败尝试。
- `install/` 保存该批专属的构建、依赖环境、安装及启动绑定。
- `slots/` 保存正式运行、原始回包、关闭回执和分段计时。
- `review/` 保存复核、补证和原件索引。
- `sealed/` 保存结批判定、封存包、SHA-256 和公开发布回执。需要准备发布材料时，可在批次根内加 `publish/`。

补跑、复核和恢复批次的相关尝试继续记在同一个批次根下，按阶段或尝试编号放入子目录。结批后保留一处完整目录。需要归档时按整个批次迁移，并记录原、新路径和固定运行绑定。公开文档使用 GitHub 固定提交链接。
