## 消费接口的具体缺口

当前首包coverage的unresolved与candidate_pool_uncovered完全相同，但消费者需要自己解释这意味着当前池内已无新的几何覆盖候选。每个covered面与实际完整视图见证没有直接关联。像素readable只代表正面和像素门限，内部覆盖还要求view mask几何完整；这个关系未投影成直接可用的每面见证。

本次161条readable都确实几何完整，不能把上述字段语义缺口写成已发生的错误放行。已有分类能够解释22个无正面候选和1个遮挡，但默认结果只给finite_camera_pool_uncovered。这些都能复用现有计算改善，不需新增几何算法。

Python globals没有本次产品事实对象，产品图片却已暴露为image_files。SERVICE_RESULT在本槽输出目录，规则没有禁止读取；准确问题是没有向模型提供直接复用的公开结果绑定，不是权限封锁。提供同一已交付JSON原文即可，无需新存储或查询框架。

模型首包后公开称first pass leaves gaps，并实际重算全场景。这支持消费表达存在改进空间，不证明其心理“不信任”，也不能唯一确定上述哪个因素导致重算。

## 两个失败不能混为一谈

第一段是预算内任务没有完成。owner第13请求在业务执行前拒绝；继承consumer收到该事件后主动按工具额度终止并清理，正常final发布代码未运行。四条agent_message是进度，最后115/23不能由审计器补成final。CLI exit1不证明provider自行崩溃；后置kill_requested=false也不能证明更早finally从未调用kill。

第二段是新launcher的末端判据缺陷。route失败及RUN_RESULT保存后，前后marshal摘要比较又抛异常。独立compile-only见证证明同一code对象、相同字节码，仅保留常量引用就能改变marshal字节，因此该稳定身份判据不成立。实际只有三项marshal摘要变化；9项新鲜指针检查及8项旧快照为true。全部源文件一致。原进程未留原marshal/co_code字节，具体内部变化仍未知。

最小修复是删除不稳定marshal比较，沿用源字节与实际对象引用；末端状态始终发布。无需增加替代防御层，也不能因为收尾错误自动重试真实会话。这个缺陷发生在消费失败之后，不能解释之前的重算。
