## 冻结前仅补以下内容

### 1. B 与 I 的公开责任相同

现有 B 还是功能探针：`image_mode=None` 仍调用渲染器，所有对象的公开代号来自 moving reference；上下文使用统一 changes；反馈直接调用写库，尚无计划/票据的会话绑定与一次消费。不能拿这个较少责任的 B 测量完整生产接口 I。

在验证侧 B 补齐同一正路径工作：每对象变更声明/代号、明确无图、计划绑定、调用者持有的轻票据及一次消费、参考替换、关闭。相同输入、附带数据、必要拷贝和操作检查必须进入相同计时段。B 仍直接组合现有组件；不得调用 I 来伪造独立对照，不增加重复 capture/encode、通用校验器、历史账本或自动恢复链。已正确的共用 bridge、无额外 after observe、before PNG 复用、一份必要位置快照继续保留。

冻结以下简单状态语义：新观察、执行开始、参考替换和关闭撤销旧 plan；活动会话内迟到的 V/A 票据可对当时实际样本更新一次，参考替换不抹去已执行证据；关闭后及跨会话票据不可写入。复制票据不受支持，不声称每副本一个 bool 能防任意复制重放；无需登记账本。无图状态、`NoAction` 原因及公开 `NONE` 拼写写清。静态 relative basis 绑定明确对象/key/relative_key 和 authored 坐标定义，缓存期间定义不变，仅 q 改变；修改定义须显式重新预备或新建会话，不做扫描/hash。世界 basis 使用当前实际 scale/A。

### 2. 上下文拓扑变化有明确新代入口

草案允许上下文 `TOPOLOGY`，构造传入的 generations 却固定，后续没有给出新代号的接口。修订为调用者在声明此变化时同时明确提供新的 context generation，并说明持久化到哪次 capture、如何进入 AO 的每对象身份。目标对维持单会话固定拓扑；替换目标按原约定新建会话。测试一次上下文换代而目标不变，公开原面/代号必须正确；不引入自动探测、哈希或世代账本。

### 3. 已写宿主后的错误不能丢失已取得的实测结果

原提议 callback 位于目标 BC 完成之后、`Outcome` 物化之前。CPU stub 已证实这一排序可以在真实命令写入后因 context callback 异常而无 Outcome。它不是已部署生产故障，也不应把 CPU stub 称为原生证明。

修订最小 seam 的精确顺序：在同一 graph/override 中完成目标回读及实际控制量，物化 Outcome 后再执行 after context callback；保留同一次目标捕获。目标/控制量回读本身失败时不能编造 Outcome，应明确宿主写入阶段和缺失的实测结果；context、图像或 AO 发布失败时携带已经取得的 Outcome。失效的 before 不可再执行，调用者按显式状态决定下一步；没有自动重试或回滚。这是写入操作的结果语义，不是额外的运行时防御策略。

提供限定的故障注入证据：写入前拒绝、写入后目标读回失败、目标已测后 context 失败、后图/AO 失败；区别真实原生测试与 CPU stub。默认无 callback 的原控制器接口及相关测试保持兼容。下一次修订给出最小 seam 补丁草图，仍先不修改生产文件。

### 4. 先固定可执行的计量方法

保留原提议：3 串行进程、既有 3 个模型、24 固定主例、每例 5 次配对预热及 31 次交替重复；连续四子段与整段、每例中位再取跨 24 例 linear p95，I/B 各进程各段均 ≤1.05。原 CF 两独立场景的 ≤1.10 回归单列，不能用旧 58 ms 与新单场景直接算提速。

这个门约束集合 p95，**不等于每场景无退化**，尤其不约束最慢单例。逐例、各族、最差例、绝对时间及全部配对原始样本必须披露。本轮不另加逐例性能硬门，也不在结果出来后更换统计。已知完整质量失败照原样保留，I/B 输出等价要求不放松。

反馈段没有现成计时噪声证据，不能预先给予绝对时间宽限。先用已补齐 B 的 B/B 小型方法探针明确时钟、配对顺序、复位边界、模型状态和计量能力；它只审核测量方法，不产生 I 收益成绩、不取代正式三进程。无法分辨 5% 时先报告原始数据与限定修订建议，不能直接记 PASS。

托管常驻额外 ≤256 KiB、峰值 ≤1 MiB，以及 RSS/GPU 额外各 ≤8 MiB 目前是候选门。补充明确的独占 buffer/共享 base 去重、托管峰值捕获、RSS 采样和 GPU 读数方法、采样点及 I/B 资源归属；冷加载、参考建立/替换、热态与 close/reopen 分开。只报对象数或 `nbytes` 不能冒充 driver GPU 字节。不可得项标待验证并提出事前可审核的替代测法或清楚限定的范围；没有读数就不能把该项记通过。主干看到可执行方法后统一冻结，不在正式结果后倒推口径。

计时内包括真实 API 的票据绑定/消费操作；区间外只放离线反馈查找与对归档 PNG 的重放身份核对。独立资源轮不得污染正式时延；同进程 B/I 共存或历史 high-water 不能归因单臂新增峰值。

补正式运行清单：逐阶段 ID、帧、mode、命令/下一命令、逐对象 masks/generations、参考、Top-K、部署与反馈输入。24 主例不变，预定但未运行的控制逐项列为待验。源码身份覆盖实际运行及消费者的项目依赖闭包、脏文件/未跟踪参与文件和精确命令/环境。现有作者源包只覆盖部分依赖，主干复跑增加了绑定范围，但不追认旧运行已封存完整闭包；正式轮需补齐。
