## 单一实现

1. 用现有生产 stdio 入口显式启用一个隔离的区域任务交付选项（建议 `--region-task-evidence`），沿现有 server 对象传入。仅在 `human_eye_scene_observe` 的 `active_observation + region_task` 成功回包生效。用同一公开工具及参数 schema，在隔离工具说明中明确该入口的 `full` 交付完整任务证据，常规诊断从原标准入口按原 `full` 合同获取。隔离入口的省略、`brief`、`full` 都沿既有简报投影，只在服务端选择输出形态，实际请求和服务调用参数原样。标准入口默认及显式 `full` 行为逐字节兼容。先确认实际服务调用只以该参数决定公开交付，若参数同时决定底层工作或权限，先取得原始证据并在本批停止，保留原语义。
2. 复用现有 `_project_region_task_brief` 及其源、图与量测核验。结果保留既有格式和直接事实，取证绑定继续沿当前机制。一次投影直接编码，避免先编码完整诊断正文或预写诊断文件。保持原 PNG 字节、图块顺序、有效回读及无图/未知的语义。其它工具、普通目标、独立 `source_region`、错误、限时、关闭沿原合同。优先把改动限制在现有启动入口和公开编码处。

## 本批准入

1. 冻结基线和唯一候选的 Git、wheel、安装、目录和回放输入。至少实际走一次安装后的生产 stdio 启动入口和同一派发路径，封存 initialize、tools/list、原始 TX/RX、退出码和 EOF。仅用封存 read-only 生产数据代替宿主采集。回放预检实际走这条启动和退出路径，再进入正式离线资格。无需复开客户端目录代理、启动 Blender 或新模型。
2. P2/P3 显式 `full` 在标准入口保持原始完整语义。相同生产者及序列化条件下，两版标准线包除已归档的动态标识外同字节。隔离入口省略／显式 `brief`／显式 `full` 与标准同版简报等价。每份夹具的模型正文 ≤10,800 B，配同序的三张原 PNG（共 8,671 B），通过固定 CLI 三工具头 × 结果/历史两阶段。逐件核三候选、两局部、六条具名挡片、同名 SCENE 各自 frame/scope、引用和公共图像回读。额外控制覆盖较小区域结果、带联合量测、无图、遮挡或数值未知、过期来源、不合法参数与紧接的正常请求。普通目标和 `source_region` 各使用有代表性的真实 `full` 回包作同字节对照。投影失败按现有业务错误处理并保留原证据。
3. 记录实际正文、内外线包、图片和既有交付审计，分段记录投影/序列化/stdio 与退出，保留所有首次失败。用原件证明每请求一遍服务派发和正常图像读回，不新增采集、栅格、全文写盘或新图重复发送。只为已实测的重复工作做一次局部优化，先复用已有逻辑；没有实测热点则记录后收口。合同无法维持、需要新代理或持久文件服务、关键质量或固定回放不通过则封存停止。
4. 产品及证据放各自隔离分支。默认安装、共享配置、竞争分支、原资产、Google、额外 API 及费用均保持本轮范围外。本批只取得工程和固定 CLI 证据，用量、模型采用和完整任务收益留未测。完成后回报 `M1-REGION-TASK-FIRST-PACKET-PROJECTION-001_READY` 至规划聊天 `local/01a1971f-eef5-7a23-a1b1-2352beb80a77`，附产品、证据提交与分母，等待独立复核。
