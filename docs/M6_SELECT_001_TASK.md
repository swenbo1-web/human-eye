## 必做工作

1. **核对当前事实。** 阅读现有诊断、几何修正、来源和反馈链，核对 `verification/m6_value_baseline_001/BASELINE.json` 与历史复核。旧模型确有 145 个训练参数，但其质量记录没有证明超过直接几何；不得重新把工程贯通写成学习收益。
2. **输出数据与标签清单。** 对保存的 11 资产/77 姿态数据实际统计：资产/绑定/派生关系、输入、标签来源、独立划分和重复特征。列出哪些样例只支持诊断，哪些含可接受修正/候选结果/序列；缺少的字段明确缺少。历史结论与本次实际复算分栏。
3. **选择一个下一步代表性问题。** 优先从已有手臂链和真实缺口出发，比较异常定位、候选选择、直接修正预测各自是否有数据和明确收益空间。面部问题可纳入数据可用性分析，但本批不同时扩成面部/动画产品开发。固定角色适配和跨角色通用专家分别说明，不能互相冒领。
4. **实现并运行最小诊断探针。** 至少保留“当前闭式几何已能解决”的控制；再对所选问题运行一个能揭示真实信息/标签/算法缺口的探针。可使用保存样例重放、特征等价性/重复检查、任务条件对照或独立几何计算。若构造新例，先登记构造和答案来源再运行，不能不断造题直到几何输。未发现缺口也是可接受结果。
5. **给出至多两个模型候选。** 从树、MLP、RBF/形状基回归、点云/网格网络、时序方法中，根据实际输入/标签/目标筛选；不要求恰好两个，也不预先固定任何一种。说明每个候选的输入、输出、训练目标、样本来源、推理路径和预计最大成本项。候选排序只是可能的任务形式，不能代替架构选择。
6. **形成下一批可执行对照方案。** 使用同任务、同资产划分、同质量目标和完整成本，与合理直接几何基线比较。若比较不同表示，明确这同时改变了输入组织，不能把全部收益归给网络。先列模型训练需要补的数据，再确定训练和验证规模；不以当前两资产保留集宣布泛化胜出。

## 本批运行边界

- 可以新增离线审计/数据探针代码和本批结果，使用现有本地 Python/NumPy、单线程运行正确性分析。原数据、权重和已验收产品保持不变。
- 本批不启动全量训练、超参数搜索、正式模型消费或新付费 API；这是选型审计，不提前训练某种模型来倒推选型理由。
- 不把非独占机器上的探针耗时当正式性能成绩。可以统计操作次数、输入输出量和实际运行范围；正式计时/Blender 窗口由复核者安排。
- 现成真实资产可先只读清点来源、文件和已有导出数据；没有可信局部 patch 时继续完成独立审计，记录缺口，不修改资产或共享 GUI。
- 数据问题和可恢复脚本错误在本批内处理；任务含义、原资产动作或账户接入出现真实阻塞时报告具体原因及仍能做的工作。

## 交付与验收

在自己的工作树下保存 `verification/m6_select_001/`：

- `REPORT.md`：当前瓶颈、代表性问题、实际证据、模型候选比较及唯一建议下一批；作者记录与历史证据分开。
- `DATA_INVENTORY.json`：来源/散列/资产分组/输入/标签/划分/重复情况，保留缺失项。
- `audit.py` 或相应小型可复跑工具、必要探针输入与 `RESULTS.json`：命令、环境、实际分母、成功/失败/未运行。
- `NEXT_TRIAL.md`：最多两个候选与合理几何基线的同任务对照，包含数据缺口、主要指标、完整成本和结束条件。
- `HANDOFF.json`：cycle `M6-SELECT-001`、固定提交、工作树、结果路径与回报状态。可在提交后生成回报文件，避免自引用提交散列。

验收不要求证明某模型一定赢，要求据实际信息排除不合适路线、提出可验证选择。没有发现学习机会时，说明直接算法能覆盖什么、下一项真正缺少什么，不能用扩网络或修改标签凑出优势。
