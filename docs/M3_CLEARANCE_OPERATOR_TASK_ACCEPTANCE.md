新增 `OperatorClearanceTask` 复用 `TrustedTaskEntry → 原 TaskGrant → OwnedGoalScheduler → 原父/子账本 → 固定 BlenderProcessHost`，没有新增求解器、动作循环或清账路径。与[顶点任务](M3_OPERATOR_TASK_ACCEPTANCE.md)只复用有限JSON/文件摘要工具，不复用授权对象或预算：刚体仍要求精确 `ClearanceTaskSpec` 和 `TaskApproval`，参考顶点恢复内核不接受该批准类型。

操作者profile严格固定运行源码、Blender二进制、输入 `.blend`、连接配置及其摘要，并携带具体对象对、原参考三角/唯一支撑发现、目标间隙、容差、方向和有限额度。启动后绑定实际PID、文档/对象实例、完整原始/原生源及解析后的三角。核对真实Popen启动参数与profile中的文件、二进制及固定worker路径，不以“协议相同”代替“启动了指定场景”。


JSON本身不是批准；受信本机调用者必须已有该具体任务的操作者授权。没有由模型参数提交的 `approved`、时间或新额度。此入口不会阻止同账户任意Python修改程序；该对手不在产品边界内。没有给当前MCP自动签批、没有改destructive注解、没有把本机入口说成默认消息自动授权。旧MCP真实表单路径原字节保持，仍可单独使用。

## 预算、保存与结果质量

原窗口从操作者启动登记起算，包含初始化、捕获、来源绑定、登记与执行；最多30秒、8步、3段、单步1毫米、累计8毫米，使用原恢复/停止规则。登记、状态读取、执行和重启均不重发grant或续期。一次排他任务目录即消费启动资格，未完成也不能从JSON恢复；另建任务目录不能绕过原连接账本中的pending/unknown。

执行后追加独立整场景原生回读及物理账本核验：非目标对象完整不变；目标局部顶点/面、非Z矩阵项和世界XY保持。独立原生事实必须有效；完成结果须满足目标容差及原完成持久化语义。固定worker不保存输入文件，末次文件SHA保持。

物理事实、核心完成提交、操作者回执提交分别记录。实际apply回执丢失时保持未知，不能根据终点猜测完整路径。核心已确认四次动作、但本层回执文件失败时，保留已知四次及物理完成，报告 `task_receipt_persistence=unknown` 和 `review_required`，不填零、不自动重跑。完成后关闭的物理账本会按旧协议把 eligibility/complete 标为false；它不等同于计数未知，独立验证按closed合同检查历史计数及原绑定。
