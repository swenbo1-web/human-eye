## 分析修正与历史失败

冻结分析器首次因暖缓存没有pair_calls而报KeyError。固定代码确实只初始化三个内核计数，cache hit绕过compute；pair_calls/rank_calls由冷compute追加。派生分析直接核三个必需零计数和cache hit，把额外未发字段标未发，没有补零冒充测量。cold五字段及数值分析不变。

作者post-run首轮的PNG列表、Windows文本换行和暖字段预期错误保留。SCRIPT/stdout/stderr先由write_text落盘、内存摘要另计；限定这些文件的LF/CRLF往返关系有代码与逐文件证据。源码、安装、pin和wire始终按raw bytes核对。

本轮运行子审也保留自身首轮错误：将原始host_identity与compact投影作全字典相等，误报88失败。固定投影代码明确将object_instances拆入target/candidates实例字段，并去掉与context重复的scope。修正版逐项核完整对象集合、实例、代次与范围，88/88一致；原失败RESULTS.json/脚本留存，有效结果为RESULTS_r2.json。没有用删除绑定检查来取得通过。

## 完整成本边界

实测入口程序批次11.9622809s，内含运行前Git检查约0.8893s、文件检查约0.0683s；四会话合计10.8087924s。business loop约3.9450s中已含即时核验约0.4924s，不能重复相加。metadata约3.0958s包含等待实际产品就绪，Popen调用自身耗时不等于全部启动。

这些不是完整研发耗时。实施聊天从开始到最终回报约4318s（约72分钟），包含准备、代码及分析纠正、审查与交付；与程序运行窗口重叠，不能相加，也不能摊成每个产品查询成本。后续必须复用已验消费者链，避免为有限对照另建测试平台。

纯callback、无QA生产延时、worker OS峰值、单请求分配峰值、模型收益均未测。当前RSS为进程生命周期高水位。
