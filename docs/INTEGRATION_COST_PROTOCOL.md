## 运行前提与基线

生产接线完成，实施方先完成既定 24 主例及控制、公开消费者、旧组件默认接口和旧 CF 质量回归。B 仍为 `42ddcf2` 的直接组合基线，使用相同已验收 RB/BC/TD/VG/AO/CF 及相同部署；必要公开接口适配必须保持相同责任，不让 B 重复 capture/encode，也不让 B 少做绑定/消费/发布。生产 I 与 B 的公开 AO/PNG、真实 Outcome、TD/Top-K、原面、方向/ray、CF 输入/更新、采集次数和生命周期先逐例等价。既有严格负样本原样保留，B 成功例不能丢失。

正式前一次登记全部源、实际模型/反馈输入、场景清单、逐阶段 masks/generations/IDs/帧/mode/命令/参考、设备线程和具体命令。冻结运行不得并发写其源码集合。保存 Blender/Python 可执行摘要、实际 Python/NumPy/Pillow 版本路径、GPU/backend/driver 和影响线程/设备的白名单环境有效值。项目源码归档及观测导入不冒称完整动态库或文件打开事件审计。

原三部署 seed 为 20261105、79463、310519。使用封存模型的等价部署导出，不再拟合或凭新成绩更换模型。正式主清单仍六族×四变体，共 24 例；所有失败和局部代价保留。反馈由功能轮真实输出的独立评分预先生成并绑定 PNG/方向/ray/操作，不能让生产内部 oracle 自贴标签。正式运行前后与所用反馈逐字节/语义对账。

## 同场景时延

三个独立 Blender 进程串行，每进程对应一个既有 seed；固定相同设备和软件、Blender/BLAS/OMP 单线程。每案例 B/I 分别持有独立同状态实例，物理实例、创建序号与 B/I 角色分开记录。创建顺序按 `(process_index + case_ordinal) % 2` 交错；实际执行顺序按 `(process_index + case_ordinal + pair_index) % 2` 交替。每例 pair 0–4 为五对预热，5–35 为 31 对计量，不改标签来隐藏创建顺序。

计时外精确恢复 authored 宿主通道、参考和模型活动状态。当前 240 活跃行、未环绕、每轮新增 V 两行/A 至多一行时，可恢复 weights+writes 并核对完整活动前缀；不得把该简化推广到满环或修改旧行的情形。两臂初值一致，本轮反馈真实写入本臂活动模型，next 读取同一更新状态。

| 区间 | 必须计入 |
| --- | --- |
| t0→t1 | 前观察求值/capture、BC、完整 TD、CF、VG 同步读回/PNG、AO bytes、附件和 V 票据 |
| t1→t2 | 明确命令预测、计划绑定/消费、必要 before 快照、宿主写入及真实后回读、后 TD/VG/PNG、联合 AO 和 A 票据 |
| t2→t3 | 当前实际 V/A 票据检查、消费、真实参数/库更新及必要复制 |
| t3→t4 | 下一次完整真实观察和后续明确命令预测 |
| t0→t4 | 同一次连续服务区间，不由四个统计量相加 |

沿限定诊断保留绝对 QPC t0…t4、next-observe/predict 分界及 GC 事件记录，GC 保持正常开启。仪器两臂一致，记录观察开销，不因命中 GC 或慢事件删除样本。模型复位、离线标签查找、独立评分、证明整理及归档写盘在区间外；真实票据入口的检查/消费仍在区间内。不要在 t3→t4 插入哈希或模型副本。

t4 后以相同审计工作核对公开 AO/PNG、next 已保存的视角/动作字段、模型活动数组及绑定；before/after/next 的共同会话内唯一 ID 可在 B/I 两个独立会话中使用相同角色值，避免把任意 ID 重命名扩成宽泛字段豁免。只豁免原已声明的私有相机自动名字。完整 TD/采集责任由功能轮及冻结源码验证，不能仅凭 next hash 代替完整质量门。外部真实消费者另报实际评分/等待在内的闭环，不把服务区间冒称外部模型总耗时。

每案例每臂取 31 次中位，每进程对 24 个案例中位求 `linear` p95；前观察、动作、反馈、next 和连续 total 的 **I/B 各自均 ≤1.05**。三个进程分别判定，pooled 不能补救失败进程。报告全部原始值、逐例/各族/最差例、绝对 p95、比值和配对差。该门是指定清单的集合预算，既不证明每例无退化，也不证明测量噪声始终小于 5%。不追加逐例硬门，不用 ABBA 块统计替换原判定。

原 CF 三 seed 的 V、A 和旧两个独立场景串行 total 沿原边界 **各 ≤1.10**，原质量/射线/MAE 门继续成立。旧 CF 成本与新单场景成本分别报告，不用两场景旧总时长对新单场景计算“提速”。

## 资源：固定可测对象和承诺范围

正式资源轮与时延轮分开；托管追踪与 Win32/DXGI 采样也分开。每种资源仪器各用 B/I×三 seed 的独立新进程，单进程按同一 24 例顺序运行。每例建立相同初值、预热五条等价链后复位，再测一条完整热链；冷加载、参考建立/替换、关闭/重开和异常释放单列。功能控制的冷成本不混入正常热态统计。

两臂统一保留/释放调用者返回 bytes 和票据。验证 B 的内部 ObservedFrame/fact、审计局部变量不能成为额外历史；完成核对后清除所有临时引用，包括 `for frame,...` 的循环变量。B 为手工编排必须保留的当前事实、参考和动作前快照仍如实计费，不以删掉真实责任降低基线。不能仅清 I 的返回值而让 B 保留，也不能反过来。

### 托管内存门

导入后、创建模型/会话前开始 tracemalloc。初始化和预热结束，在 t0 前读取 current 并 `reset_peak()`；t4 后先读取 current/peak，再生成 owner 清单和报告字典。正式托管轮不启动 OS/DXGI 采样线程。记录完整窗口峰（包含原已活分配）及其高于起点的增量，两种值不可混用。

对每个 seed、每个对应案例及预先规定的保留点，热态 current 的 **I−B 最大差 ≤262,144 B**；完整 t0→t4 窗口 peak 的 **I−B 最大差 ≤1,048,576 B**。负差保留，不以别的案例负差抵消正差。根集合包括 bridge/index、模型/经验库、参考、渲染缓冲及调用者公开输出/票据，明确哪些是内部临时态；沿真实 backing 去重并列归属及共享关系。NumPy owner 字节只作归因，不再加到已含它的 traced current/peak。无法覆盖的新类型显式处理，不能静默计零。

保留点至少含：初始化/参考建立后的冷点、热链 t4 公开输出仍持有、已消费票据且外部输出释放、参考替换、close 时外部 bytes 仍持有、外部引用释放、重开后的对应点。冷点和异常轨迹单列；正常热态门不把启动以来累计峰当成热峰。

### GPU 逻辑资源及生命周期门

I 使用与 B 相同数量、尺寸和格式的 VG offscreen/纹理/批次及相机资源；统一接口不得额外常驻第二套 renderer、bridge/index 或完整历史。验证层登记实际拥有者和资源创建/释放，不在生产中增加监控账本。close 必须释放本会话持有的原生 offscreen/相机及模型/数组引用，调用者保留的 AO/PNG bytes 仍可消费。

固定执行 close→reopen 对应状态，并检查本会话引用/资源不串到新会话；不以 allocator/驱动未瞬间归零断言泄漏，也不以一个空根宣称全进程零占用。检查完成后清除验证者为审计保留的 renderer/私有结果引用，再看外部释放后的托管状态。沿用既有 VG 内核，不为本门重开 VG 优化。

### RSS / DXGI 观察最大值门

采用目标进程自身的 Win32 WorkingSetSize 和固定 adapter LUID/node 的 DXGI LOCAL、NON_LOCAL CurrentUsage。GPU 值固定为**同一记录中 LOCAL+NON_LOCAL 之和**，同时分列两组；不能相加两个不同时刻的单独峰，不能选择较小一组，也不与 RSS 相加。PrivateUsage、Budget、Reservation、进程 lifetime peak 仅作诊断，不冒充本热窗读数。

目标周期仍为 2 ms，但它不是已实现的采样覆盖保证。每次查询记录起止时间、错误、实际间隔和阶段边界；在 t0 前、每个主要阶段结束和 t4 后取得对齐分点。每个对应热窗的观测集合为这些预定阶段点加上完整位于该窗内的有效周期记录。窗口最大值定义为该集合的最大值，明确命名 **observed sampled maximum**。

每 seed/案例该观测最大值的 **RSS I−B ≤8,388,608 B**，**GPU（同记录 LOCAL+NON_LOCAL）I−B ≤8,388,608 B**；每个窗口分别比较，不能用 pooled 抵消。完整披露采样数、首尾覆盖间隙、最大实际间隔和查询持续时间。无有效窗口样本、必要阶段点缺失、查询失败、buffer 饱和或适配器归属不明时，该项是 UNVERIFIED，不能填 0 或 PASS。

这是在任何 I 资源成绩产生前，对原候选“峰值”承诺作出的明确限定：**不认证采样间隙内的真实瞬时 RSS/显存峰**。本机诊断已出现 22.402 ms 间隔，不把标称 2 ms 写成实测。新增持久 GPU 状态和资源释放由上面的逻辑资源硬门另行约束；该门也不能推导所有未采到的瞬时驱动分配。

## 执行及失败规则

满足生产功能自测、同责 B 和登记条件后，授权按本协议执行一次完整正式成本试验；不要求再做无边界 B/B 资格循环。诊断两次通过只是主干选择此有限前瞻方法的证据，首次 B/B 1.076810 失败仍有效，根因仍未确定，不合并成新的历史 PASS。

保存全部失败源码、输入、原始时序和输出。计时门失败、质量不同、测量不可用或输入/源码/统计需要改变时，报告精确范围，等待主干事前限定后续，不自发加测直至通过。正常功能工作可继续。成本成绩由实施自测后主动回传主干独立验收；本协议本身不授予整机 PASS。
