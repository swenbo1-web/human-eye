## 2. 一个直接入口和准确的任务语义

复用 `human_eye_scene_observe`，新增一个 `query.mode=surface_scan` 和有限非负 `threshold_m`。默认范围是当前场景全部 mesh，包含隐藏 mesh，沿用目录对象范围；请求不需要对象名、目标、候选数量、Top-K 或 requested_facts 组合。

固定消费者问题（本批只冻结，不调用消费者）：

> 检查当前场景全部网格对象，列出所有两对象三角表面最短距离不超过 2 mm 的对象对及距离，并说明检查是否完整。这里仅要求表面距离，不要求判断实体穿入或包含。

谓词为 `surface_distance(i,j) <= threshold_m`，等号包含。按实际捕获 binary64 数值的精确平方距离与阈值平方比较，使用现有 exact distance key，不能对四舍五入后的展示值分类。

公开结果给全部匹配、距离、必要见证状态、覆盖计数、未解原因和当前来源版本。负例不逐条发送给模型，完整 dispositions 留在诊断证据中。匹配数超出交付预算时明确未完整交付，不以 Top-K 代替找全。

**表面距离不是穿透深度。** 包含关系即使表面相距大于阈值也可能实体重叠；本任务把它判为 surface nonmatch，不得宣称无碰撞。后续实体扫描需要另一个谓词和闭壳算子。本批不默认请求 spatial/closed，以免重复计算无关事实。

覆盖全集为当前 N 个对象的 `N(N-1)/2` 个无向 pair，0/1 对象和零候选都有明确空结果。守恒式：

`total_pairs = bound_excluded + measured_match + measured_nonmatch + unknown + deferred`

全部已判定且无 unknown/deferred 才标 complete。已知全集但未做完为 partial；全集/当前来源不能确认时为 unknown。排序只影响先后，不减少全集。不支持的来源须体现在范围/未解记录，不能静默跳过后称全场完成。

## 3. 最小算法与架构流程

`任务参数 → 同一窗口目录/包围界 → pair 宽筛 → 候选端点去重并一次获取 → M3 本地求解 → 覆盖与结果`

1. 复用 nearest 现有 outward 包围界与保守距离下界。仅当下界严格大于阈值时排除；未知界保留。第一批 24 对象的上三角数组宽筛足够，先记录它的实际成本，不另建空间数据库或通用规则语言。
2. 在一个宿主同步读取窗口确定全目录和候选端点 union，每个所需对象最多展开一次，复用 resident resource/pose 和 wire delta。不要先走会遍历全部求值顶点的 cold directory，再为每对重新读取；不把昂贵精测放进 Blender 主线程。
3. 同一次 ReadContext 正常化一次，服务端对候选逐对调用已有 `_surface_pair_measurement(... retain_exact_rank=True)`。一对最多一次新求解，pair 之间不发模型或宿主 RPC。可按下界和廉价工作估计排序。
4. 状态挂现有 ReadContext/scene_cache：任务参数、版本、pair dispositions 和未解队列。复用现有取消、请求期限、数据预算和每对几何工作上限，不加新审批或通用保护层，也不逐 pair 重置期限。
5. 没有候选时只交全目录绑定与排除计数，支持 0 个展开对象；不能制造假目标以通过 nearest 的旧校验。空场景还需在扫描专属路径支持空目录，当前 `_objects` 拒绝 0 对象，仅改 union 校验不够。当前 256 对象等现有入口包络如适用须明确，不能将本次 24 对象样本写成任意规模已支持。
6. 被工作上限留下的 pair 计 deferred；有合法排除证明和命中缓存不算新精测。硬超时沿既有错误协议；可控工作上限的测试要在剩余交付时间内返回真实 partial。旧 partial 不能永久缓存成一个无需续查的终局。

首版沿 existing nearest 的静态独立三角源域，开放且有效的三角面可进入表面距离。invalid/degenerate、modifier、实例等按实际支持情况记未解；不在本批同时扩源域。包围界的几何包围前提须由资格导出顶点独立核验，不能仅凭浮点 outward 认为 API bbox 一定适用。

预计改动在 query/schema、live_service、现有 host 命令与传输两条接线、auto_router 的扫描 scope/空 union、task_query reducer 和 scene_cache。提取共用获取代码，不复制整个 nearest 引擎。工具 schema 和普通返回投影必须贯通；只有内部 helper 通过不算完成。

### 明确保留的一轮优化

初版先测 cold → 静态重问 → 单对象刚体移动。根独立审计后，优先消除“全场 generation 改变导致无关 pair 重算”。沿现有受信资源版本、对象 incarnation、姿态及 document epoch 建 pair 依赖键，复用未变对象对，更新受影响 pair 和目录；不另存一套几何。

这是有依据的首选候选，最终仍以初版 trace 为准。若初版已无此冗余，根复核选实际最大的另一项重复工作。按已批准流程至少形成一个实质优化候选并同输入测量；无收益则保留更优实现和失败证据。不要为满足轮数制造无关代码。全场索引/BVH 跨 pair 重构不预先加入本批。

## 4. 先冻结一个能核清漏检的输入

构造一个固定 **24 mesh 装配单元**：底座、长导轨、U/L 支架、滑块、盖片、垫片、止挡、销/隔套，共享空间并有多对象相互作用。对象中性命名，至少两个有匹配的装配子区，不把目标集中在 active object 周围。不能用 12 组独立盒对或一堆远物体制造收益。

几何应含斜长件、局部凹槽、薄片、开放有效表面、重叠 AABB 但表面不匹配的负例，以及表面间隔大于阈值的严格包含控制。主问题是距离匹配，不把所有装配接触叫做缺陷。建议 600–1600 总三角面，每对低于现有准入；最终规模以独立真值可完成为准，不靠无效重复细分加难。

按以下顺序推进，不等下一次人类确认：

1. 创建合成副本，原生导出实际求值世界坐标/三角形、单位、帧及目录；冻结生成规则。引擎输出尚不参与选题。
2. 独立列全 **276 对** 真值。oracle 不导入产品几何/候选代码，处理所有 pair，不只核产品返回项。采用独立相交与点面/边边距离，精确有理比较；如自行使用剪枝，记录其独立包围证明和全 pair 覆盖。用解析可核的间隙/接触控制交叉检查，分歧先解决。
3. 输入应同时有可宽筛排除、需要精测的负例和真实匹配；至少 69/276 对不能仅凭采用的 AABB 下界排除。记录实际比例及匹配数，但不告诉消费者。若资格未实现，最多按预先记录的形态调整一次；不得观察性能或消费者输赢后换题。
4. 固定同一资产的静态重问与一次局部刚体移动，新状态也保存全 pair 真值。资格通过即提交输入/真值冻结点，再实施产品；不另造等待审批阶段。

若 oracle 太慢，先优化独立验证的实现或在冻结前减少无关重复三角化；所有未判定对保持未判定，不算阴性。未实现预定几何时如实回报，根决定下一项，不无限重构样本。

必要定向工程检查：阈值等号与紧邻两侧、零对象/单对象/零匹配、invalid bound、源域不支持、低工作预算 partial、名称/active 次序改变、删除、撤销/重载 epoch、局部移动与来源变化。复用既有测试架构，保持相关原期限/取消/缓存和 P1 数值反例，按受影响范围跑回归；不机械重跑无关历史大矩阵。

同一固定候选核源码、隔离安装和实际支持的宿主入口。原始记录至少给：全目录对象/面数、宽筛 pair、保留 pair、端点 union、实际展开点面/世界变换、host RPC、kernel/work、缓存命中、编码字节、驻留/峰值内存和端到端服务耗时。cold、静态重复、局部变化分列，启动/构建成本单列且不消失。

本批工程时间使用固定、事先说明的配对次数（建议 5 个独立进程序列，每序列 cold/repeat/edit），不把重复的同一输入算成多个场景。运行发生可恢复错误时保留原记录，在原预算内修复；产品改动后重新固定候选再比较。外部时延与求解时段分开。

初版并不等于模块验收完。后续顺序：**初版 → 根深审 → 一轮实际优化 → 根复审 → 固定 N/P 消费**。N 可批量导出、用数学库/BVH/脚本缓存；连续状态测试保留双方进程/缓存，不能让 N 每次从零而 P 热态常驻。双方均不获得 oracle 或预选对象。

后续消费者门继承批准架构的中等任务目标：同质量，完整任务配对中位时间降低至少 30%，同时披露全部 token、费用可测性和完整准备成本；总 token 不得被默认为已改善。失败/遗漏/超时在总分母中。本工程批不提前启动这些消费者，不把局部 handler 提速称作完整收益。
