## 3. 最重要的新发现：M2 能采集，不代表 M3 能精测

当前 `surface_proximity._admit` 在进入几何计算前检查：总三角面数不超过 4096，且两个对象的面数乘积不超过 16384。闭实体关系也调用同一准入逻辑，此外还有顶点、拓扑和实际工作预算。

根本次使用核对过 `fac9b437` Git 字节的两个模块，构造几何完全相同、仅表面细分不同的两个闭合立方体。第一个为 `[-1,1]^3`，第二个沿 X 平移 3 米；独立解析答案为分离、最近距离 1 米。网格检查包括边关联数均为 2、Euler 特征为 2，细分面覆盖同一六个平面。

| 每个对象 | 两对象面数乘积 | 表面距离结果 | 闭实体结果 |
|---|---:|---|---|
| 8 顶点、12 三角面 | 144 | measured，1 米 | measured，separated |
| 98 顶点、192 三角面 | 36864 | unknown，surface_geometry_work_limit | unknown，closed_solid_geometry_work_limit |

第二组总面数只有 384，尚未触及总面数上限；两个路径均在实际几何谓词工作前被乘积门挡住。**这是当前支持范围的明确限制，不是碰撞算错；也不是只有上万顶点才会遇到的问题。** 报告把当前实现描述成面向任意复杂拓扑的通用认证，范围过宽。

初次审计脚本把闭实体的错误原因也预期为 `surface_` 前缀，断言失败；源码实际将其映射为 `closed_solid_`。仅修正审计预期后两组检查通过。初稿、失败输出和最终结果均保留，不改产品或隐藏失败。

这改变了后续优先级：复杂任务可能首先需要解决“可计算却被原始组合数拒绝”的规模问题，而不是将回包再缩小几百字节。若下一固定任务命中此处，算法方向应先利用已有层级包围结构与实际测试计数，减少不必要的候选对，再评估准入。当前闭实体已有 BVH 和工作预算，表面最近距离仍有逐对扫描，不能把“新建 BVH 层”或“直接删除/调高常数”当成已经可行的完整修复。需同时覆盖自相交检查、最近见证与跨物体关系的实际工作，不能只证明两个分离包围盒可以早退。

证据：`verification/fixes/20261112_m4_user_analysis_review/ADMISSION_PROBE.json`、`probe_admission.py`。这是两个离线资格检查，不是新消费者成绩或复杂资产验收。

## 4. 三类具体建议需要改写

### 4.1 减少往返是目标，不是固定收益定额

九格里两调用和三调用的 token 有明显分组，但内容、格式、模型输出、缓存和轮次同时变化。因此不能写“少一轮绝对不会被大回包抵消”，也不能把每轮 8–13 秒、1.1–1.5 万 token 当作已测边际收益。

附件的同轮次 ±0.5% 也不准确：sgc07 相对 N 的两个两调用格为 −0.6406% 和 +0.5242%；另一个 G 两调用格 sgc05 为 +4.4511% 和 +5.6756%。sgc03 与 sgc07 首轮还同时改变了精度和文本结构，不只是 JSON 缩进。

未缓存输入的算术上升成立；追加工具内容以后可以成为历史前缀，不能据其追加位置推断永久无法命中缓存。当前没有逐 provider 请求、图片编码、分段 token 或真实费用。整 turn 的 output_tokens 也不是最终答案文稿 token，不能据此算最终解码耗时。

### 4.2 Reference Bounds 没有补上这次第三调用的信息差

sgc03 首轮已经交付全部 28 个对象的范围与中心，包括 N24/N12/N04/N19。第三调用新增这些参照物的局部顶点和变换矩阵，并重复部分中心与计算距离。因此，新增仅参照范围参数会重复已有内容，不能据此保证三调用降为两调用。

现有 geometry 已是显式选取，`include_triangles` 默认为 false；三格 G 主动选择四对象并请求三角面。没有“默认无条件交付全网格”的现行为可直接删除。现有关系也已经提供最近点/方向，以及相交三角面和局部位置，不能再建一套同义见证接口。

1–2 KB 可以作为某个有限局部定位所需新增数据的目标，但不能保证任意孔道、凹体或整体分离证明都能放进同样大小的 patch。局部点和截面不能独自证明全局最近或全程不穿插。当前驻留资源未保存原始 polygon 分组，仅凭三角面不能唯一恢复；直接读取 raw polygon 也不能替代 evaluated 表面。应先固定问题需要的形态信息，再决定是否新增截面或轮廓，不先改通用几何协议。

静态长文和重复封装可继续审视，但当前投影已经集中部分公共测量合同。对象身份、单位、状态代、结果有效性和测量范围是模型正确使用事实的组成部分。目标应是缩短其表达并减少重复，而不是删除会改变答案含义的字段。详细字段核对见 interface/REPORT.md。

### 4.3 答案后的等待不能直接派给产品 launcher

保存运行器先记录公开答案、再记录 turn.completed，继续读取 stdout/stderr 到 EOF 后等待并记录“观察到 CLI 退出”。显式退出后清理只有约 6.7–9.3 毫秒；主要尾段位于 turn 完成到观察退出之间。其内部原因未细分。

产品 owner 的关闭在 consume 返回之后另行执行，约 0.2–0.3 秒。不能把 G 的 5.9–7.4 秒 final_to_cleanup 全算为产品 owner/launcher 清理，也不能把其余墙钟全算为模型推理。保留分段计量；当前不据此开产品收尾重构。

## 5. 唯一后续方案：一个固定任务的支持范围与最小证据准备

本次修订的是下一批方案，尚未派发。拟定批名 `SPATIAL-TASK-QUALIFICATION-001`；它是任务资格与证据准备，不是另建模块，也不以插件获胜为出口。

1. **先固定用途与一个独立任务。** 优先使用已有可用资产的隔离副本，问题限定为装配中的实体穿插、指定间隙或需要定位的接触关系；写明资产来源、对象/目标歧义、容差和回答应包含的位置。在看 N/P 消费结果前冻结选择。复杂性来自凹形、邻近误导或实际配合关系，不以“原生必须失败”挑题。不自动借角色原资产做修改；如果只有合成资产，则明确标为合成资格案例。保留一个简单控制。
2. **用当前 fac9b437 做一次有界的链路预检。** 复用已通过工程复核的 M2 目录，接当前关系和已有见证，记录每步真实范围、三角面数、乘积门、拓扑支持、精测结果与新增信息。本阶段不启动模型试答，不反复换资产找通过项。已知失败保留。
3. **建立独立答案与最小充分输出合同。** 分开目标选取、关系分类、间隙数值、位置与必要形态。只要求任务需要的证据；先用已有测量/见证，不预装 Reference Bounds、polygon 或 patch 新协议。强原生允许批量读取、逆变换、已有宿主空间 API、解析捷径与合理缓存，并接受同一真值核对。全任务原生不得混用插件求解。
4. **预检只决定一个后续实现接点。** 若命中面数乘积提前拒绝，下一批只解决相应 M3 规模/剪枝问题；若精测够用但发现工具不可调用或缺任务所需证据，则只做 M1/M2 最薄接线或对应的一个信息缺口。只有链路已能完成题目，才准备一次固定消费者对照。Hook、视觉扩展和专家模型继续在这条链之后。

准备完成必须交付一份固定资产/任务/独立真值/原生允许能力/最小证据/成本边界清单，或一个已复现的明确支持域失败，并给出唯一下一改动。没有新缺口则停止立项，不靠换题、增字段或新模块延长循环。

随后实际实现仍遵循：一个候选、至少一次有证据的简化审查、固定验收、独立复核；没有可证实的删工序机会时无需为了“再优化一次”强行改代码。准备和实现成本纳入总账。未来正式消费同时记录回答时间、完整生命周期、实际 token、调用次数和必要补查；原旧门槛与失败保留，未暴露费用不折算。

## 6. 本轮结论与证据索引

当前最值得推进的是让“发现 → 可完成的精测 → 足够解题的短事实”连成一条有效路径。已证的 M2 采集收益应被复用，M3 的实际支持范围需要先弄清楚，M4 的消费效果再用独立任务验证。旧题无法证明普适净收益，也没有证明这条方向无效。
