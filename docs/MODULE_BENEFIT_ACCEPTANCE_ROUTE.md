# 模块收益验收：按实际任务路径组织

本文件落实 MODULE-BENEFIT-ARCHITECTURE-002，对上一版 MODULE-BENEFIT-ACCEPTANCE-001 的划分作勘误。采集、场景暂留、增量、空间处理、任务证据、视觉、交付七项保留为**收益与成本维度**，不当成七个独立串行源码模块。源码文件、可隔离机制和产品价值不是同一层。

004A 仍只准备六题 P/N 组合流程，不启动正式消费者或新增算法。004B 的 P/N 整体比较不能分别给多尺度、注意力、缓存等机制记功。未接线机制按未实现/未测处理，不能因旧文件存在就写成当前能力。

## 四条实际路径

| 路径 | 实际入口和流向 | 必须分开的边界 |
| --- | --- | --- |
| A 默认 Live 场景 | MCP/Hook → 新鲜求值场景 → 概览或对象对事实 → analytical projection 或 native → 交付 | 模型/路由目标绑定、完整读取/验证、分层复用、索引/精确量测、两种视觉、实际接收分别记账 |
| B 注册结构/曲面任务 | observe 早分流 → TaskStore → 原始目标 → 领域算子及 patch/reference 视图 | 不经过普通 scene_delta 链；patch_ref 不等于观察缓存或同响应 JSON 引用 |
| C 固定来源形变 | SmallSkinSourceProcess CLI/SDK → 外部绑定 B2 完整 rows → region/anchor/core/context | V21 QualifiedReader/DeliverySession 是专用库与试验链，不是已接默认 MCP 的公共摘要层 |
| D 有限执行 | 刚体候选/TrustedTaskEntry/OwnedGoalScheduler；另一条 surface_owned 同索引参考恢复 | 两条分别验收，不称通用小脑/角色修复；本规划不授权新写试验 |

每条路径列四栏：代码存在、默认入口可达、实际触发、模型受益。旧文档阶段、注释或演示只能说明历史，不能替代当前运行证据。身份、精度、原预算/期限、取消、事务和计量贯穿各链，不能为省 token 简单关掉。

## 后续可隔离验收单元

| 单元 | 等价对照与主要分账 | 当前结论和注意事项 |
| --- | --- | --- |
| 入口与目标绑定 | 同任务、同意图/对象约束、同拒绝范围，比较有效派发与错误绑定 | 不把已给对象对/core 的题当自主任务理解；未知/歧义不得被替换成猜测 |
| 宿主/来源读取与规范化 | 同新鲜度、完整字段、依赖与精度合同；测读取/验证/哈希/编码独占成本 | 必要基础能力先以正确性及成本上限验收；不能漏字段或减验证换跑分 |
| 分领域事实与纯求解器 | 对同一已绑定完整输入，输出等价；索引筛选对照保留支持性证明和预算 | SpatialSceneIndex 包含支持性/预算，不能只取剪枝快段；alignment_evidence=false 仅无图，不能作视觉单变量 |
| 分层观察复用 | 历史 scene_cache、支持性 memo、pair memo、router 整份 observation 分开，固定分支与生命周期 | scene_cache 不等于持久逐对量测；整份命中绕过索引/量测/分析渲染，native 图在 router 后重新读取，不能叠加节省百分比 |
| 任务证据选择与关联 | 完整来源绑定 rows 是几何→任务投影隔离点；覆盖、关联和纯编码分账 | V21 同面跨帧预连接少补查只记一次；C 路成绩不能套到 A 默认缓存 |
| 各视觉实现 | projection/native 是替代实现；结构非平面 patch/曲面 reference 各有专项路径 | native 增量含额外捕获、恢复和独立验证；关 attention 的基线仍补齐 Q4、共享准备和被否决候选 |
| 具体交付协议 | 完整重建要求相同的 full sync 与 scene_delta；具体引用协议分别验 | scene_delta 是依赖历史的显式附加对象级协议、updated 发整对象；不能与普通简报当等价输出 |
| 有限执行反馈闭环 | 固定具体写域/权限、回读、未知、取消与原账本，分别验证各有限路径 | 缓存可淘汰，原预算、未决动作、物理 setter 账本不可当缓存丢弃；不因本规划启动写域 |

复核交接指出的**待测现状**：普通 observe 仍全量 capture/validate；scene_transport 是显式附加而非端到端增量；路由历史约束为 2 MiB/16 帧。后续登记应重新核对适用配置，不能把这些描述当已获得净收益。TaskStore patch_ref、同响应 JSON 引用及 V21 落盘 artifact 引用不是一种统一缓存。

## 每次冻结的验收合同

1. 固定候选、任务/输入、实际入口、依赖、状态生命周期和预算。先声明主要收益指标、该具体域的最小有用改善与允许退化范围，冻结后再测；不设一个盲目的全局百分比。
2. 单机制贡献采用同链路、仍能完成同任务的契约等价替代，只改变一个机制。产品价值才比较合理原生完整流程，允许其本地脚本、状态和缓存。无法隔离的现有实现标不可归因，不为消融先开发新系统。
3. 分账采集、验证/哈希、缓存、几何、渲染、输出、模型消费，保留独占成本与完整任务成本；公共启动单列，inclusive spans 不相加，模块百分比不相加。estimated_saved_ms 只是旧 compute 估计，不是扣除新哈希/编码/落盘后的净收益。
4. 适用时覆盖冷/暖、静态/局部变化/持续变化、删除、撤销、重连、场景切换、失效重建、失败、回退、尾部延迟和内存。未知、超时、不支持和遗漏保留在分母，不刷样本到优化赢。
5. 内部等价输出先做确定性验收；影响模型消费/行为时再安排真实消费者，避免每个模块重复大套模型试验。Pro 未公开指标记未测，不能用字节/像素推 token 或美元。
6. 正确性按通过/失败/未运行，收益按成立/证据不足/负收益分栏，声明适用域。必要能力按正确性和成本上限验收；可选优化无收益保留显式可选，负收益提出回退/合并建议，不能自动删必要检查。

## 本视觉批次后的顺序

004A 完成后先交回复核，004B 按已授权的相同六题范围运行；本文件不扩大当前批。视觉批次收口后，优先选**一条明确的普通 Live 连续任务链**，固定宿主、查询和接收端，分清场景暂留与交付的连续多轮成本，再从分账结果选一个机制。每次由复核聊天派一个清晰模块，不把默认 Live 缓存成绩套给 V21 双源链，也不为了架构整齐先重构全项目。
