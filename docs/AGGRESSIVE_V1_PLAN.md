# Human Eye 激进架构与算法版本：方案与双线推进

日期：2026-11-05。实验分支：`codex/aggressive-v1`。共同历史基线：`284699285c349bd4124bf8c863c4546df1c6d033`（`2846992`）。

后续整体架构以用户最新规格融合形成的 [三大引擎、共享接口与推进批次](RADICAL_V1_INTEGRATION_PLAN.md) 为准：E1 主动视觉、E2 记忆先验、E3 几何与动作执行。原 F0–F7 仅为内部职责；本文件保留已有第一版技术选择与历史双线方向，不再单独决定排期。

## 任务决定

用户最新要求是第一版本阶段进行最激进的架构与算法优化，去掉防御性策略，另分支交付方案与第一版，供两端分头推进和比较。此指示取代旧路线对本实验分支的等待、阶段准入和只允许单个小改动等限制。

本版采用可信本地调用者、单一会话拥有者、稳定拓扑与调用者声明变更的模型。直接重写数据流和数值内核；不通过把旧验证器配置为关闭来继续运行整套旧平台。新运行包为 `human_eye_fast`，导入和运行均不加载 `human_eye_plugin`。历史实现留在同一 checkout 作为比较对象。

本分支新的使用入口是 `human-eye-fast` / `python -m human_eye_fast`。已有 `human-eye-live`、MCP、Hook 命令仍指向历史版本；性能比较必须记录实际使用的入口。

## 架构决定

新链路：

```text
调用者给定 reference + triangle topology
    → 一次参考基与顶点-面邻接构建
    → 常驻连续数组保存多帧
    → 全帧批量计算 / 脏顶点关联面的局部计算
    → 向量化区域选择与完整核心归约
    → 同面跨帧见证
    → 仅在出口生成紧凑 JSON
```

| 历史路径的工作 | 本版决定 |
| --- | --- |
| 来源、运行源码、依赖、catalog/profile 哈希及加载见证 | 从新路径全部移除；输入标签和索引直接使用 |
| LBS/FK 独立重放与完整来源准入 | 输入直接采用已经求值的顶点数组 |
| 逐层 JSON schema、类型、规模和支持域拒绝 | 不设这些运行时门；按数组接口执行 |
| 原期限、子期限、读取配额、一次性发布和审批回调 | 新计算会话没有这些状态或守卫 |
| 每次发布的账本、审计、fsync、四文件回读、重复摘要 | 新查询不写盘；输出文件仅在 CLI 显式指定时写一次 |
| 每来源启动、反复 inspect、跨进程协议嵌套 | Python/Blender 内常驻会话；JSONL CLI 保持同一进程 |
| 全量事实转 dict、编码、解码、复制、再验证 | 内部使用 NumPy 列数组，按需要在出口构造少量对象 |
| 静态数据每次重复计算；哈希检测是否改变 | 调用者提供 changed_vertices，邻接索引定位受影响面 |
| binary32 误差包络与保守 unknown、Fraction 精确谓词 | 普通 float64 计算，直接给出数值；数学未定义用 NaN/null |
| 超时/失败自动回退、重试和恢复平台 | 原生异常直接返回调用端；没有隐藏重试 |

数组首次进入会话时建立自有副本，保证随后局部更新具有明确所有权。之后查询复用内部数组；这不是零拷贝跨进程承诺。Blender 临时 mesh 的释放是资源生命周期，不是恢复到旧防御性平台。

## 算法重写

1. **表面形变**：缓存参考三角的局部正交基和逆尺度；所有面以数组批量构造 3×2 形变梯度。用 2×2 对称矩阵解析谱求最大主伸长，叉积模与最大值之比恢复最小值，避免逐面 Python 调用及大规模 SVD。面积比由两主伸长乘积计算，测试 oracle 另用三角面积比核对。先算一次、查询复用。
2. **空间区域**：三角 AABB 向量化粗筛，余下使用三角法线与边×盒轴的 SAT；与盒坐标轴共 13 轴。以闭集相交为语义，接受点/边接触。取消逐面有理数多边形裁剪。
3. **更新粒度**：顶点到面 CSR 邻接索引一次构建；修改顶点只更新受影响面的指标和包围盒。没有变更就直接查询已存事实。新帧仍需完整计算。局部复杂度要求输入已是 float64 ndarray；从 Python 列表或其他 dtype 转换仍会遍历输入。区域查询本版扫描全部缓存 AABB，尚未实现 BVH。
4. **任务输出**：完整选区归约得到计数、三态、极值及面索引；先选各正例核心的同面双阈值见证，再填充未定义和极值，跨所有标签直接索引同一面。显式 details 保留；输出条数是用户选择偏好，不是权限配额。
5. **数值行为**：取消旧坐标精度和误差上限拒绝后，旧版 unknown 可能变成本版数值；近边界舍入、病态三角、上下溢也可能不同。一般非退化域用独立 QR/SVD 对比；所有域的完全等价并非本版本的定义。

从防御检查中节省的时间、NumPy 批处理节省的时间和减少无用序列化节省的时间分开披露。用独立批量 QR/SVD 作为第三基线，避免只和昂贵旧 Python 路径比出大倍数。

## 第一版交付边界

本次交付完整的“已给定参考拓扑与求值帧 → 区域 → 同面任务见证”快速纵向链，包含批量内核、常驻会话、稀疏更新、NPZ 输入、JSONL 服务、Blender 进程内采集适配器、公开测试与可重跑基准。

本版没有实现新的通用刚体碰撞内核、执行控制器、渲染器或自动任务语义。它也没有删除历史包中的每个防御函数。防御性策略的移除适用于实际新路径；旧路径仅用于比较。对整个项目的进一步替换按以下双线推进。

## 两端分工与后续模块

以本次第一版提交为共同起点，后续分别使用 `codex/aggressive-architecture-v2` 和 `codex/aggressive-algorithms-v2`。本轮只创建并提交 `codex/aggressive-v1`；两个 v2 分支在实际分工启动时创建。

| 方向 | 架构端 A | 算法端 B |
| --- | --- | --- |
| 首要交付 | 默认 Live/Blender 常驻数据链与最短模型接口 | 向量化几何的进一步加速和更强空间查询 |
| 数据 | 长期保留 topology、reference、frame；直接绑定宿主求值数组；显式 dirty 更新 | 沿共享数组接口，研究 CSR/紧凑邻接、BVH/refit、SoA 布局 |
| 采集与传输 | 去掉重复捕获、验证、编码与文件交付；必要时共享内存传数组 | 内核完全消费已有数组，避免隐式重采集或复制 |
| 形变 | 把目录选择和帧生命周期接入直接会话 | 批量 LBS、参考基复用、SIMD/JIT/编译内核、多帧批处理 |
| 普通空间任务 | 同一场景句柄上的对象/区域/近邻接口 | BVH 距离、三角最近点、批量碰撞与增量 refit |
| 图像 | 同宿主直接提供实际原生图；统一文字和图像输出 | 任务区域选视向、屏幕空间细节估计、向量化遮挡采样 |
| 动作 | 直接宿主 setter 和同会话回读；去掉旧授权/账本层的新执行入口另实现 | 直接求解有限位姿/表面修正，复用几何数据，减少重复模型规划 |
| 优化选择 | 输入到实际交付的墙钟、调用数和序列化量 | 同输入的数值误差、查询时间、更新时间与内存 |

两个端可以各自大改内部实现，提交时附带可运行入口和公共基准结果。两端的首批比较分别固定另一部分，以辨认架构和算法贡献；最终再合并最有效组合。GPU/编译内核可直接做候选，但计入编译、上传、下载、同步、首次调用和小规模成本。

模型入口也走最短路径：明确操作名、数组/帧句柄、区域和必要参数；工具结果提供足够完成任务的数值与图片。不会先重建新的认证、审计或通用消息平台。

## 比较方式

- 历史参照固定 `2846992`；保留源码 SHA 仅用于离线实验记录，不回到运行热路径。
- 本轮公共合成夹具覆盖规则/倾斜三角、缩放、剪切、刚体、塌缩、区域接触和局部修改。规模记录实际面数，所有方法吃同一输入。
- 同时报冷准备加计算、参考已准备的热计算、空间选择、全更新、稀疏更新、任务视图和 JSON 字节。完整冷启动的模型/Blender 任务另测，不能由局部项目相加冒充。
- 增加常驻形变/空间任务的 128、2048、20000 面测量；后续两端扩到百万面、长期帧更新和真实用户任务，不在 hot path 设置这些规模为上限。
- 同域数值正确性用独立 oracle；旧版拒绝而新版本接受的数值独立列出。剥掉原安全/精度合同属于设计变化，不能只用速度比隐藏。
- 模型比较保留同问题、同输入和真实完成质量，记录图像、token、墙钟；缺失指标直接标明。无需为每次局部内核修改重复模型试验。

## 运行

```powershell
python -B -m human_eye_fast demo
python -B -m human_eye_fast demo --write-input sample.npz
python -B -m human_eye_fast analyze sample.npz --bounds -1 -1 -1 2 2 2
python -B -m human_eye_fast serve
```

NPZ 只需 `reference` (V×3)、`triangles` (F×3)、`frame_<label>` (V×3)。各帧沿用同一顶点及面索引、同一度量坐标系。模型输出中的面索引直接对应输入，标签由调用者赋值。

JSONL 会话示例（每行一个请求/响应）：

```json
{"op":"load","path":"sample.npz"}
{"op":"query","labels":["rest","deformed"],"threshold_high":1.1,"threshold_low":0.9}
{"op":"update","label":"deformed","vertices_file":"next.npy","changed_vertices":[4,7,9]}
{"op":"rows","label":"deformed","indices":[0,1]}
{"op":"close"}
```

`changed_vertices` 指本次相对该标签已存状态的全部变化索引；漏报不会触发扫描或自动纠正。调用者改变拓扑时重新创建会话。物理采集失败、错误索引或不符合接口的数组会直接抛异常。

在 Blender 的 Python 环境中，把 checkout 放在 `sys.path` 后：

```python
import bpy
from human_eye_fast.blender import BlenderSession
s = BlenderSession("Mesh")
bpy.context.scene.frame_set(1)
s.read_frame("a")
bpy.context.scene.frame_set(10)
s.read_frame("b")
answer = s.query(["a", "b"], bounds=[[-.5,-.5,-.5],[.5,.5,.5]])
```

此适配器使用 mesh-local 米坐标；原始网格为参考，当前 evaluated mesh 为帧，调用者负责对应索引。原生采集目前仍 foreach_get 全量顶点；稀疏收益首先发生在数值处理，尚未实现宿主端局部读取。保持拓扑的骨骼/形变修改器可直接进入，改变拓扑需调用者重建参考。真实 Blender 接入验证状态另见结果文档。
