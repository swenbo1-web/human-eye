## 2. 当前真正需要解决的效率问题

九格实测来自同一 28 网格场景，每路线三次；P0 是本次修改前候选，不是 11 月 3 日的历史主干。

| 路线 | 完整正确 | 完整任务中位数 | 三次实际 input+output token | 工具调用合计 |
|---|---:|---:|---:|---:|
| 原生 N | 3/3 | 48.303 秒 | 143,762 | 7 |
| 修改前 P0 | 3/3 | 48.958 秒 | 172,454 | 9 |
| 当前 P1 | 3/3 | 47.416 秒 | 172,370 | 9 |

P1 对 P0 时间下降 3.15%，token 仅少 84，属于旧门槛下的边际通过；对原生时间下降 1.84%，token 增加 19.90%，尚未证明完整任务净收益。三次重复不能支撑稳定性能承诺。

六条插件路线仍全部经历“原生全场目录 → 插件关系 → 原生局部形状”。新增交叉位置证据被正确采用，但没有覆盖开孔、材料区间及其他参照形状，所以没省下最后一轮。没有证据表明模型因为不信任插件而完整重算所有几何关系。

P1 的 owner 工具时间合计 0.7694163 秒，完整任务合计 139.6149947 秒；占比 **0.5511%**。在其他部分保持不变的前提下，这块计算即使全部归零，整批时间最多下降约 0.55%。减少模型往返、避免不必要的回退、扩大有用观察覆盖不受这个局部上限限制。不能把模型服务和生成等未细分时间都称作“推理”。

九格实际参数均关闭 Hook，并忽略用户配置/规则。因此 Hook 冷启动不能解释这批约 50 秒耗时。Hook 可能有独立收益，需要单独证明，不能先把预计节省的 20 秒计入当前候选。

## 3. 对两份报告的取舍

### 3.1 采纳的主方向

1. 无目标问题先取轻量空间目录，避免先展开全场网格再只交付包围范围。
2. 选中对象以后，一次组织任务需要的局部形状与已有关系，减少跨工具补查。
3. 复用当前宿主驻留、选择性采集和 `ReadContext`；不再造第二份场景缓存。
4. 精确内核用剪枝、整数算术展开、准备数据复用提速；采集用批量读取；删除确实重复的 RPC、计算与序列化。
5. Hook 复用上述读取结果，承担提前交付，不单独解释几何或维护邻接缓存。

### 3.2 必须修正的具体论断

| 报告论断 | 本次复核结论 |
|---|---|
| 五个 Hook 堵点串联造成当前慢 | 漏判后直接跳过，未必进入后续重采集；九格关闭 Hook，不能作该批归因。 |
| 变换八个 `bound_box` 角点得到精确世界网格 AABB | 可得到外包范围；旋转的非盒几何通常不是紧致世界网格 AABB，其中心不能替代真实网格范围中心。原对象 bounds 与 evaluated 变换混用还需处理修改器/实例语义。 |
| AABB 最近 Top-K 可以当完整候选目录 | 下界排序不等于表面距离排序。确认最近需要真实已测上界及未测候选下界；全场碰撞检查不能只保留 Top-K。稠密场景候选数本身可能是平方级。 |
| 示例 frame/rod 的 AABB 下界为 0.023 米 | 对相交的外包盒下界为零；不能把实际表面间隙填到包围盒下界字段。 |
| Hook 示例参数可直接复制 | `requested_facts` 的三个名称在旧双对象接口合法；错误在把 `N16` 名称当作实际 `id`。真实 ID 是 `blender:...`；该示例也没有表达当前批量关系路径。`--mode fast_scout` 当前 CLI 尚不存在。 |
| PreToolUse deny 加修正模板可以消除重试轮 | deny 后仍需模型重发。优先修精简工具的 schema、默认值和入口归一化，不新增读工具拒单链。 |
| 只加状态词就补齐意图识别 | 有的例子已有操作词，漏判发生在另一条件；需覆盖整个判断式及否定/引用/代码讨论，不能照抄局部补丁。 |
| 删除 observe PostToolUse 立即节省开销 | 当前本地配置已经仅匹配两个写工具，没有该项可再删。 |
| mtime/size/expected hash 缓存证明源未变 | 仅命中 stat 不能证明磁盘字节未变。当前 137 源已区分核验后加载代与磁盘状态，并冻结/驻留宿主源码，不应重建旧方案。 |
| `1e-14` 放宽 AABB 剪枝即保证 0 ULP | 固定相对余量不是普适数值证明；候选遍历顺序还影响等距 witness。须按几何真值、下界可靠性及明确的输出契约验证。 |
| `foreach_get` 后换运算顺序或删除齐次列完全等价 | 批量获取原值、把原来已有的 `projection @ view` 外提都可独立优化；改变浮点归约、Python `sum` 版本及负零处理可能改变坐标/摘要，不能捆绑声称逐字节不变。 |
| 18–28 秒、token -30%、数十倍内核提速可直接验收 | Hook 数字是预测；未定位到 PERF 新微基准的完整脚本/输入/raw，暂为报告作者主张。实际入口及完整任务还未测。 |

本次离线反例只检验“普适等价”论证，没有运行产品，也不声称极端示例可通过产品准入。优化的目标是正确几何与约定输出，不是保留旧浮点算法的错误值。详见独立算法报告与 `numerical_claim_checks.py`。

## 4. 收敛后的运行架构

```text
Blender 同代场景
    ↓
现有宿主驻留：对象目录 / 失效标记 / 选定几何
    ↓
同一观察服务：发现候选 → 按需精测 → 局部形状与关系一起交付
    ↓                               ↓
MCP 直接调用                    Hook 提前交付同一结果
    └────────── 模型完成任务 ─────────┘
```

这是现有 Live 读取路径的收敛，不把七个收益维度变成七层串行服务。注册诊断、形变专家、有限执行仍按各自任务使用，不强迫一次观察走齐所有路径。

- **目录**：稳定对象 ID/名称、单位、版本、范围类型及有用空间筛选；轻量外包范围明确标识。凡是目标判定依赖紧致中心或真实尺寸的，按候选需要细化，不能用宽松范围悄悄改变目标答案。
- **选定观察**：显式选择对象、所需形状字段和关系对；尽量一次采集、一次求解、一次返回。几何证据来自场景，不能从标准答案拼成产品输出。
- **空间算法**：优先利用现有粗筛/索引及准备数据。nearest 用有效上下界逐步收缩；全场检查用覆盖完整的 broad phase。Top-K 只作排序或分页，不作完整性证明。
- **缓存/暂留**：继续使用现有场景代、dirty 信息和 `ReadContext`。目录与详情共享快照；发生编辑、撤销、删除、重连或场景切换时按当前失效机制更新。避免新建第三份状态系统。
- **交付**：结果先给对象、关系、单位、必要坐标和短的范围说明；细节按需查询。几何精度状态用结构化字段，不在每次回复塞入长篇说明。模型不必先读使用手册再生成调用代码。
- **视觉**：数值事实不够表达形状时才增加有目标的局部视图；模糊、多尺度和扫视属于后续可单独验收的感知能力。目录预载不能称作已经实现人眼感知。

## 5. 唯一推进顺序

### 第一步：完成已在做的离线观察覆盖

继续 `M4-BATCH-OBSERVATION-COVERAGE-001`。按六次真实补查建立必需/可推导/可省略/缺失信息表，交一个目录加选定观察原型，再做一次针对性简化。比较同信息、同精度的合理原生批量读取，包含重命名、刚体变换和同形干扰物。

出口是：确实覆盖任务需要的信息且没有隐含第三轮，实际字节/内存/采集计划有结构机会。若只是同等原生脚本外包一层，记录收益不足，结束该设计；不再堆字段或换简单题刷过。

### 第二步：接入同一实际读取入口，测清冷、热与变更

覆盖通过后，在固定 137 源候选的实施分支接入最薄观察组合。复用已有驻留与 exact 关系内核，明确哪些目录字段无需网格、哪些候选必须细化；实际记录 RPC、`to_mesh`、三角化、对象/面数、内部占用、输出字节和缓存命中。不能用离线逻辑响应数冒充宿主调用次数。

仅优化这条链实测最大的一个剩余瓶颈：若重复采集/RPC，就合并；若密集 exact 求解占主导，就复用准备数据/剪枝；若是当前路径误拒，修该路径准入。报告中的旧 SAT/浮点 Morton 或注册曲面方案不自动升级为前置条件。一个候选加一次简化后冻结，停止零碎微调。

源码级质量覆盖当前原始案例，以及旋转非盒对象、凹洞/套合、下界排序与真实最近不一致、等距见证、外部编辑/撤销/删除/重连/场景切换。只有宣称支持的求值范围才计入成功分母；未完成测量不能算作“没有问题”。这里使用定向离线与宿主验证，不为每个工程边界启动模型试答。

### 第三步：一次受控完整任务验收

固定原生 N、当前 137 源 P1、新观察候选三路。首先所有路线关闭 Hook，隔离观察能力收益；原生允许合理批量读取、解析捷径和同等缓存。固定任务、源、初图、模型/effort 请求设置及期限，使用平衡顺序并预登记重复数。

任务族至少覆盖：明确对象的简单控制；当前开放发现+局部形状任务；真实最近/邻接排序容易被外包范围误导的任务；稠密、凹形、遮挡混杂的未知目标任务。提高复杂度应增加几何歧义和证据要求，不只是复制大量容易剔除的方盒。每族保留未用于调参的变体，独立答案从原始几何/独立方法得到，不由候选给自己出答案。

质量先匿名封存，再看成本：完整回答、目标遗漏、错误关系、错误最近、unknown 的正确解释、证据是否被使用。随后统计真实模型轮次和工具调用、Hook/目录/安装等分段成本、完整墙钟、真实 input/output/cached token、数据量及可得费用。缓存 token 不能与 input 重复相加，未知费用留空。

产品目标仍是简单任务不拖后腿、复杂任务净收益明显。发布净收益要求质量不降，时间与 token 均不变差，且至少一项超过预登记的有用改善幅度。具体性能余量在正式试答前由固定基线波动和成本需求写定；不能沿用“少 84 token、快一点就算过”的宽松规则，也不能把有噪声的 p95 严格零差当数学恒等。样本不足则报告未证明，不用不断追加试验改结论。只有时间更快但 token 更高的结果，明确列作取舍。

### 第四步：Hook 只做同一观察结果的提前交付

在读取本身通过以后，单独验证 Hook 是否进一步减少首轮发现。优先探测本机能否使用官方 `mcp_tool` Hook，复用已有 MCP 连接及同一服务；不先新增 Named-Pipe daemon。若本机不支持，再评估薄标准库转发或直接 Python 命令，只有真实测量才决定去掉 PowerShell 的收益。桌面宿主与 CLI 分别验证，不从 CLI 版本号推断桌面兼容。

官方当前协议支持 MCP tool Hook 调用已连接服务；它不会自行启动/重连服务。还支持 `PreToolUse allow + updatedInput`，但这不构成必须新增参数改写层的理由。详情见 [Codex Hooks 官方文档](https://learn.chatgpt.com/docs/hooks)。本机已读到 CLI `0.152.1`，上述能力尚未实证。

不靠 deny 反复纠参，不用正则拦截原生算法迫使模型选插件，不自动注入全场平方级邻接表。Hook 与手动观察有相同的源范围与输出语义；无几何需求时轻量退出。不能把截断目录标成完整，也不能把预载和 AGENTS 文本当零 token。

先做同一候选 Hook 开/关单变量比较；再对原生提供同等可用的预取/缓存机会，区分“提前给了上下文”与插件空间处理本身的收益。计时从用户提交前后约定的统一边界开始，必须含 Hook 和底层读取，不从预载结束以后起表。完成本批后关闭无收益的自动预载，不再反复调文案。

## 6. 退出规则与后续能力

每批遵循：固定缺口和基线 → 一个候选 → 至少一次有证据的简化 → 固定验收 → 独立深审 → 关闭该批。复审重点是数据是否取对、是否减少一次真实工作、是否只把成本移到隐藏阶段、是否仍有可删除的层。质量达标不代表净收益达标；收益未达不自动开新模块续命。
