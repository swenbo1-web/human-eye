## 公平的三轮 episode

每个 episode 只在第一轮新建 owned Blender、模型上下文和必要产品进程。三轮间维持同一 backend、模型线程、工作目录、本格原生脚本/几何缓存；C 另维持同一产品 runtime 和 session。第三轮的姿态修改由外层在上一轮完成后、下一轮题面前实施，两组条件相同。结束 episode 才统一关闭。

1. BASE：第一次完整全场查询。
2. REPEAT：场景未变，重新查询当前状态。
3. EDIT：实施登记姿态后，再查询当前状态。

未来模型 T1 使用原逐字题面 `6a78e38a474647c0c0c49558be215864cb672932273b3e15ca6ba7f9fa02b4fc`。T2/T3 使用同一共同文本：原题面前仅加“请重新检查当前场景。”。不透露是否真的改变、改变对象、答案数量或旧答案；模型可自由选择查证方式。缓存可保留，但在 EDIT 用旧 71 对回答“完整”会判错。不得清除 N 的缓存或给 C 注入已算答案。
