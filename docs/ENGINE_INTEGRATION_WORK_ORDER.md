## 需要冻结的生产结构

建议一个 `BlenderRadicalSession` 持有调用者明确指定的 scene、对象 ID 映射和目标 pair、一套 RB 数组/BC 索引、VG 资源、TD 参考/原始指标，以及该会话自己的 CF 模型和两头库。按职责拆文件，不创建多进程、事件总线或通用框架。生产模块不得 import `verification`、夹具、评估记录或训练结果目录。

- **共享捕获状态**：现有 `BlenderControl` 自有 bridge/index，不能再由观察器复制第二套。说明是复用其持有状态，还是提取最小 capture/readback 接口；若需更改已验收组件，先提交精确 seam/补丁及兼容回归范围，不重写内核。一次真实观察中每个所需对象只捕获一次，共用同一 depsgraph、单位和求值结果。动作后必须刷新受影响对象，再重算真实事实；复用不能变成读取旧帧。
- **参考与坐标**：验证 fixture 的 `rest` 恰在世界系、对象矩阵恰为恒等，这不是生产前提。明确参考顶点所属局部/世界米制坐标、参考时刻变换、样本帧和位置帧。非单位 `scale_length`、父级、非均匀尺度、旋转和平移只能换算一次；区分固定世界参考下的真实运动与同时变换参考/当前的坐标重表达。原始 loop-triangle 行、polygon 映射及拓扑代不能混用。
- **动作定义**：只承接当前已经实现的世界米制 `Translate` 和相对线性 `SetShapeKey`。已知静态 relative basis 必须来自真实 RNA 并正确转换为世界米，实际当前 q 和执行后的 q 必须回读。明确预测适用域与真实宿主执行域；父变换等若影响模型的有限动作定义，需解析证据，不能假定恒等 fixture 的预测可泛化。不给见证向量自动冠以求解动作，不新增通用规划/求解器。
- **部署模型**：显式数组/参数对象或明确的部署 NPZ 契约，只含部署需要的权重、训练统计和库数据，不依赖 `FrozenModels` 验证类。调用者选择实例；没有固定磁盘路径、全局单例或按新评估成绩换 seed 的模型。可离线从已有封存快照导出，记录字节/数值等价。无模型时如需支持 F，必须由请求明确选择确定性路径，不能 L 失败后隐式退回 F/R。
- **结果与所有权**：生产输出包含可直接消费的 AO 字节及实际 PNG 字节/明确内存附件。不得只有虚构路径、配置或依赖私有评分器才能解释的结果。明确借用数组的有效期，动作前观察和待反馈特征需要保留的部分显式拥有；禁止动作后原位更新改写已经交付的 before。关闭释放 bridge、索引、GPU 和模型库，两会话互不串写。

接口草案至少覆盖 `observe(request)`、明确命令预测及 `execute(action)`、真实 `view_feedback(...)`/动作 Outcome 更新、`close()`；具体拆分由实际共享数据流决定。首版目标是一个调用者可直接持有的生产 Python 对象和独立后台 Blender 的公开示例入口，不在这一阶段重建旧 MCP/Hook 平台。公开包的普通 NumPy 导入路径不得无条件导入 bpy。若需要新传输适配，另列边界，不能靠测试私有对象冒充入口。

视角反馈只能来自真实消费者已评分的实际呈现方向，未知方向保持未知；不能生产内调用独立 oracle 自贴标签。预测 → 原生呈现/执行 → 实际反馈 → 一次更新 → 下一次查询，绑定观察 ID、方向/命令与实际结果。绑定属于操作语义，不新增来源哈希、权限/配额、TTL、账本、隐式重试、兼容 fallback 或双算法保险。保留现有完整 TD 数值及精确 Top-K，按需增加的单项选择须明确任务和预算，不能乘 S 权重改写原事实。

## 基线、质量与完整成本

草案必须给出具体场景/操作清单、源码身份、基线代码、计时边界、失败与补测规则，主干审定后冻结。以下是本阶段的设计约束，不是已经取得的成绩：

1. **薄编排基线 B**：用同一批已验收生产函数、相同冻结模型/初始库和同一真实任务做直接手工编排。不能故意重复 capture/encode、弱化图像或删掉反馈来制造差异。生产会话 I 和 B 具有相同当前输入、变更声明、参考、动作、图像、事实/附件与学习责任。基线必须先通过独立质量检查。
2. **真实同场景闭环**：预定同一对象对的观察→明确命令→真实回读→后观察→消费者反馈→下一次查询。覆盖两种动作、自然/剖切、零距/空面/已达目标、同帧不同观察 ID、上下文随动作变化、参考与拓扑换代、会话隔离和释放。精确列出支持域；不靠克隆两条独立 fixture 拼成同场景闭环。
3. **依赖质量不变**：I 对 B 的公开事实、原面 ID/见证、TD/Top-K、图像及方向/射线、前后 Outcome、预测/经验与权重更新必须逐例等价，既有数值预算照用。相同 GPU 算术时优先 PNG 字节一致；如仅编码或资源名字不同，先固定允许变化的字段并独立检验 RGBA/公开语义，不临时豁免差异。完整主链须由公开消费者只读返回包及附件完成任务。
4. **既有 CF 回归**：用已封存的三个模型和原清单核对生产接线。明确这属于既有评估重放，不声称新未见数据或再次学习收益。V/A 原质量/收益与分段时间门继续成立；不重新拟合或改选超参。已验收 RB/BC/TD/VG/AO 的必要接口回归按真实修改范围执行，不机械重跑整套优化。
5. **接线成本门**：建议 I/B 的完整公开调用 p95、观察子段、动作及反馈子段 p95 每进程均≤1.05，且原 CF 的≤1.10门保持。基线同样允许复用同一已持有当前观察。观察输出和动作执行边界分别说明，不能拿两场景 CF 的58ms与单场景新链直接算提速。三串行进程、固定线程/设备、预定场景及至少31次配对交替顺序；计时含采集、全事实、CF、真实 GPU 同步读回/PNG、AO、动作回读、应执行的写库/更新及对外必需拷贝。消费者等待单列并另做真实闭环，不只测内部 infer。
6. **生命周期/成本披露**：冷启动、部署加载、参考建立、热态、完整消费者成本、NumPy常驻及峰值/RSS/GPU分别报告。新增状态不得隐藏第二份 bridge/index、完整重复历史或全局会话残留；初始化分配与借用/持有快照的合理成本据实际契约冻结，不用“零拷贝”掩盖RNA传输。两会话和关闭后重开要实测。
