# VG 主动视觉：事前冻结协议

2026-11-05。继承[六模块工作流](RADICAL_V1_COMPETITION_WORKFLOW.md)的24例、质量增加至少20个百分点、基线已见不丢失及热态p95≤1.20倍门。本文件先行冻结设计；实施必须等BC主验收通过。历史教训落实为真实底图、相机RNA、原生射线及公开消费者字段联合核验。

## 实际产物和接口边界

VG接收RB捕获的世界米制网格、实际基色、对象/帧标识及BC真实面ID/见证。输出实际1024×512双联HUD：左512×512完整原始场景，右512×512见证局部图。图上标识目标、全局与局部的关系、未取整距离和NATURAL/SECTION语义；可叠加见证标记，但验收可见性只用叠加前底图。底图另存审计，不当作额外的公开观察能力。

实际图片、公开相机/视口/单位/对象/帧关联和剖切声明共同组成观察结果。只给相机计划、射线布尔值、GPU提交句柄或纯色PNG均不构成交付。GPU完成、读回、HUD及PNG编码全部计入观察时间，不能称显存提交为最终图像。

采用可信输入和显式更新；没有来源守卫、期限、配额、哈希校验、隐式重试或保守备用流水线。浮点几何、方向归一化、深度裁剪、资源释放与明确的无间隙取景语义是算法本身。接触/相交单独检查，不将零间隙画成正间隙。

## 固定24例

令s=0.01m。目标A是闭合四面体，四点为(0,0,0)、(-4s,-2s,-2s)、(-4s,2s,-2s)、(-2s,0,-4s)。目标B由A以x→g−x镜像。两者唯一最近点为(0,0,0)和(g,0,0)，真距离g；实际查询必须经过RB→BC，不能将解析点直接代入VG。所有面外向，源三角ID保持。A/B用不同的固定基色，障碍物用第三种基色；两方法完全相同。

每类四个变体固定为(绕Z转角°,g)：(0,0.000025m)、(45,0.0001m)、(90,0.0004m)、(135,0.004m)。目标与障碍物共同旋转。以下障碍坐标以见证中点q=(g/2,0,0)为原点、旋转前定义，均为真实不透明闭合网格：

| --- | --- | --- |
| F1 无遮挡 | 无 | NATURAL |
| F2 单挡板 | x=[9.5s,10.5s]，y=[−12s,12s]，z=[−10s,16s]的盒 | NATURAL |
| F3 顶板与错位立柱 | 顶板中心(0,0,8s)、尺寸(18s,18s,s)；两柱中心(10s,−6s,2s)、(−6s,−10s,2s)，尺寸(2s,2s,12s) | NATURAL |

## 对照方法和剖切

基线局部视向固定为世界空间normalize(1,−1,1)，双方全局图也固定该方向。候选局部视向由几何与实际可见性决定，可使用正交于间隙的候选方向和原生ray_cast；公开候选方向、射线数和选择结果。不允许硬编码本表的场景ID/最佳方向。双方均拿到同一公开BC见证和对象ID，局部中心q、正交宽度W=32g，不能让基线只拍无放大的远景。

双方相同的实际基色、统一光照/着色、深度测试、分辨率、颜色与PNG编码策略。允许以RB基色做科学几何可视化；两边用同一GPU绘制实现，差别只在主动视向及其计算。第一轮之前在实施说明冻结具体着色配置。禁止一方透明、透视轮廓或额外图片优势。全局视野必须包含完整原始场景，局部虽可裁掉目标大部分身体，必须有全局关联。

方向d定义为中心指向相机，C=q+D*d，相机前向为−d。相机位于所有几何的外部，near/far覆盖全场景深度，natural不能用近裁剪偷穿障碍。PNG坐标原点为左上，射线通过像素中心，GPU读回恰好翻转一次。两个面板各使用512×512的投影参数；局部图输出横坐标加512，不用1024×512宽高比作为单面板宽高比。保存并独立读回实际Blender相机RNA及GPU实际使用的view/projection矩阵，米制换算后核对一致；只记录计划字典不足。

F6双方均获相同剖切能力：n=(pB−pA)/g，t=normalize(d−(d·n)n)，平面通过q，保留t·(x−q)≤0。对全部网格应用同一半空间，不能只移除遮挡物；两见证位于平面上且保持。局部显式标注SECTION、平面/保留侧；全局保持未剖切源几何。允许临时GPU裁剪或裁剪副本，源几何事实不改变。剖切成功不能冒称自然可见。

## 实际可辨评分

每例成功须同时满足以下条件，独立验收器不能直接相信候选的visible字段：

1. 读取实际相机RNA/矩阵，把真实BC见证投影到局部底图，二者在视口内且欧氏间距≥4像素。
2. 每个投影见证半径3像素的固定圆邻域，至少两个像素显示对应目标的实体表面；射线从实际像素中心发出，原生几何命中对应对象，底图颜色也与该目标一致。不能把HUD十字作为目标像素。边界抗锯齿不按单个顶点整数像素硬判。
3. 两见证之间的数字线段上至少3个连续像素是真实可辨空隙：底图像素不属于A/B，射线首命中为空或严格位于对应间隙线段深度之后（按两见证深度插值）。后景可以透过间隙可见，但其像素须与两个目标可区分；位于见证深度之前的障碍仍失败。特别是SECTION保留的后半壳不能被误判成遮住空隙，也不能为凑背景再次删掉。单凭投影坐标分开不足。固定采用端点投影取最近像素后的单像素8连通Bresenham数字线，仅在两端点之间统计连续3个合格像素；不以宽条带里同一纵向位置的多个像素重复计数。射线比较的float32深度容差事前按8*eps32*场景包围盒最大边长固定，不能逐例调值。
4. 全局图和局部图的对象、帧、图片内容、实际相机及BC面ID关联一致；section验证声明半空间应用到全部几何，natural验证源几何没有可见性改写。原生射线以实际裁剪后的几何审计section，同时对照未改动源状态。
5. 固定颜色判定采用目标/背景基色的预先公布色彩映射及像素误差范围；着色若使颜色变化，原生归属和底图局部轮廓联合判定，不能逐例调阈值。实施前写入评分器并用造假负例检查。

至少拒绝纯色图、只有HUD的伪见证、图像与相机不一致、错对象/错帧、未声明section而删除挡板等负例。主对话另写或独立检查评分器，查看24例底图接触表并对失败/边界例原图复核。自动几何/像素评分不能冒称外部大模型已经完成消费任务；AO另验公开消费。

质量门：总分母24，候选成功数−基线成功数≥5，且基线成功集合包含于候选成功集合。按natural/section及六类分别报告。无图、错误或无法判断均计失败；总体收益通过不能掩盖某类能力失败，不能在F6为0/4时声称剖切已验收。若合理基线已成功20例以上，保留原结果，不能换题或削弱对手凑收益。

## 冷热计时与复验

作者启动三个独立Blender进程；主对话按工作流最新修订审核流程、原始数据及算法/架构，有疑点时针对性复验，不默认重复完整采样。每进程先让双方各完成全部24例首次观察，把shader、section与各场景batch初始化的冷成本逐例另记，避免把未见资源初始化混进热态或偏给先调用一方。然后双方各5次完整预热，再31组成对观察，AB/BA交错。正式样本第p进程第i项使用scene_id=(i+8p)%24，p=0..2，i=0..30；21例各4次，其余3例各3次。预热固定scene_id=0..4。质量24例完整独立核验，可使用该进程首次实际生成的底图，不能用93样本称每例p95可靠。

主边界从已捕获事实开始，包括方向选择/射线、相机与section设置、全局和局部真实GPU绘制、同步/读回、双联合成/HUD、公开PNG编码，至可消费PNG字节和元数据完成。磁盘写入与质量审计在计时外，编码必须在内；两方相同。场景创建与RB/BC计算另列完整整链成本，不混称VG门。禁止成品图像缓存；允许双方同等复用GPU几何与着色资源。各场景第一次观察、GPU初始化、资源构建另列冷成本。

每进程记录完整原始样本、实际GPU vendor/renderer/backend、Blender/Python版本、代码摘要、每次射线数/间隙像素/实际相机和图像摘要。主门为93样本汇总p95候选/固定≤1.20，同时披露三进程中位数、paired差值p95与各类分布。质量门和成本门同时通过才放行AO。首轮失败不覆盖，修复后新文件重跑。

本机已验证EEVEE后台能生成真实64×64PNG；首次19.45秒含shader初始化，不是VG热耗时，也不证明GPUOffScreen路径可用。Blender5.2官方新增gpu.init()支持后台初始化，实施者须实际探测并记录目标GPU路径，不能用显卡库存代替实际后端信息。官方依据：https://developer.blender.org/docs/release_notes/5.2/python_api/ 。
