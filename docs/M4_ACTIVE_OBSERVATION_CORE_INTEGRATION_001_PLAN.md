## 一个完整的核心调用流程

稳定API需能表达“准备当前完整场景与已给定相机池 → 选下一视角 → 使用真实帧核可读性 → 提交已观察覆盖 → 输出短事实/未覆盖范围”。可以用少量函数和一个状态对象；不要求新增协议或通用回调框架。

保留以下实际含义：

- 单对象单个连通无孔平面矩形，允许已验细分；整个场景的遮挡物参与共同depth/owner。多个面片合在一对象、自遮挡通用化不在本批。
- 输入为完整当前世界几何和显式相机池，不把发现目标列表、最优视图或oracle塞给运行器。现有固定正交相机能力保留，不新增相机生成算法。
- 预测完整可见与实际已观察分开；只有真实RGB/owner/depth反馈满足原16表面像素、4对比边界像素、RGB24口径并绑定当前图像/来源后，才增加covered。不得只导出planner而省掉反馈链。
- 图像适配使用规范四角/front和真实细分网格，不能搬回旧adapter的“4顶点2面”假设，也不能用四角替换实际遮挡网格。
- 重复查询复用同一状态/图像；场景或相机身份改变沿用现有失效重建语义。ROI几何身份可在等价细分中稳定，完整场景来源身份仍随实际表示变化。
- 产品与模型可用的简要事实保留对象名称/ROI、实际视角与图像引用、像素依据和有限池unknown。内部逐面诊断不进入默认短事实。此次图片只交给本地核心验证，不声称模型收到。

将旧代码搬迁所需的最小数据转换直接写清楚，避免保留一串“兼容旧实验”的产品包装。源/输入/输出合同在首次新候选执行前固定。
