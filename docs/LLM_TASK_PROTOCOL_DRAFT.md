# E1 本地间隙任务收益验收草案

2026-11-06，主审 024 修订草案。每臂 12 个复杂任务和 2 个简单控制。两臂用相同初态、目标、容差、写入范围及可见材料。上版数学清单和证据保留在 `revision_002/delivery_001` 和 `revision_002/protocol_smoke_001`。本版先交付场景清单、数值评分器和原生辅助程序设计。实际 MCP 宿主、真实模型和成本按各自登记执行。 [任务架构](LLM_ENTRY_ARCHITECTURE.md) · [主审 024](LLM_ENTRY_PREFLIGHT_REVIEW.md) · [限定复验](LLM_ENTRY_RECHECK_PROTOCOL.md)

## 任务及固定清单

对已明确的移动和固定参考对象，把其全局无符号表面间隙缩到指定世界米数。终态应为达到目标所需的最短刚体平移。两臂都只能平移 moving。保持 moving 的求值形状、方向、缩放，及 reference、父级和其他物体的变换与几何不变。纯数值题应报告达标状态、最终真实间隙和实际世界米平移。带图题还应交付指定模式的终态图，说明图中是否能辨认两个目标的最近端，证据不足时据实报告。真实碰撞分类不属于这些任务。

下表的场景由 `verification/llm_task_reference.py` 的固定 recipes 创建，来自已知世界米制的 `verification/integration_fixtures.py` 公开构造器。`d0` 仅用于离线确定请求参数，在正式开跑前换算成表中的固定数值并散列；两臂都只收到目标值和相同对象标识，不能读取场景构造参数或评分文件。数值与图像族的 mesh 各不相同。目标容差取 `64 × ε_float32 × fixture.scale_m`，在清单中用具体值给出。

## 证据与独立判定

在各臂执行前，用同一场景创建入口生成 Blender 场景并冻结输入文件、mesh/父变换和提示词哈希。清单由 `python -B -m verification.llm_task_reference` 生成。独立读取 evaluated RNA，逐顶点验证 moving 的统一最短平移，并检查 reference、父级和其他对象的矩阵及求值几何。用 `llm_task_reference.check_numeric(..., arm=..., writes=...)` 检查实际结果。沿登记的分离轴投影全部实际顶点得到全表面距离下界。对实际三角拓扑中的登记点、边或面，用独立最小二乘求两个仿射支撑的最近点，再以可行重心组合构造上界。D02 要求两条实际边的重心权重均大于 0.05，D03 要求实际三角面的三项权重均大于 0.05。两案额外核对实际支撑平面附近的顶点集合正好是登记特征。上下界各向外留 `64 × ε_float64 × 最大实际坐标绝对值` 的数值余量，最终区间必须有序，两端均须在任务容差内，并匹配公开结果。保留前后边界、重心权重和失败原件。评分器不读取候选 AO、BC、Outcome 或候选回传的见证坐标。

审计前端在同一 Blender 主线程和 `temp_override(scene=..., view_layer=...)` 中读取 `evaluated_depsgraph_get()`。对每个登记的 mesh 和父级记录稳定 ID、评估 `matrix_world` 及当前帧、单位。对 mesh 调用 `evaluated_get(graph).to_mesh()`、`calc_loop_triangles()`，保存原顶点与三角索引，并在 `finally` 调 `to_mesh_clear()`。世界米顶点使用真实 `matrix_world` 变换后乘 `scale_length`，输出 `matrix_world_bu/world_vertices_m/triangles`。同时枚举实际 scene 对象和数据身份，查有无新增、替换或删除。记录第一笔可写调用之前的 before，以及终态包括错误路径 `finally` 的 after。保留快照和原回包各自的哈希。

独立写入审计记录对象、顺序、操作和实际次数。I 在验收 runner 按冻结源定位 `BlenderControl.execute` 里实际 `moving.matrix_world` 的 setter 行，N 的 runner 定位通用 `translate_world_m` adapter 的实际 setter 行。两臂使用相同的解释器局部 trace 策略，记录进入 setter、完成或异常及绑定对象 ID，终态仍由独立 evaluated RNA 复核。N 脚本可任意编排计算、只读原生查询和多次调用受审计平移，实际写操作走该进程内 adapter，无额外工具往返。保存实际执行脚本供独立核对，出现审计覆盖外写入、绕过 adapter 或未能确认写入时保留失败。前后快照无法发现曾写后恢复的越界修改。计量前固定 audit 开关及原始边界，任何窗内审计开销原样计入。

C02 两臂均零写入。其余案例检查 I 一次写入的实现合同，N 可以多次明确写入，只要范围和终态质量达标。所有写入与回读计入本臂总耗时。将两臂公开结果统一为米制字段时，仅用已交付给模型的状态、数值及其确定性换算，不能从评分 oracle 补缺失事实。

V 族还要求每臂实际交付终态图。按 `(case, arm, task_id, observation_id, frame_id, mode, sha256(PNG))` 关联实际标准 MCP 图片及同一图的相机证据。I 通过 `eye_inspect` 的 `camera` 读取当前图的缓存证据，N 的 adapter 同时返回对应渲染证据。评分原件保存两个面板的裁切矩形、相机/投影矩阵和像素坐标约定、单位、对象 ID 和色标。SECTION 同时保存实际有符号切面、保留侧、对象集合和切后几何或同源可复算的裁切参数。评分射线在对应面板的实际保留几何上判定，NATURAL 用未切几何。裁去的端点、前景遮挡和无图分别记录。缺同源相机、切面或像素证据时保留未知。不能重渲染来补旧 PNG 的相机或切面证据。

每个面板、每个目标端点分别投影，按像素中心约定取中心和上下左右各偏移 2 像素，共五点。独立射线先判顶层对象与该目标证据，再与实际 PNG 的冻结色标或轮廓一致性对照。单点标签为 `visible`、`occluded`、`cut_away` 或 `unknown`，无确认的 hit、超出面板、边界不稳定和射线/像素冲突均为 `unknown`。同一标签取得五点中至少三票才输出该标签，否则给 `mixed`，保留五点原始分类。不可判定的票仍在五点分母。最终回答以登记的 witness 面板判定为主，场景面板保留独立标签作上下文复核。正式前每个 V 案至少一项有独立证据的确定标签，整个 V 组至少有 `visible` 与 `occluded` 各一项，不能以四案全未知取得资格。

正式开始前须独立冻结 V01–V04 的实际相机、各样点坐标、切面及标签。两臂使用同一冻结观察条件或证明等价遮挡难度，评分端实际取得 PNG 后仍需复核绑定和图像。当前四案的实际相机和标签未采集，视觉资格尚未冻结。模型答复只能基于交付给它的图与公开证据。

双臂每案独立新模型上下文，不继承其他案的答案和临时脚本。固定硬件、Blender/驱动、宿主、模型可观测版本、采样设置、工具输入及等待上限。镜像恢复同一初态，预先交错两臂，按表顺序用 `IN, NI` 交替。各族第一案测完整冷启动，余案使用同一进程的常驻工具和帮助代码，使用新目标会话和相同的必要建表。C01 冷、C02 热，两例只报告控制结果。预先记录实际顺序、超时和故障原因。题目、评分、执行命令和真实前置条件在第一份正式成绩前由主干签定。

## 合理原生对照

I 为候选，N 为同模型使用 Blender 原生工具。两臂可获得相同的对象目录和场景，能写相同对象，使用等价的目标读回与图像能力。N 可用 Blender Python、NumPy、BVH、预置通用几何/渲染 helper、常驻函数、缓存、批处理及其自己的脚本。一次批处理可以测量、求解、执行和核验。I 或 N 都不强制把逐步算法决策交给模型。只有用户意图和允许对象从提示及相同公开目录获得。N 可以从原生工具读取实际网格和顶点索引，其通用计算不得利用评分器所知的特定顶点身份、轴或真值，也不得读取 HE 内核和候选输出。记录并冻结 N 实际使用的通用 helper、加载与派发。N 的脚本若已经单工具调用完成，往返按一次计。原生工具无法达到同职责时先报告资格缺口，保留原始材料。

原生起点 helper 是 `llm_task_reference.native_surface_pair(vertices_a, triangles_a, vertices_b, triangles_b)`。它对实际求值三角形按 AABB 下界筛选，直接计算保留下来的三角凸包最近点，返回世界米间隙和两个见证点。正式 N worker 单独封装此通用函数与 `verification/test_bc_acceptance.py` 中 `_supports` 和 `convex_pair_oracle` 的必要数学源码，输入只含模型本来可读的 evaluated mesh，不给 N worker 装入 task recipe 或评分器。N 可以替换成更快的通用精确实现，先冻结身份和依赖。若使用此起点，主线程 adapter 一次调用做以下操作。

1. 用 `capture_pair(scene, view_layer, object_ids)` 依上述 RNA 协议获取实际两网格与单位，调用 `native_surface_pair`。无可测表面或请求增距时原样报告。已在容差内直接返回实测结果，零写入。
2. 对正的缩隙，计算 `delta_world_m = (d - g) * (point_b - point_a) / d`。调用 `translate_world_m(moving, delta_world_m, scale_length)`，读取实际 world matrix，将米增量按单位换算并仅赋一次世界平移。通用脚本可按需重新测量并明确再次调用。
3. 重新取得 depsgraph 的 evaluated RNA，再调用同一 helper 核验实际间隙和实际位移。按需在已登记相机下提交终态图和同源证据。N 的采集、真实 setter、回读、可选渲染与外部工具配置尚需实际冻结，当前仅有独立数值 helper 和可执行接线约定。

同责证据记录与实际计量分开。下线前，独立评分核对真实终态，产品前台可见的工具输出必须足以答题。若需要补查或重取图，应由模型实际请求并计入窗口。人工预绑定、目录和工具 schema 的生成、加载、注入均分别计时或计量。冷任务含首次启动和 helper 加载，共享的一次性准备不按每个热任务重复计费。使用同一开发预算冻结两臂初始工具，不强迫原生每题重新编写通用脚本。

## 端到端指标与事前门限

每案在同一任务材料释放事件开始计时。冷案事件先于任何本臂专属的进程、工具、绑定或模型启动，热案只把实际复用的工作留在窗外。终点为最终答案及其必要证据首次齐备。计入 schema/目录、模型等待、全部工具调用和补查、读取图片和编解码。独立评分过程本身在计时窗外，失败或超时用预登记 180 s 截止值进入完整耗时统计，实际时间与状态保留。记录时间戳、请求序列、独立评分及首次正确完成的事件。报告 12 配对完整值、每族 4 配对和单独的两个控制。完整 p95 使用最近秩 `ceil(0.95 × n)`，主样本 `n=12` 因而取最大值，表明本批尾部而非服务 SLA。

| 指标 | 冻结候选门限 |
| --- | --- |
| 质量 | I 的 12 个复杂任务和 2 个控制均通过独立间隙、作用范围、写入和答复检查。N 成功配对中 I 不新增失败。错误/超时保留。 |
| 完整任务时间 | 12 案配对截断时间的 I 均值 ≤ N 的 50%，至少 9/12 配对 I 更快，各族均值及全部复杂任务 p95 均 ≤ N。 |
| 模型决策往返 | 纯数值对象明确题一次 `eye_run` 可完成。N 多轮子集的串行决策往返中位 I ≤ N 的 50%，子集为空时记不可检验，报告真实轮数。 |
| 文字 token | 全 12 案模型可见的总文字输入输出 token（含 schema、目录和补查）I ≤ N 的 50%。同时记录真实工具 UTF-8、PNG 和 IPC bytes。使用方若不公开这类用量，标为未测，E1 整体保持未通过验收。provider 计费和图像 token 保留各自的实际数据或未知。 |

脚本确认功能、本地通道时延、实际 MCP 宿主可消费、真实模型整任务收益分别出结论。本草案不签发执行权限。E1 达标前不推进 E2 形变任务。
