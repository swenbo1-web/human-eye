## 正式序列与失败归因

正式序列采用五组 `AB / BA / AB / BA / AB` 顺序，每组覆盖三档。每 arm/tier 分首次 1 次、静态 3 次、姿态变化 3 次、几何变化 3 次。控制只修改私有背景对象，目标保持固定。

完整 caller RTT 是主要指标，服务内 line-to-flush、宿主采集、启动、EOF、CPU 和驻留峰值分别记录。原 10 秒产品 TCP 超时、64 MiB 响应上限和数量预算保持一致。

中、大档各类别要求中位数改善至少 `max(1 ms, 5%)`，且至少四组达到该门限。所有类别 p95 回退预算为 `max(2 ms, 5%)`，小档中位数回退预算为 `max(1 ms, 2%)`。p95 使用 nearest rank。门限在正式序列前冻结。

第 28 个运行 `block04-tier64-B` 失败栈为 `run_formal.py → run_baseline.await_file → json.loads(path.read_bytes())`。该运行没有 SERVICE_READY、WORKER 或 MCP 请求，Blender 随后正常发布 READY 并退出。失败位于测试器启动交接。

写入端直接创建 READY 文件，读取端看到 exists 后立即解析。空或部分发布窗口是当前诊断推断。失败那次实际读取字节没有独立封存，因此这一诊断的依据为异常栈、发布代码和事后的完整文件。

冻结规则要求保留失败并终止剩余运行。本轮保留了失败行、正常请求数量审核的附带错误和两个未运行项。评分器只调用一次，返回未完成，性能类别列表为空。部分样本的原始延迟保留用于故障审查。

正式阶段实际完成 270 次完整 RPC，累计 `1,105,031,873` 字节。243 次 QA 属性赋值由独立控制驱动完成。全部已启动进程正常回收，27 个真实入口完成 EOF 来源核验、host close 和 reader join，二进制、安装与场景哈希保持稳定。

## 测试器纠正与证据边界

最早无计分 smoke 发现模板验证器间接导入候选 host，提前加载了 `array`。修正后由实际外部 service 的原格式化方法生成绑定模板，Blender 测试桥以纯标准库验证完整模板。第二次无计分 smoke 证明两个 arm 首次执行前 `array` 均未加载，候选在首个真实 host 执行时完成导入。两次 smoke 的耗时全部排除评分。

READY 文档记录了较早 freezer 的哈希。实际 FREEZE 使用增加了安装预核及生命周期口径的 freezer，执行中的 server、worker、runner 和 scorer 与已复核版本一致。主执行在 GO 前检查并记录这一差异。

真实 Undo/redo、排除图层对象求值、共享 GUI 与第三方 addon 调度均列为覆盖边界。本轮保持零新模型消费者，Codex 任务质量与完整模型任务成本仍待后续独立对照。M2 场景驻留与完整架构验收继续开放。
