## 模型与引擎分工

独立 MCP 候选提供 `human_eye_owned_reference_inspect` 和 `human_eye_owned_reference_restore`。前者读取当前原始网格、意图参考差异及历史；后者只接受1–8个顶点索引。模型不能传路径、参考正文、批准、时间、事件、预算或 journal。固定操作者配置选择 Blender 二进制、输入 `.blend`、参考及其哈希、目标身份、运行源版本和持久 journal 根；参考作者必须可信且确实保持同索引对应，文件哈希本身不证明意图或正确对应。

审批表展示冻结的当前/目标局部坐标、源与参考摘要、单位、矩阵、语义目标、最大位移、尝试次数和原期限。只有协商支持 form 的 MCP 客户端严格返回当前表单 ID 和布尔 true 才通过；数字1、错误ID、拒绝、取消和模型参数都不授权。stdio 所有者被信任会诚实呈现表单，脚本测试不是真人批准证据。

执行在一个新的、固定源码的后台 Blender 进程内完成，目标场景只含一个原始三角网格，至多128顶点/256三角、8个选中顶点、每顶点1毫米、包括恢复在内至多2N次 setter；原30秒从 MCP 接收时算起，包含排队、来源检查和审批。本地每步回读并检查完整原始状态、保护顶点和离散中间状态新增自接触，无需模型逐顶点重算和逐步发命令。

没有认证连续扫掠曲面的安全性，也未开放跨对象碰撞、拓扑、骨骼、自由重建、任意编辑或保存。最终状态只在子进程内成立，`save_status=not_saved`，输入文件始终保持。旧刚体 worker 的全 setter 保障未扩大到顶点写；这个专用 worker 自己只含有限读/目标/审批回复/关闭协议和唯一顶点 setter，没有模型代码执行命令。

## 可靠性与计量

同一个连接最多16次工具调用，重复 ID 只给历史收据，不再次动作。具体审批与原始接收时刻绑定，队列中的取消也阻止准入。原窗口外、未知响应或计数不可信会停止并关闭该进程；不得当作零动作或重新开始。

每个 journal 根终身16个目标槽，setter 前持久化 pending，实际读回后提交结果；缺记录/缺终态/未知保留 null 计数并隔离。重启可读取，不从 JSON 恢复授权，也不能清空未知重开。SDK callback 尝试与真实 RNA setter 尝试分别计量；后者由固定专用 worker 的唯一写入口统计。保障范围不包含恶意修改的同账户代码、扩展或操作系统级对手；文件 fsync/原子替换不冒称完整掉电证明。
