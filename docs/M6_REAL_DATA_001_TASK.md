## 实施顺序与交付要求

1. **取得实际输入。** 核对源文件并制作本批隔离副本，记录前后散列；原件不写入。优先复用来源可核实的旧导出，否则在独立后台 Blender 中禁用文件自动脚本，仅运行本批只读采集脚本。记录 Blender 版本、文件来源、场景、单位、坐标系和帧。不要连接或操作共享 GUI。
2. **一次清点所需结构。** 记录对象类型、网格顶点/面数、拓扑连通分量、变换、modifier、Armature/骨骼层级、顶点组及实际权重、shape keys、动画/pose 是否存在、外部依赖是否可用。先读取数量再展开需要的数组；只对选中对象或 patch 导出完整数据。原始网格与求值网格分别记录，不能把它们默认为同索引。不得因为旧入口的 16,384 上限就跳过原生数据调查。
3. **固定一个手臂区域的输入表示。** 若实际数据能辨认手臂，保留选区依据、对象/顶点原始 ID、坐标、拓扑与现有相关绑定；闭合截面和骨链只有实际存在且可核实时才填写。若不能可靠定位，保存能说明原因的原生结构或必要局部视图，明确缺少什么定位条件，不虚构标签。完整几何及原始文件留本机，提交脚本、汇总、清单与散列。
4. **分清三种结果。** 分别交付“原生输入存在并已采集”“现有产品 adapter 接受/拒绝的具体条件”“目标或监督是否存在”。adapter 域外仍继续完成只读清点与输入表示分析；原生采集不冒称 product verified。实际输入若符合现有几何域，再运行一个明确任务条件下的几何控制和独立实际形变核验；不符合时保留原结构，不把真实权重/骨架改成旧三骨公式的形状。
5. **确定可比较任务。** 若只有静态外观、无绑定或中性参考，列出实际可观察量与当前不能监督的输出，提出一项最小补数办法。若已有 pose/rest、修正 shape key 或实际参考，核对其配对关系，形成可复用的局部数据样本和下一轮明确任务。人工接受、原画美术偏好、几何物理量、已知合成扰动分别标注；不能把程序制造的答案写成真实修复效果。原始数据不满足任务时也必须给出可执行的下一步，不以一句“来源拒绝”结束调查。
