# 刚体执行坐标系与面向对齐的坐标系检查

本轮真实 Blender 测试发现：六棱柱和十五棱柱拥有明确的宿主坐标系，精确间隙也有效，但旧的面向对齐检查要求三个物体轴都平行于某个面的法向，因此拒绝了合法的世界坐标刚体增量。该限制适用于旧对齐控制器，不能直接决定任意刚体是否可以执行明确的平移和旋转。

插件现在分别报告两份证据：

- `measurement.axes_valid / axes_check / control_frame_trustworthy` 保留旧对齐算法的含义。其失败不被改写为成功；角度目标仍使用原有角度验证规则。
- `rigid_frame_valid / rigid_frame` 验证宿主明确提供的原始轴、物体枢轴及来源。轴必须有限、正交并且为右手系，原始来源必须是 `host / explicit`。缺失、推断、模糊、反射、病态及通过字符串或布尔值伪装的坐标系不能被反序列化默认值升级为可执行。

新合同仅支持调用者已经明确给出的世界坐标 XYZ 欧拉旋转和米制平移。旋转以实际物体枢轴为中心，随后应用世界平移。它不自动生成对齐动作，也不证明接触角度达标。

`rigid_frame_valid=true` 仅证明坐标系满足该合同。执行还必须通过当前完整场景的实体支持、工作预算、精确终态碰撞、观察身份与时效、宿主能力和版本比较，并读取实际执行结果。部分场景、未知实体和不支持的宿主操作继续阻断写入；该合同不证明运动路径安全。

观察、预检、实际执行及执行后验证使用一致的新合同。旧观察合同在导入和执行边界失效，缓存算法版本更新；执行中的日志和隔离状态继续保留。已知的准备阶段拒绝会保留具体原因，不再被笼统替换为“需要观察”，也不会先写入一个本来就无法执行的操作日志。

本轮新旧候选使用相同预注册 Blender 场景和 2 微米间隙／姿态标准。旧包的失败证据独立保留，不能用修复后的结果覆盖。几何精度、诊断图和隐藏变化识别不等于模型任务收益，后者仍需要另行实战评测。
