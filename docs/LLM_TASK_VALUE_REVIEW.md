# 大模型接入第二次设计复审

2026-11-06。结论：保留常驻通道，改用任务执行与最小结果；修订1的逐动作入口尚不足以证明用户要求的复杂三维任务大幅提效。**本次通过的是设计选择，不是产品收益验收。** [当前架构](LLM_ENTRY_ARCHITECTURE.md)与[实施工单](LLM_ENTRY_WORK_ORDER.md)已同步，原设计/决定在37c672c和原证据ZIP中保留。

## 为什么必须改变

[B3e原报告](B3E_PRO_TASK_QUALIFICATION.md)记录精简core与合理native均初答10/10，native资料39,288B，core为99,427B；这些是文件字节而非模型usage。旧9.7.2报告记录纯视觉有限试验插件55.3、native68.1且各1/3成功，不能推广成算法优劣，却足以否定“给模型更多图/字段自然会更好”。Y1原始失败还表明负反馈已经返回，模型仍因处方冲突弃用。必须把可确定计算、目标误差与真实结果连起来。

独立复核的逐动作候选会固定按binding渲染after、转发全部联合AO；细粒度功能夹具还反复predict/read/observe。它符合原工单，不能据此指责实施偏离；问题是原架构把优化重点放在了通道。作者已经据本轮要求改写任务入口，旧审查缺项绑定其阅读时间/hash，不能冒充新版本仍有同一缺陷。

## 主干采用的架构与算法改动

1. 交互单位从一个动作改成一个明确目标；公开run/inspect，生命周期由宿主负责。正常任务没有强制预测、确认、评分和重复观察回合。
2. 依赖按任务选取。首个close_gap直接复用public BlenderControl的RB/BC，返回typed真实结果；不跑无关TD，不生成完整AO后再解码，不强制CF推理。需要视觉才调用一次VG终态图。数值内核不重写，原完整Session继续用于其适用任务。
3. 全局最近点a/b、初始间隙d、目标g满足可信刚体前提和0≤g≤d时，采用delta=(d-g)(b-a)/d。三角不等式给全局下界g，旧最近点给上界g，得到解析解；无需逐候选预测或搜索。真实执行后的全局回读仍决定是否达标。
4. 默认结果只含目标、实际控制/误差、达标和必要身份。定位问题保留对象/原face ID/世界米坐标，视觉问题保留当前真实图及语义。矩阵、Top-K、日志等按具体请求给，不让必要信息靠强制第二轮补查。

这比独立审查最初建议的“在本地做有限候选循环”更直接；该早期建议没有被实施验收后再重开。主干与独立审查共同核对解析证明及实际前提。32个CPU设计状态用已验BC与独立SVD凸包穷举oracle交叉检查，最大误差4.440892098500626e-16m。仅证明本例算法构思与数值计算一致，**未证明Blender刚体合同、图片交付或实际LLM收益**。

没有把函数命名为任务就声称得到通用规划。单轴/增大间隙不满足当前解析证明，零距离不证明未穿透，第三物体避障不是此次任务。场景前提由可信绑定声明，验收检查其真实成立；不建设运行时全依赖扫描和旧防御框架。

## 如何取舍审查建议

采纳合理native、完整任务2倍目标、失败计入、模型输出与字节区别。先缩到E1的三类复杂任务共12episode/臂另2简单控制；未采用首轮审查建议的shape/扰动恢复24episode大混合集，因为它会把未实现能力混入本阶段，并稀释解析任务的交付。E2 shape求解在E1通过后再定独立任务集。

原20%桥收益和3×5+31局部微基准降为实际瓶颈时的归因实验；没有已产生的正式入口成绩被改门放行。新的主要门：限定任务质量通过，复杂任务完整均值至少减半、至少75%配对更快、各族及p95不劣；可见文字token目标减半，native多轮子集决策往返中位减半。合理native可预建通用helper、使用解析公式、批处理与缓存；它已一次完成就如实按一次比。usage不可见时token/费用未验，脚本成功不等于模型收益。

首批只测正确动作/回读、单位/身份、真实图片及必要收发/关闭，不再展开防御边界矩阵。难题的小模型是后续独立能力；当前CF V+A不承诺通用求解，也不能替错误几何或缺失定位兜底。
