**隔离候选通过离线工程验收。** 在已有 `--region-task-evidence` 端点里，成功的区域任务简报可携带 `witness_image_paths`。只有实际交付的完整局部见证才进入该可选表，列为 `frame_index` 和 `local_image_path`。同一帧最多一条。候选从现有服务读缓存核对当前捕获代、原 scope、原帧、像素行和本机路径。两个局部作用域的文件各以自己的第一个构造序号 `001` 命名。证据缺失时省略可选地址，原图交付沿既有合同。

## 实装冷、热回放

先以 `24b88557` 回放 A1 的真实 `brief` 和 B1 的真实 `full`，再用候选 `1535d08a` 的证据端点分别回放原参数。每格通过同一个实际生产 stdio 服务先走冷生产入口，再走正常热缓存。真实安装的 Blender MCP 宿主解码封存采集增量，首次构造只使用同一闭槽的光栅生产记录，保留正常的服务绑定、缓存、编码和发布。两次请求访问同一缓存对象，热请求证实命中及复用三帧。

四格全部正常 EOF、退出码 0、句柄回收。候选冷、热共四份公开回复通过独立帧、图、像素以及固定 CLI 三工具头双阶段核验，共 **24/24**。两个旧模型槽的四个原图地址，在冷、热都与真实历史 `read_images` 的同槽路径原样一致。关闭后直接按地址读回的字节与本轮三个公开 PNG 中各自对应的图块相同。两格候选各有三张原 PNG，合计每个回复 7,918 B，图像顺序、摘要及业务事实保持。全场低像素 SCENE 仍有原图（对 R 仅 1 个表面像素、1 个对比边界像素），其帧没有路径表项。局部 SCENE 和 LEFT 的路径各绑定原作用域和帧。

每个候选正文 **7,564 → 8,144 B**，增加 580 B，低于冻结的 10,800 B 上限。实际 JSON-RPC RX 增加 594 B。运行源码身份和当次会话标识单独核对，其余公开正文除可选表逐项相同。两次公共读图复验在每个产品版本下各与原槽真实回包对象相同。[正式结果及分段原件](evidence/RESULT.json)

## 见证反例与范围

独立检查实际 QA、QB、A1、B1 四份原简报。将实际 QB、A1、B1 的 R 见证 `frame_index` 从 1 改为 0，只变一个字节，外层回复仍为 18,912 B，原图、帧表、像素计数和生产记录均保留。旧恢复评分器三次误收。新验收三次都因公开见证与自身作用域和生产帧不一致而拒绝。原测试判定保留。本批验收另外关联选区 ROI、原像素行和原生内容块位置，避免用两个同名 SCENE 替代彼此。 [独立见证反例和原始摘要](checks/PUBLIC_WITNESS_CONTROLS.json)

15 项装载实际候选的定向检查通过，含同字节跨槽、同槽跨生成、真实 Windows 大小写别名、错代、无保有记录、不确定匹配、未交付图、编码后文件缺失、坏图摘要和每帧去重。同槽另一生成的等字节文件用内存文件视图模拟，原目录和文件没有写入。坏图仍走旧的摘要拒绝。另用四个实际生产 stdio 进程做 **30/30** 兼容比较，覆盖标准全文和简报、普通目标和独立选区、无图、已过期引用、无效参数及正常恢复。工具目录逐项一致。 [可选路径控制](evidence/PRODUCT_CONTROLS.json)
