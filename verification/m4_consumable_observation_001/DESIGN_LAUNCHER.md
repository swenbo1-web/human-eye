The launcher belongs to M4-CONSUMABLE-OBSERVATION-001. It runs one fresh P1 route after the root freezes the candidate, installation, inputs and entry sources. The shared prompt retains SHA256 `ecbcb28c961847f14ae9564425f1b8152f07b952d2d5f38ebfcd9fd143ff79d4`.

## Accepted execution chain

- Load the pinned localization launcher from its original path and obtain the actual accepted `connect` chain. Reuse its route, consumer, archive, result matcher, CLI settings and held-handle cleanup code objects.
- Give the new route private globals for this namespace and its input check. Replace the actor command with the current namespace's bootstrap and bridge, plus this batch's product binding and budget paths.
- Keep one P1, one user turn, the original 450-second absolute route deadline, 12 business-tool admission limit and six actual raster attempts. Preparation uses zero model sessions and zero rasters. The entry has one exclusive start marker and one call site for the real route.
- Preserve prior module objects and source bytes. The inherited source closure remains pinned against the accepted localization freeze. Explicitly add the candidate installation, new binding, bridge/bootstrap, inputs and scorer to the new freeze.

## Runtime identity checks

The entry retains actual function and code-object references in its own process. It checks those references, current private globals and original archive/matcher references before and after the route. The eight inherited `connect` predicates remain explicitly labelled as a connect-time snapshot.

Source bytes are checked against the frozen map. Function descriptions record original module/path/name and source-file SHA. Runtime serialization fingerprints are absent. The identity guard relies on references and pinned source bytes.

## Final publication

One small execution wrapper surrounds the route call with `try/finally`. It preserves a returned row, including an ordinary failed row, and separately records a route exception. Publication records carry the actual route state and terminal exceptions. A post-route source or identity failure remains separate from the route result.

The finalizer attempts each required receipt independently so a write failure in one receipt does not suppress the other receipt attempts. It writes the aggregate `RUN_RESULT.json`, launch outcome and final timing. The parent process receipt supplies the complete outer boundary. It retains all source, route and publication failures and performs no retry.

## Zero-model finalizer checks

A small separate check script injects only literal route returns and exceptions into the finalization wrapper. It covers a successful row, an ordinary failed row, a route exception and a post-route-check exception. Each case must retain its actual row/exception and publish the aggregate, launch and timing records. The script starts no CLI, actor, product, renderer or model and imports no product implementation. It never calls the old fake consumer or protocol matrices.

## Evidence boundaries

The new bridge owns the exact public JSON reuse and its source-bound image delivery. The launcher records its actual route outcome without interpreting answer quality. Product projection tests, quality grading and cost analysis keep their separate evidence and scopes. The root performs the only real provider launch after qualification and freezing.
