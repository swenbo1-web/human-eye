# b32g 整版隔离验收

现行桌面发行 `9.7.2+20261110.scale.opt.r1` 对照产品集成 `6c93f237` 对应的 `9.7.2+b32g`。两版源码和启动绑定分别核验 137/137、143/143。几何、只读观察、普通 MCP、隔离 Hook 功能和正反向迁移通过。桌面默认继续绑定现行发行。发布前仍须验收自动 Hook 派发，固定 launcher 的既有轻路径审计缺口需要处理。

## 真实 Blender 和普通 MCP

四个独立冷槽按 A G60、B G60、B D48、A D48 顺序运行。12/12 几何、4/4 只读复核通过。四个 Blender 和 MCP 均正常退出，四份副本逐对象初末世界网格相同。无模型或费用。实测均为各场景一对。

## Hook 和回退

- 固定 Hook 实际命令离线用例 A/B 各 10/10，候选 console 3/3；错身份与畸形写前事件按原合同拒绝。共享一个额外隔离 Blender 的实际只读 Hook 两臂均取得 12 对象，72 个真实包围盒坐标逐项同值，各一次只读采集，零执行和渲染。原评估将能力字段误作执行，闭槽依据同一实际回包复核通过 2/2，无重发。两版固定入口轻路径均因未注册的 runtime_identity 别名抛出 KeyError 并返回空结果，漏记 skip/trace。空间读取的重路径有真实审计记录。自动 Codex 宿主派发及信任生效未测。
- 用现行配置、Hook 和账本的隔离副本运行实际管理工具，A→B→A 各改四个管理文件，状态只改绑定指纹。实际 MCP A/B/A 三个入口通过初始化、目录、状态、ping 和退出。过期反向计划被拒绝且零改写，重算计划回退保有 6 个会话、2 个 goal segment 记录和后加的检查标记。两版审计代码的原合同会在文件超过 2 MiB 时保留最近 1000 行再追加。第一遍脚本错误要求 MCP 运行后副本审计文件完全同字节。第二遍脚本把摘要字段误写成 source_sha256。两次原件都在，最终验证逐字节复算六条试验启动/状态记录及原保留策略，管理命令自身对副本审计文件没有改动。
- 桌面前后 8 个受保护文件中，MCP 配置、Hook、两份连接器、两份状态和一份日志共 7 个 SHA-256 一致。桌面 routing-spatial 审计在窗口内记录两条现行版初始化 trace，时间和 PID 均与已记录的验收进程不同，来源未确认。保留实际日志及两份指纹，本轮仅对隔离副本执行迁移。

## 发布判定

几何和隔离迁移通过。保留 `b32g` 集成版本。正式切换前，在隔离宿主配置补自动 Hook 派发和信任验证，验证轻路径审计稳定交付。D48 大幅改善与 G60 整窗回退都是本次单对现场观测，正式发布记录需按冷启动、业务及完整生命周期分别记账。
