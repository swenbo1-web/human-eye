# b32g Hook 修复与实测

固定启动器里的轻量 Hook 已恢复审计与请求追踪。隔离固定入口、真实 Blender 只读重路径和普通 MCP 兼容检查通过。外层耗时本轮未证实稳定提速。Codex 自身的自动派发与信任验收仍待进行，桌面版本继续使用原发行。

## 固定版本与修复范围

基线 `6c93f2375d1073b33e721a168f1fcf610ac6dbdc` 对应 `9.7.2+b32g`。候选 `31792523ecb48a500b8eed0ecb531c7ecc8e767e` 对应 `9.7.2+b32hook1`，产品分支 `codex/b32g-hook-release-closure-001-product`。固定安装核过 Git、源码快照、wheel 与安装文件的 143 个运行源，仅 `human_eye_hook.py` 有产品差分，032 BVH 的 `surface_proximity.py` 逐字节相同。候选源集 SHA-256 为 `a72aefd84549c05ec37ee09490354416e06f6451c14e8115f395efb80cf0a62d`。候选 wheel SHA-256 为 `53283911b4adc8084d29b36d2139ad876afe8d23cba6481d8a054565b0aef293`。[安装绑定](BUILD_BINDING.json)

旧轻量分支用私有别名执行支持模块，缺少固定入口的源码执行见证。运行身份初始化在审计前异常，两类事件仍返回 `{}`。候选在固定启动器的源码守卫下复用已核的规范模块。直接启动的独立 Hook 保留原有标准库路径。守卫错根、冲突及预载无见证模块均拒绝。篡改隔离副本的实际注册命令以退出码 2 拒绝。53 项现有回归和 11 项额外源码守卫核验通过。[守卫核验](GUARD_REVIEW.json) · [回归](REGRESSION.txt) · [篡改拒绝](LIGHT_TAMPER.json)

## 发布状态

实际管理入口通过隔离 `b32g → b32hook1 → b32g`。三次固定 MCP 握手、五项 Hook 注册及六条分阶段构建审计均核验。状态实改后，旧计划被拒绝且配置文件保持原字节。重算计划后保留最新状态，服务、Hook 与连接器配置回到初始字节。首次准备复用了旧状态标记，未制造陈旧计划，保留该次原回执并使用独立副本完成反例。[真实回退核验](ROLLBACK_SUMMARY.json)

032 历史 99/101 继续单列。扫描用例的旧测试替身未接收真实接口传入的 `before_compute`。旧启动用例运行源码入口，既有失败档案只记了测试名，无法确定失败断言。此前 b32g 固定入口的四次初始化与本批身份、普通及 opt-in 实装握手分别通过，历史启动失败照存。

隔离验收调用实际固定启动器和注册命令。Codex 真实信任评估和由宿主自动派发的三类事件未在本批触发，在途主动终止也未验证。候选以隔离安装验收，产品源码与复核证据已发布到独立 Git 分支，未执行桌面切换或扩大默认模式。模型 API 调用和增量费用均为零。

本目录提供审阅用记录和白名单复核包。完整 1,126 件原件留在本机归档。其中包含宿主、场景、会话与环境记录。归档与发布文件摘要见[证据索引](EVIDENCE_INDEX.json)。
