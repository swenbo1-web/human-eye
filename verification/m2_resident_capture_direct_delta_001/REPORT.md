# M2 Blender 驻留整场捕获直接生成增量

**隔离候选通过 2/2 个真实 Blender 槽。** 生产 `BlenderMCPHost` 的整场捕获在现有主线程和锁内，将当轮驻留数据与原有令牌交给同一个增量编码器。增量编码可以直接从私有缓冲区读，回包元数据与需要发送的资源仍由编码器独立构造。全量回退和普通 `capture_scene()` 继续返回独立快照。产品 `4104add4` 从 `ee385e98` 派生，仅改 `blender_host.py` 和 `blender_mcp_host.py`。[固定方案](PLAN.md) · [分段与原件索引](RESULT.json)

## 离线回归与准入

- 两臂各通过 21 项实际安装回放控制和 26 项既有公开宿主测试。用前一批冷完整和热增量真实 TCP 原件，经现有生产命令、编码和解码核对资源 2→0、原令牌和有序几何。控制涵盖几何、姿态、显示、换代、错绑定、无驻留、部分资源与法定恢复、快照隔离、线程限制、异常后恢复和普通选件路径。冷装载只在捕获采集边界接入已封存数据。
- 采用当前安装各 8 个同机交错热样本，采集返回到编码结束的中位 **163.661→0.090 ms，下降 99.945%**。提前复制的几何缓冲区 **6→0**。单独编码器中位 **0.06635→0.06690 ms**。这些实测使用正常 GC，范围从回放采集返回至原编码器结束。
- 现场前复现旧批两处拒绝，旧 1/2 判定保持原样。新验收器核宿主区间在完整 TCP 内，按连接后实际重叠分账。NPZ 按本槽真实 ViewLayer、帧和原捕获核绑定，跨臂逐项核像素与归属。三个定向反例分别拦截宿主出交换窗、宿主晚于外层解析和图像跨槽错绑。两臂经实际入口到 Blender 启动边界、五项目录、非法参数拒绝、合法请求恢复和 EOF 验证，预飞合计零 Blender。[捕获控制](controls.py) · [实际评分器](live_checks.py)

## 真实 Blender 对照

同一 Blender 程序和两份比特一致的 Yanyite 只读副本。两臂均依序执行上区无图、下区无图、上区首次有图、同图热读。宿主资源均为 **2、0、0、0**，整场归一均为 **1、0、0、0**，独立准备均为 **1、1、0、0**。热 TCP 命令 1,320→1,271 B，热响应均 3,123 B，首个响应均 3,318,955 B。两区源三角／点为 311／184 和 331／192，隐藏 Cube 的 12 个整件三角参与测距。两臂同为 **0.370117193892 m** 和 **0.435546882075 m**，世界 +Z，最近点对和源映射一致。

各槽首次有图实构造一次，热读复用。MCP 回包提供同槽原图路径，进程关闭后可读。两臂 PNG 均为 16,975 B，原图 SHA-256 `1c2ed6d23fdd8c92bedd7d94a19ebe86cebdebc1ef9d5e9968191131f9d63837`，上区 49,480 个选区像素与 116 个有样本源三角。NPZ 的 14 个非实例字段相等，`display_identity` 与 `image_scope_identity` 分别验证各自的 ViewLayer 和真实绑定。两槽初末原生、求值、姿态、显示、文件及所有进程和管道关闭均通过。
