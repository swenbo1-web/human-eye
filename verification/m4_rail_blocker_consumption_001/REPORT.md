## 实际证据

- 封存的 21 对象、148 顶点和 184 三角中，独立求得两根导轨、四个端面。M17、M18 的 +X 端面都仅在 SCENE 几何完整。旧全场 SCENE 实测各为 11／6 和 10／3 个表面／对比边界像素，均未达 16／4 门槛。 [独立真值](truth/CURRENT_TRUTH.json)
- 实际局部 SCENE 原图中，M17 的 +X 端为 **91,559／542**，M18 为 **91,559／271**。两臂两个局部原图及其 NPZ 分别逐字节一致，原始 MCP 图块各含两张局部图和一张全场图。六组固定 CLI 预算重放完整保留正文和 PNG，即每臂三个头长度各走两级限制。
- 两个 −X 端的唯一前向 LEFT 均有正面积遮挡。A 的普通工具对当前求值源独立算出有效挡片。B 的首包直接给两端当前 **M12／三角 10**，与现有实际相机、对象与实例绑定吻合。目标端面投影重叠对 M17 为 **1/4 m²**，对 M18 为 **2/11 m²**。这是存在性证据，其他合法遮挡片也保留在独立真值中。
- 两臂各启动一个 Blender，执行一次 brief 和一次普通求证，各构三帧。源文件、独立副本求值与初末指纹核验通过。产品、资产构建、替补、Google／付费 API 消耗均为零。

## 验收工具故障

消费者传输收据包含 `TX_bytes`、`RX_bytes` 和 `RX_sha256`。冻结核验代码在确认客户端、转发层、宿主三处原 TX 字节一致后，又试图从该收据读取 `TX_sha256`。两次审核都抛出同一错误。离线审阅唯一的兼容处理是从封存 `TX.bin` 直接计算摘要。原 `FROZEN.json`、两份原失败回执和正式准入全部按首次结果保留。原运行包保存在本机，由索引绑定每个文件及 ZIP 的 SHA-256。 [QA 原回执](qualification/QA_REVIEW.json) · [QB 原回执](qualification/QB_REVIEW.json)
