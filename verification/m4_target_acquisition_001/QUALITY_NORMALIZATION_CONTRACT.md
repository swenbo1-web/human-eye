# 目标采集 A/B 质量比较合同

本批比较新目标功能的全量采集 A 与选择性采集 B。质量判断在各槽当前来源校验完成后进行。离线工具只读取已保存材料，不创建图片或执行观察。

本批实际主输入在 A 资格阶段被独立核定为 `not_realized`。B、正式矩阵和其他控制均未运行。本文件保留已准备的比较合同，不签发后续执行授权。

## 来源及对象对应

- 每槽先将安装来源 `source_sha256` 与该槽冻结的 A 或 B 来源核对，并检查实际 loaded host SHA。A 与 B 可以使用不同的源码摘要。
- 原始 capture 的 document epoch、对象运行实例、对象顺序必须与本槽结果 binding 一致。当前图片的 view、几何、相机、owner 和源面映射都绑定该槽。
- 每个 frozen asset 对象登记唯一 `asset_key`、原对象序号、稳定 `object_id` 和名称、完整世界顶点、原局部三角面顺序。逐项比较实际 capture 后才允许映射。
- fresh session 的运行实例和 document epoch 在各槽内有效，跨槽不要求数值相同。不能只靠同名归并，不能对顶点或面排序来掩盖变化。
- B 中保留对象必须是冻结场景原顺序的严格子序列。目标必须存在。未采集对象没有生成几何事实或虚构面编号。

## 图像及 owner

- 每个实际数组文件先验证外部登记的文件 SHA、帧自身 SHA 和元数据绑定，再加载保存数组。RGB、depth 逐元素比较，背景保持原有无穷深度。
- `owners` 按本槽 mesh 顺序解释。`triangle_ids` 按本槽三角 offsets 解释，前景像素必须同时落在获胜对象的局部三角范围。
- 通过本槽验证后，将 owner 映射为冻结资产原对象序号，将 triangle ID 映射为资产原三角 offsets 加局部面号。背景继续为 -1。
- 保留源面原顺序，等深 winner 继续服从原对象顺序和原局部面顺序。不能通过几何排序重新选择相同位置的面。
- RGB、depth、归一 owner 和归一 triangle ID 应一致。不同 scope 的映射 SHA 可不同，但每份都要先通过自己的来源验证。差异保留像素计数及首个坐标，不能在测后提高容差。
- 生产早停保留原行为，只比较实际同序请求产生的帧。A/B 选视顺序或帧数量不同应报告质量差异，不能只取共有帧。

## 完整目标事实

- 比较目标全部 region、源面集合、六方向 classification、选视顺序、coverage、readability、完整见证和全部 unknown 原因。不得只选成功 region。
- 目标源面划分覆盖全部实际目标局部面，supported 与 unsupported 无重叠。非目标仅作遮挡，不能混入目标分母。
- 固定几何意义保留数值与字符串原值。允许变化的本槽实例、原文件路径、图片引用和 source/geometry binding 先核本槽关系，再明确映射为稳定标识。
- 完整采集与子集采集的对象处置清单和计数另存审计。该 scope 差异不能吞掉目标的新增 unknown、额外声称或缺面。
- actual include_image=false 应保留 prediction-only 状态，不能写成已取得图像见证。
- 当前 adapter 适配实际 brief-v5、原始 capture、actual observe audit 六方向分类及保存缓冲。主输入 A 已完成来源和当前检查范围的接线，B 及跨槽比较保留未运行。

## 独立数值依据

目标相机以真实目标世界点确定共同中心和六方向 XY span。全场可靠粗界及未知粗界对象的必要细采只参与保守深度，A/B 共用同一生成函数。

筛选 oracle 用有理数计算世界 AABB 八角经冻结 view 和 projection 两段仿射的极值，同时检查生产外包覆盖实际 binary64 乘加误差。视窗为闭区间。只有六个视窗分别具有严格分离轴才能排除，触边或未知保留。跨视窗大三角无需任何顶点落在窗内，仍须保留。

独立解析遮挡例覆盖近挡板、侧后几何、非矩形遮挡物、同对象不同面片互遮挡、unsupported 目标及等深顺序。它们给出冻结的解析答案。只有保存的实际产品证据与这些答案对上，才计对应产品语义通过。数值 helper 通过本身不替代图像验收。

## 执行预算

离线数值和保存数组比较均不消耗 raster。根独占 Blender、raster 和完整资格调度，累计启动上限 24，资格及修复 48，正式 72，总 120。离线工具不重跑缺失槽、不调用原 probe、不生成替代帧。
