# M6-036-POST032-PROFILE

**决议 `insufficient_evidence`。** 三类普通入口的七条业务回执全部通过真值和来源核验，追加的一对 D48 基线／诊断槽共四条业务回执，事实和计数一致。D48 可辨认的重复目标准备即使完全删除，实测毛额上限也只有 **62.601 ms（冷窗 1.36%）**。最大的剩余耗时是精确树遍历整段，其中可删除的子段还无法归因。Yanyite 同代换盒证实重新筛选，现有遥测只给出包含排队和传输的宿主整段。本批没有可移交的优化项。

## 现场资格和真值

未插桩基线为 `6c93f2375d1073b33e721a168f1fcf610ac6dbdc`、私有 `9.7.2+b32g`。从固定 wheel 到在用安装逐文件核对了 143 源，源码集合 SHA-256 为 `0f9e6336ec54adf9e7b9a5379b02d2c2cab9f6d1f734138c3fde29e08ccee241`。实际解释器和 launcher 回报同一身份，业务后再次核对安装字节。五个测量槽均用独占副本、普通 Blender 5.2 GUI、原 add-on 和主线程命令队列，通过私有回环连接普通 stdio。每个槽正常停止 add-on、回收 Blender 和产品进程并释放监听端口。原 add-on SHA-256 为 `c836e1e7f9a7177e0101abeb9b34d80103e194dcdec8d086deb0bd9251451767`。

- **D48** 的真实目录为 48 件，目标是 `Target`。独立有理证明覆盖 47 个候选，最近对象唯一为 `Peer_000`，正确距离约 0.0030000059049562493 m。发布距离、证据、覆盖及空 unresolved 与固定 b32g 原件逐项相同。几何 oracle 提供窄区间和唯一对象，规范面证据另外与历史发布回执比较。归档世界坐标求和次序使 25 个近邻的少量坐标相差不超过 2.776×10⁻¹⁷ m，核验改为使用逐位相同的本地顶点、对象矩阵和三角顺序重算现场世界坐标，见各槽 `INPUT.json`。
- **Yanyite** 使用同字节 YB 归档重新绑定缺失的 B1 原绝对位置。测量时在同一 Scene／ViewLayer、frame 1、subframe 0 和实例／资源代，Cube 保持隐藏。高盒、高盒、低盒通过原版 `--source-region-measurement` 公开无图单区入口。高／低为 262／174 个原三角，距离分别为 0.14501953294680436／0.40625000327621974 m，规范原生面为 `[49114,0]`／`[46767,0]`。独立完整闭盒证明同时核对距离、点、面归属及原顺序。宿主主对象含 53,264 个原三角，送入几何求解的合计上限仍为 4,096 面。
- **G60_D12** 保持旧 12 件夹具的真实任务请求。闭壳关系 `separated` 与表面接近事实均与原回执及独立真值对应。冷查实际执行一次闭壳和一次表面求解。表面端沿用同一准备和树，本身新增建树为 0，但访问 399 个节点对并有 168 次窄相，未走线性路径。暖查的两项都由结果缓存承担。

独立 oracle 离线合计复核了 199 对既有证书及 49 个独立闭棱柱身份，运行 1.656 s，含历史数值编辑对照。没有可用的合格已保存 D48 编辑副本。三类新槽都走真实入口，离线 QA 和历史回放独立列账。历史 b32g D48 日志约 4.354 s 的冷端计时和历史 035 单区宿主拆分仅供追溯。

- P 冷端 47 对均以同一个原生 Target 作为左侧，使用同一精确原点和 dyadic 指数 55。双侧准入 21.622 ms、整数框架与三角准备 82.394 ms、建树 21.008 ms，合计 125.024 ms。目标侧四项中保留首次 1.208 ms 后的 46 次重复毛额为 62.601 ms。任何资源验证、缓存键、保留数据和失效管理还需扣成本。该上限低于冻结最小辨识量 150 ms，即使取双侧准备总时也远低于重载整窗 20% 的门。
- 树遍历含叶循环、窄相、平面和投影，共 4304.240 ms，占 P 冷窗 93.27%。这并未区分严格堆尾、节点开销与必要精算。用归档有理世界坐标、仅取实际三角引用顶点重算紧对象界，47 个候选对 Target 的三轴间隙都为 0。即使已有正确最近距，对象级 AABB 也只能严格排除 0／47。现有工作计数不能换算出树尾可节省的时间。
- Yanyite 的完整成员枚举仍在窄路径内执行；实测未把它与准备／求解区分。闭盒索引、规范见证缩减、树剪枝都未获得能扣成本的净上限。G60 已有共享和暖命中，未形成额外的重复准备候选。

## 保留原件与未运行项

第一次窗口检查把已完成且暂未加载的 M4 会话误判为占用，改用明确 inactive／completed 加实际进程检查。随后三格在业务前分别遇到一个归档浮点求和顺序差异和两个审计字段解析错误，原件保留。唯一的主业务序列也因同一审计字段的错误读取在顶层标为失败。原几何、回包、审计与子进程收据完整，修复后对原件离线关联通过，业务没有重发。最终确认五个有效槽的进程和监听均正常退出。

D48 编辑／恢复、连续扫描、非凸闭壳、Yanyite 原生细分探针、第二次扰动配对及 037 均未运行。未新增模型消费、训练、付费、部署或产品／Hook 写入。密封索引列出全部运行原件的字节和摘要。

## 独立复核与公开范围

复核者对照固定交付的 27 个文件和全部 719 个密封原件（34,318,208 B）的摘要，核对主序列七条实际回执、补充 D48 配对、原始时间窗及扰动门。主序列的原始关联错误仍计入记录。复核使用封存现场原件，本次复核未启动新 Blender。

62.601 ms 是一次诊断运行中重复目标准备的乐观毛额，占该次诊断冷窗的 1.36%。它低于本次扰动合同要辨识的 150 ms，无法作为可重复的提速或跨任务估计。暖端 A/P 都没有进入探针内核，超门限记录表明这对完整窗无法支持暖端归因。结论保持 insufficient_evidence，无待接入算法。
