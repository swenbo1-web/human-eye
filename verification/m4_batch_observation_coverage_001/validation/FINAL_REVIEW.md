# 离线覆盖与推进条件复核

本次只读复核支持主会的收口判断。固定输入下，两阶段薄投影能交付所选必要字段，当前公平对照尚未给出直接产品化的增量收益依据。保留原型与结果，暂停直接接入和扩大接口，符合本批冻结推进条件。已有证据仍保留一个可验证的结构机会，即把同一选择性捕获内的几何与已有关系一起按需交付。

本次读取已保存结果与源码，未重新执行验收、性能测量、产品、Blender 或模型。本文仅新增本审查文件。

## 唯一一次简化

`prototype/draft.py` 到 `prototype/final.py` 只删除目录中正常分支与缺失分支的 `center` 赋值，并同步模块说明。`selected_observation` 和 CLI main 保持相同 AST。中心由同一 AABB 派生，原 AABB、source、单位、几何和关系字段继续交付。

四个 fixture 的保存响应均满足删除 draft 目录 center 后与 final 相等。base 两响应由 14998 B 降至 13174 B，中位投影加编码耗时由 367.1 微秒降至 336.6 微秒，单次额外 traced peak 由 42718 B 降至 38430 B。这是固定原型内部的简化结果。四个实际捕获对象的拓扑合同纠错在所有 lane 共用输入中完成，没有被算作这次简化收益。

## 公平原生对照

两个实现使用相同保存几何、原关系记录、字段选择、源绑定、精度和紧凑编码。native 允许保留输入、建立索引并批量投影，输入读取与关系计算在两侧均位于计时范围外。独立源核验先由原始文件确定期望值，候选输出没有充当几何或关系真值。

各 fixture 的两个 final/native 响应逐字节相同。固定 12 个独立 worker 每个保留一次 warmup、21 次计时及一次独立 tracemalloc 投影，原始样本与退出记录齐全。native 的本次中位投影加编码耗时均较低，final 的 traced peak 各低约 1.8 KiB，当前资源表现包含具体取舍。

计时只覆盖两次投影及两次 UTF-8 编码。Windows peak 是整个 worker 至取样时刻的 lifetime 工作集峰值，包含解释器、导入、输入、warmup、计时与 tracing。其跨 fixture 波动不支持普遍内存胜负。所有样本来自本次冻结离线输入，不能据此推导任务时间、模型代码、token、费用或生产负载表现。

共同供给既有关系限定了这张成本表的含义。它刻画事实已经存在之后的交付成本，实际 native-only 取得相同固体关系及距离的成本仍在本表范围外。当前对照没有证明薄投影的数据传输优势，也没有评价既有关系求解器的整体价值。

## 两阶段与实际宿主

主请求只输出两个对象的几何，三对关系的底层对象并集为四个。当前 `capture_task_scene` 的 1..4 selector 合同可容纳这个并集，实际捕获资源已包含所需顶点、变换、单位和三角片。字段层面存在一次选定捕获同时供应形状与关系的接点。

第一阶段是全场目录，第二阶段是调用方明确选择后的几何与关系。两个逻辑响应已经离线实现。实际 host 调用数仍是计划，当前 host 的全场捕获会读取完整求值几何，模型面前目录变小并不会自动消除这份内部传输与校验成本。跨阶段 generation、一致选择、ReadContext 归一化和常驻资源的实际复用都未实测。代码中的对应接点为 `blender_host.py` 的 `capture_scene`、`capture_task_scene`，以及 `live_service.py` 的 `_overview`、`_observe_task` 和 `read_context.py` 的 `activate/normalized/result`。

主请求已预先固定选择，不验证模型能从目录自行识别目标或一次提出充分请求。八对象 optional union 的离线字段投影通过，但现选择性宿主上限仍是四。一次全场回退、拆分读取或扩大选择合同都会带来独立实现和成本，现有结果没有将它们计成免费能力。

## 当前可以保留的结构机会

- 同一选定捕获内的目标与探杆几何，可以和三对已有关系一起按字段交付，避免已取得数据在接口间分散。
- 普通目录保留完整 AABB，可供应中心及有限位置算术。中心字段简化已给出可重放的内部改善。
- 真实三角拓扑与原三角片顺序能支持形态复核和局部证据定位，原始顶点云和坐标层级的观察缺口得到明确表达。
- 可选解释所用额外对象与当前必要集合已分开登记，调用方能控制几何载荷。

这些机会也可由合理 native 批量代码实现。产品入口可能减少模型临时编写和维护这类代码的工作，但本批没有实际模型消费记录。源绑定、字段一致性与复用接点构成接口设计依据，当前证据尚未量化它们相对公平 native 的任务收益。

## 推进判定

当前可以接受有限离线覆盖结论和唯一简化结果。两逻辑响应有可落地的源码接点，主请求符合既有选定对象规模。当前产品接入依据仍缺实际两阶段调用、当前源绑定与消费者采用的证据，公平交付对照也未显示新增字节优势。

主会拟定的“覆盖接口可成立，当前产品推进条件证据不足，暂缓直接接入或扩写”与冻结计划一致。未来如另批继续，应围绕已保留的一个结构机会回答实际调用或代码负担是否减少，并完整记录宿主获取和关系成本。现有几十微秒投影差异无需被提升成新的产品硬门槛，继续优化微基准也不能替代缺失的整条链证据。

本批的零新产品进程、零 Blender、零模型与零图片是执行范围记录。它们没有参与收益计算。
