我在控制器中增加了 `RESULT.process_id == Popen.pid` 的假设。实测启动句柄 PID 为 23456，结果及全部 TRACE 的实际 Python PID 为 20368。目录绑定一致，结果时界位于本次启动和退出之间，六张图像的字节与既有固定图像匹配。

本机 venv 的 `pyvenv.cfg` 指向基础 Python 3.12.14，本地 `Lib/venv/__init__.py` 第 282–301 行说明 Windows 会使用 venvlauncher 副本。venv 入口的版本资源 OriginalFilename 为 py.exe，其字节及基础解释器摘要另存于 `PID_BINDING_DIAGNOSIS.json`。这些材料支持“启动器与实际解释器使用不同 PID”的解释。本次没有记录现场父子进程关系，这个绑定缺口仍需解决。

这条 PID 相等校验由我引入，静态审查漏掉了 Windows venv 启动器这一实际条件。首个 A 的渲染和数据回读成功已保留在原件中，正式准入结果继续按冻结条件记录失败。
