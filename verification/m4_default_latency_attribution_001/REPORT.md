## 执行与完整性

每会话有一个 cold 和一个单列 warmup，profile 均为 OFF。随后十组相同业务请求配对，ON/OFF 两种先后各五组。前两会话从 ON→OFF 开始，后两会话从 OFF→ON 开始。每会话十个 ON 暖请求、十个 OFF 暖请求。

总计 88 次业务调用、40 个暖配对、92 个 worker RPC 和 104 个产品 stdio 消息。worker 的 1..22 序号绑定业务请求，第 23 个为 OFF 关闭。四条 metadata 消息各会话产生零 Blender RPC。启动数为四，失败会话、替换和追加样本均为零。

相同会话内的事实、捕获代及来源绑定逐项一致。cold 完成原有四次网格求值、三角化及宿主世界准备，归一化一次，三对闭体及表面求解。后续 warmup 和暖请求缓存命中，已发出的三项内核计数、网格准备与归一化计数均为零。ON 的捕获 callback 计数可见，OFF 的 callback 字段明确为 null/not_collected。bpy C 方法名称不可见的观测限制继续保留。

四个实际产品 PID 为 42392、31612、21848、14060，均经原保留句柄确认退出、exit0 且句柄关闭。四个 Blender 实例正常返回 closed、exit0、未 poison，场景指纹及源文件保护通过。保存的图片和 render 事件核验通过。原期限内完成全部退出。

## 实际成本和计时边界

入口程序批次墙钟为 11.9622809 秒，包含冻结提交核验 0.8893355 秒和本次执行前文件核验 0.0683031 秒。四会话墙钟合计 10.8087924 秒。更早的只读准备校验另有记录。这些程序范围排除了分析设计、源码编辑、解释器 import 和最终结果发布尾部。

四会话的 native startup 合计 2.6394 秒，metadata 为 3.0958 秒，business loop 为 3.9450 秒，产品关闭为 0.4111 秒，native 关闭为 0.6269 秒。逐请求即时核验合计 0.4924 秒，已包含在 business loop 内。完整阶段、字节与生命周期峰值 RSS 见分析报告。

Peer receipt 的 elapsed 截止于最后回执/RPC 日志发布前，外层 entry 包含该发布，后续核验另计且纳入会话墙钟。新的 before_probe 包含安装和状态检查，after_probe 包含恢复检查，profile_scope 包含状态建立及 before 采样。这些区间相互重叠。

ON 使用真实计数字典，OFF 使用 null，发布内容因而不同。ON−OFF 表达本 QA 模式链的实际控制差异。callback 独占成本、无 QA 的生产延时、worker OS 峰值和单次分配峰值尚未测得。产品 RSS 是进程生命周期高水位。

## 分析脚本修正与复核范围

冻结分析器 `ce877249…` 首次离线读取在 warmup 上因 `pair_calls` 缺失报 KeyError。其源代码、错误和部分检查保存在 analysis/run_01，冻结源码及 31 项 pin 保持原字节。

对两套实际安装的来源核对确认，缓存命中仅发出三项初始化内核计数及 result_cache_hit，pair_calls/rank_calls 由冷态实际计算路径追加。派生脚本只修正这一读取合同，暖态直接检查三项必需计数，未发出的额外字段标记 not_emitted_on_cache_hit。冷态五项检查及既定分析规则保持。九条纯 metadata 回归覆盖真实窄结构和缺失、非零、缓存未命中及新增 hash 的拒绝。

修正后的保存记录分析通过 1502 条检查，失败为零。该数字是记录断言数量，实际实验覆盖仍为一个资产、四会话。派生差异、来源片段与原错误均保留，性能矩阵没有重跑。

独立保存材料复核通过 1581 条检查，原始 wire、事实、捕获绑定、计数与退出证明对应。首轮独立解析对图片列表、Windows 文本落盘换行及暖诊断字段的预期有误，首份错误报告保留。SCRIPT/stdout/stderr 的逻辑文本摘要依据明确的 LF→CRLF 存储关系核对，源码、安装与 wire 继续按原始字节核对。该复核同样没有新增业务请求。

新增模型消费者、图片、安装、Google/API 及付费调用均为零。Agent Learning 自身绑定缺失，本批依照管理员允许的本地工作单记录。完成证据提交后交管理员独立复核，本次归因到此结束。
