# 两眼预算下的遮挡绕看独立复核

在两次真实冷 Blender 会话中，基线与候选各执行六次公开观察。目标和参照由请求指定，最近源面及相机由插件选择。两个镜像开口的有效取证率从 0/2 升至 2/2，每题仍实绘两帧。阈值沿用产品原有的 16 个当前目标源面像素。

四题各自的 A/B 首张 PNG 字节完全相同。按当前有序网格的面偏移、对象索引和有限深度，从原 NPZ 复算全部目标像素；解码 PNG 与同帧 RGB 一致。另从相机矩阵逆投影像素中心，与实际世界坐标三角相交，独立核验固定网格、命中的目标样本和公开像素的最近表面及深度。两份原工具回包中的图块均匹配本槽磁盘文件。两臂两题的最近源面均为 0，距离均为 1/4 米、沿 −Z，原报的两端点各自落在当前对应三角上。

对封存夹具每个目标面取 15 个有理重心坐标点。两道镜像题默认方向的射线均先遇前壁，面法线均遇顶板，朝开口的斜向 15/15 畅通，反侧 15/15 遇顶板。两臂实际总计各 7 次构图。同代重读的已交付图仍能按原字节读取；重读及无图请求均零新构图、零视角探测。

## 选向成本与适用范围

候选只在 SCENE 实图低于阈值后比较原法线和环绕法线的八个 45° 侧偏方向，每方向用 8×8 个稀疏采样位置预测目标面能见度。稀疏票用来选相机，最终计数来自实绘。朝 +X 最高 19 票，朝 −X 最高 20 票，对应两次选向各花 33.43、27.34 ms。封闭对照 9 个方向均是零票，沿原法线完成第二帧并返回未知。超过 16,384 个参与显示的三角或 65,536 个总顶点会走原纠正路径。

两镜像题从服务开始至候选发布首张达标图分别为 401.24、363.18 ms。整个调用往返分别由 562.54、460.45 ms 变为 421.53、380.23 ms。每臂只有一次冷宿主，每题每臂一次调用；基线在预算内没有达标图，无法给出同质量首图提速。

## 独立的旋转检查

闭槽后用相同已装产品与封存几何，在离线 MCP 中将整套几何绕 Z 轴统一转 90° 和 22.5°，每种角度均测两道开口。基线四例都为 0／0。候选在 90° 的两例均为 0／76,373，在 22.5° 的两例分别为 0／43,148 和 0／61,345。每张实际生成的图都另核像素来源。其中一轮准备使用不符合宿主协议格式的离线文档标识，入口按预期拒绝；改用各自派生几何的完整摘要后执行上述两臂。四例共用原夹具的几何结构，作为旋转检查单列。

## 可追溯性

基线 ad35b150、候选 120b1e62，各 146 个 Python 运行源与 Git 对象、wheel 及隔离安装逐件一致。候选直接承接基线，只改 observation_focus.py。521 个归档成员同磁盘原件逐字节核对，CRC、长度及 SHA-256 通过。ZIP SHA-256 为 f24aaa5073b0f9bbbf2e26b2be4a97b09113847cb688bb0af60a9544b180e48d。

原基线评分器强索引零目标像素回包中可省略的 sampled_pixel，产生 KeyError。原失败保留。同一批已关闭的 A/B 证据另按公开协议和真实图像复核，无现场重跑。用户桌面仍使用原安装。本批结束，未测试模型消费或整题时间。 [现场报告](REPORT.md)
