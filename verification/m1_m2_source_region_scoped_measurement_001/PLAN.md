# M1/M2 选区量测 MCP 可选入口

选区冷读和同代复用已通过真实宿主工程对照。以 `ff0105db` 为基线，用一个隔离候选让现有 `human_eye_scene_observe` 在明确启用的证据端点接收独立选区量测模式 `source_region_measurement`。由实际工具声明公开这一模式及适用条件。原生标准工具目录、旧 `source_region` 各模式/详情级别及图片引用沿旧合同，现有默认和共享配置保持。

## 输入和交付

- 仅明确世界闭盒、两个唯一且不同的对象、有序选区到参照整件、单项 `surface_proximity` 与 `include_image=false`。在同一工具内留原有选区观察。新模式使用单独验证，复用已验私有求解及主线程当前绑定。旧 `region_ref`、原始面列表、带图、非支持事实或无法确认当前几何按该模式的明确原因拒绝。
- 向调用方交付独立量测事实。包含当前选区及两个对象、世界单位与方向、距离、两个实际最近点、当前两侧源面及区域范围。此模式的少字段表述保同一事实，详情值若允许，按声明保持量测证据。图像、全文映射和旧引用继续由原入口交付。完整场景及私有数据保有既有硬隔离。保留内部原双端线包与数值证据供核验。
- 缓存确认与失效继续按已验宿主合同，所有输入包括是否无图及所需事实先校验，拒绝路径记录零几何派发。可恢复的宿主不支持/缺失按公开错误报告并保现有普通入口。

## 端点及真实宿主验证

A 用现有 `ff0105db` 的旧公开无图入口，B 用从它派生的同工具新显式模式。同题统一核实际选区、量值、方向、最近点与两侧原源面。两资产各臂首次、同区复读、换区 12 次，在冻结前以实际安装、公开 tools/list/tools/call、stdio、本机宿主桥、同一正式调度与核验完成独立冷回环。核工具 schema 是否只在候选启用端点增加模式。候选默认关闭、正常旧 brief/full、旧 ref 跨到图片、普通和其他任务的真实兼容在正式冻结前用原件复核。反例覆盖旧/错 scope、代际、错源身份、参数、同名、失效缓存和错绑定。

实际冷入口到预约前的预飞通过后，正式装配、Yanyite 各 A/B 一个冷隔离 Blender。沿 709d7274 原资产和三调用顺序记录精确源、宿主及 MCP 双向线包、启动源码、首次及热读、调用方正文、宿主选择量、精确求解、完整窗口和内存。当前选区冷数据量应保持此前规模，同输入热确认和换区按原机制分别核验。只报已观察到的结果。正式模型自然采用、token 和整题收益另以真实消费者验证。
