## 验收器限制

- `execute.py` 没有对所有直接阶段调用强制验证完整的前置阶段 outer 来源链。实际五阶段记录的顺序和来源已逐项核对。
- legacy 结果缺少显式 `passed` 和预期数量门，outer 默认通过。本批实际五行数量已独立核对为 6、0、0、0、0。
- engineering 的直接入口允许选择本 namespace 内其他预算目录。实际四条链和全部 8 个 intent 均绑定唯一固定目录。

上述限制没有影响本批已执行证据，当前验收器的适用范围是有限单 controller 流程。一般并发或对抗调用的强制准入能力尚未验证。

复核者参与了固定输入与独立证明编写，发现器和工程执行器由其他 agent 编写。管理员独立复审另行进行。RSS、模型消费收益及域外拓扑能力未在本批测得。

可重放的复核脚本只读既有 JSON、PNG、NPZ 和源字节，未导入候选算法、工程执行器或光栅器。首次回读误把 pretty-printed JSON 流当物理逐行 JSON，修正及失败原文摘要保存在 `READBACK_ADJUSTMENT.json`，原始执行记录和冻结源均未改动。

最终脚本要求显式 `--output` 指向 review 下的新文件，采用 exclusive create，已有结果不会被复放覆盖。最终版本已实际生成 `INDEPENDENT_EVIDENCE_REPLAY.json`，1069 项通过、0 项失败。
