# M6 六类异常的联合处理与验收

2026-11-14。用户确认六类专家方向，并要求处理耦合，防止多类问题漏判和引擎出错。本文件是后续实现与验收要求，当前没有新增运行源码或训练模型。

## 1. 能力分类与当前边界

六类能力为：局部形状、绑定蒙皮、姿态关节、接触穿插、场景空间关系、时间连续性。它们是可共存的任务标签，不是六选一分类，也不预定六个独立网络。

当前 `arm_twist_expert.py` 是指定截面的有限诊断；`arm_twist_correction.py` 是有限三骨域的几何预览，其 `not_checked` 明确包含 `outside_patch_objects`、`volume`、`animation_winding` 等。它的 candidate 或 no_op 只说明本任务内的截面目标，不能被聚合为整个角色或场景无异常。`arm_twist_source.py` 已复用来源事务、场景状态版本及静态准备；后续应复用这些信息和既有 M5 执行/反馈循环。

本设计增加专家之间共享的信息和组合验收，不创建第二调度器、独立审批服务或每次调用六套完整检查。

## 2. 发现异常：保留共存问题与覆盖范围

一个区域可以同时保留多个标签，例如蒙皮体积丢失、姿态不合理和穿插。观察症状、推测原因与已确认原因分别记录；没有因果证据时不把一个症状的解释当作其他问题已排除。

利用已有场景扫视及廉价几何事实产生区域/关系候选，专家读取所需上下文：

- 路由同时使用任务、可用输入、依赖关系和已观察信号；不能仅凭一个最高分标签就排除其他类别。
- 顶点拓扑相邻、共享骨骼影响、对象近邻接触、支撑/装配依赖、时间邻接分别构成关联。局部包围盒不足以表达整条骨链或跨帧影响。
- 重复发现同一问题可合并证据；同区域不同问题保留各自目标，不能因位置相同去重掉伴随异常。
- 受取数或推理预算影响而未检查的候选仍记入覆盖清单。未评估、缺输入、模型不适用、调用异常均不等于正常。
- 全局扫视漏掉的真实问题计入完整任务漏检，不能只在已成功裁出的 patch 上计算召回率。

不要求每个模型自己重扫全场景。复用 M2 的状态和已有拓扑/关系准备，按任务读取局部上下文；关系越过选区时记录外部引用及已取得的证据。

## 3. 修正方案：同一状态、共同目标、一个写入口

专家输出诊断及可选修正建议，复用既有来源/任务记录表达以下必要信息。这是逻辑字段要求，具体名称沿用接入接口，不另建一套状态账本。

| 信息 | 用途 |
| --- | --- |
| 场景/来源状态、对象与原始区域 ID、帧或时间范围 | 判断两个结果是否基于同一输入及可比较的时段 |
| 已评估类别、异常标签、证据与未评估项 | 保留多标签，并避免将缺失结果合并为通过 |
| 目标、修正变量、预测效果、读写依赖及受影响范围 | 找出冲突和候选的完整影响 |
| 结果状态、实际求值结果、执行/回读状态 | 区分模型预测、几何结果和实际执行 |

联合选择采用以下顺序：

1. 相关专家基于同一状态提出方案。需要共同修改骨骼/顶点、存在依赖影响或接触变化的方案组成一个关联组；无关联的分析可独立处理。
2. 关联组按整个任务评价候选。候选效果使用各目标的实际单位/容差及事先定义的优先级，不直接平均不同专家的未校准分数。
3. 多个独立方案同时修改一个变量时，不相加位移或先后盲执行。先在同一局部状态上求值组合效果；有明显耦合时直接联合求解这组变量。限制到真实关联的变量，不枚举全部六类组合。
4. “修好了”要求所有必达目标满足，以及任务要求保持的量在容差内。单项改善不能抵消另一必达项恶化。可接受的权衡按任务条件表达，没有共同可行解时保留冲突与已知结果。
5. 选定方案统一交现有 M5 执行/回读。专家自身不各自写场景。真实多类任务需要的执行器尚未实现时，只交付诊断和离线候选，不能冒称现有手臂入口已支持任意网格/时序修改。

状态变更后只失效受影响的准备和结论；依赖边必须包含共享骨架、求值 modifier、接触近邻及相关帧。不能仅失效直接写入的顶点，也不能继续采用旧状态的另一专家方案。新位置产生的接触候选需要重建相关近邻。

## 4. 反馈与运行错误

一次实际回读同时供各相关目标计算与记录。复查范围为实际变更传播到的区域/对象/时间片；静态未变准备继续复用。

- 一个专家失败时，保留其他独立诊断；依赖该失败结果的联合任务不能显示完成。正常、未评估、异常、冲突和执行状态分别表达。
- 验收检查结构/形状不匹配、缺少引用、不同状态版本、非有限数值及空结果，避免传播为正常分数或直接进入动作。尽量复用现有接口检查。
- 同一修正不能因回执或报告生成失败自动重做。沿用真实 committed/unknown 等执行状态，先核对实际效果。
- 反复 A 修复后 B 撤销、相同状态重复选择、任务目标无改善时，使用现有任务预算和进度判定结束该组，记录冲突；禁止用无终点的专家互调消耗预算。

这些是引擎可测试行为，不是已经实现或“永不漏判”的承诺。

## 5. 数据与验收矩阵

六类形成 15 个两两组合，建立覆盖表，记录适用条件及已测/未测。优先落实与当前实现相关的组合：形状×蒙皮、蒙皮×姿态、姿态×接触、形状×接触、空间关系×接触、接触×时间、姿态×时间。三类组合先选择实际高影响案例，如蒙皮×姿态×接触。覆盖表不等于本批立即实现所有专家。

每个要验收的组合至少区分以下现象；按具体数据固定样例与答案，不能只叠加两个合成标签：

| 对照 | 需要验证的行为 |
| --- | --- |
| 正常、仅 A、仅 B、A 与 B 共存 | 共存时不只报告最显著的一项，正常例不过度修正 |
| A 掩盖 B 或一个症状具有不同原因 | 保留依赖上下文，错误原因不能吞掉其他问题 |
| 修正 A 导致 B | 检测实际副作用，完整任务不误报成功 |
| 分别可解、组合后目标冲突 | 正确报告联合冲突，不平均分数强行通过 |
| 依赖越过 patch、共享骨架、接触对象移动 | 影响范围与失效传播正确；新接触关系重新评价 |
| 跨帧出现和消失、修复来回震荡 | 连续性和终止行为正确 |
| 一个专家缺输入/报错，或执行回执失败 | 不误报正常，不重复动作，独立分析仍可用 |

训练/测试按原始资产、绑定和派生关系归组，多标签保留；另设未在训练出现的组合，检验组合泛化。先由离线精确求值或明确的真实参考建立答案，人工偏好与程序扰动标签分开。候选排序的输入不能提前含有全部候选的最终求值答案。

报告至少列出：

- 各类别与各组合的发现召回、异常定位、误报和未评估数量；分母包含未路由及未取数的问题。
- 整项任务全部必达目标同时完成率、新引入问题数、冲突被错误判为成功数、重复动作及震荡次数。
- 每个独立资产的结果，组合最差组结果，不能仅用总体平均值掩盖缺口。
- 完整采集/准备/路由/所有专家/所有候选求值/执行反馈/重试成本；保留独立处理基线和联合候选的同任务对照。

上述引擎错误路径和冻结组合反例必须逐项关闭；单类精度不能替代组合验收。模型质量目标与成本目标在训练前按任务固定。第一版后一次有据优化仍适用，随后依据结果决定保留或停止。

## 6. 对当前 M6-REAL-DATA-001 的增量要求

保持一个真实资产、只读数据调查和原交付边界。本批只补充能支撑未来耦合处理的证据：

1. 在已有数据清单中保留同一场景/帧/来源身份、局部原始 ID、选区与组件归属、边界和可获得的关联对象信息；优先复用已导出数组，不要求新增模型或重跑完整采集。
2. 区分实际观察到的结构关系、可支持检查的类别、没有输入的类别、待验证的潜在耦合。没有骨架/动画时，不生成蒙皮或时序通过记录。
3. 对一个实际选区给出一项可执行的耦合探针建议，写清所需任务/参考和缺失字段。没有异常真值就标为待构造或待标注，不把组件数量、边界或空间相近直接当作异常。

本补充不要求发现新的真实缺陷，不改变冻结原件、搭建骨架或启动训练。实施者完成后把这些条目与本批结果一并回报；复核者再选择最小的下一项实现。
