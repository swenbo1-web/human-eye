# Thin MCP adapters for CONSUMPTION-RUN-PREP-001

Prepared only. No consumer, Blender, native/product RPC or API has been started by this helper's author. This is experiment code under verification; all131 product files stay unchanged. The bridge contains no inventory, geometry solver, target selector, task answer or example solution algorithm.

`bridge.py --kind native --cell CELL.json` registers one normal MCP tool, `execute_blender_code(code, deliver_paths?)`. The model calls a function tool through its MCP client. The adapter forwards `{"type":"execute_code","params":{"code":...}}` to the owned neutral NativeSession endpoint, using its real socket. It returns the complete original response as one text block, preserving its JSON meaning. Full bpy/Python, math, efficient scripts, aggregation and per-answer cached namespace variables remain available. The neutral host still requires original geometry at the end of each RPC. No shell/JSON forwarding protocol is delegated to the model.

`bridge.py --kind he --cell CELL.json` launches the supplied frozen `he_argv` and forwards normal MCP requests and responses. HE descriptions, schemas and result bytes are not rewritten. Host-side `enabled_tools` filtering belongs in the Codex process configuration, not this adapter; the full server-returned `tools/list` is still retained and measured. This proxy must not be used with the previous three-state fixture/profile/bootstrap.

## Controller contract

The controller creates CELL.json with `ledger_path`, `audit_root`, `deadline_perf_ns`, `endpoint.host/port`, `action_observation_threshold=8`, `max_native_rpc=128`, `max_public_text_bytes=1048576`. Root's CONSUMPTION_BUDGET_CLARIFICATION_001 supersedes the original hard8 suggestion before any consumer. More than8 actions never fails or stops a cell. The deadline is the original180-second dispatch deadline in same-machine perf_counter_ns; the controller terminates its owned process tree by that deadline. Native128 is the existing neutral helper's separate execution ceiling, not a logical-tool quota. The longer neutral host deadline remains a separate cold-chain ceiling. HE also uses he_argv and optionally he_cwd.

The controller calls `Budget.create(cell)` once; creation is exclusive and never resets an existing ledger. Both MCP adapters use this same ledger under a bounded Windows msvcrt file lock. Public API:

- `reserve_action(label)` counts each MCP tools/call, including bad arguments and fallbacks, without an action-count rejection. Initialization/list/ping are not actions; their exact frames and descriptor costs remain recorded. Model-visible public tool events are a separate controller counter, so code-mode carriers and nested MCP operations are not added together as if the same level.
- `reserve_rpc(label="HE_owned_socket") -> token` before attempting the owned-endpoint connection; `complete_rpc(token, unknown=False)` after a known terminal response. Reserving only at sendall would allow an over-budget connection to consume an extra neutral-host guard event. The native adapter reserves before create_connection; the frozen HE bootstrap reserves before its original connect_ex. Do not double-count HE RPCs at the MCP proxy. A terminal inflight token invalidates successful completion.
- `charge_public(byte_count, label)` or alias `charge_text(...)`, also available to the controller for prompt/final or observable builtin-tool text. `halt(reason)` or alias `poison(reason)` blocks later reservations. Unknown physical execution marks the shared ledger halted; no replay is attempted.
- `remaining()` supplies time remaining for socket reads, connection setup and protocol queue waits. It never renews a deadline.

`tools/list` is conservatively charged as the UTF-8 serialization of the complete returned tool descriptors before host filtering. Text blocks are charged by literal UTF-8 bytes; image base64 is not text. MCP wire bytes, original server catalogue bytes, host-filtered actual descriptors and actual provider usage are distinct layers. The proxy cannot establish a host's final schema reserialization or token cost. It never presents the old18,884-byte catalogue value as a new measurement.

Every incoming protocol frame has exact TX bytes, generated response bytes, actually published RX bytes and elapsed wall time. A generated late/over-budget response is retained separately as GENERATED_RESPONSE.bin and is not labeled as public RX. There is no payload truncation. If a limit is reached, the bridge ends instead of emitting an uncharged or late error. Errors and generated-but-unpublished payload costs remain auditable. Native socket files retain exact TX/RX and known/unknown outcome; original responses are not replaced with fixture answers.

## Optional image relay

Native `deliver_paths` may request up to1 PNG already produced by the consumer's Python. No renderer is added. CELL must supply `native_workspace`, `native_helper` and `native_helper_sha256`; the exact frozen neutral helper is hash-checked and only its existing `ImageLedger` is reused. Requested paths must resolve beneath the private workspace. The frozen common limits are `image_limits={max_images:1,max_single_pixels:589824,max_total_pixels:589824}`, `max_image_dimension=768`, `max_constructed_images=1`; these use the existing ledger's actual parameter names. Additional adapter checks enforce width and height at most768. The ledger decodes/qualifies PNGs and reserves delivery before standard MCP image blocks are published. Reservations remain unknown until independent host-public-event evidence proves delivery; this helper never asserts model receipt. This path requires the already installed Pillow dependency at real execution time. It has not been exercised with Blender, images or a consumer in this preparation stage.

HE's original PNG blocks pass through the same existing image ledger and shared Budget before publication; successful blocks and the full HE response remain byte-for-byte unchanged. Generated block count is charged before qualification; failed image admission or construction credit is not refunded. Every attempt records origin, encoded bytes, qualified rows, reservation and errors. A multi-image HE result exceeding the one-image common cap is retained as generated evidence and the whole response is withheld; there is no silent image selection, trimming, replacement or fallback. This policy may make an original image mode fail the cell, and that remains in the single batch denominator.

Full consumer Python can create unrequested PNGs or render images before the adapter sees deliver_paths. The adapters therefore enforce image-output/publication admission, not a hard generation gate. The controller must inspect original neutral worker render/new-PNG events and invalidate any observed over-construction. Complete underlying file/render access cannot be claimed. If a common image route or actual model-image capability cannot be confirmed, the root may freeze only a numeric/text engineering diagnosis. The adapters do not justify a full-product/visual-baseline comparison by themselves.

## Explicit limits

The bridge does not enforce a hard action count. Root's budget clarification removes the proposed hard8 precondition; no new gate, hook trust change or weakened native capability is needed. All model-visible event counts, MCP tools/call counts and physical RPC counts remain separate. The shared180-second absolute deadline still applies, including errors and fallbacks.

The ledger is experiment coordination, not a security boundary against full Python. Arbitrary Python can read local files, including locations outside the private asset folder. Public code parameters/results can be audited, but the helper does not prove complete underlying file-access observation or hard blindness. Any observed answer/admin/source-material access, ledger tampering, undeclared direct endpoint use or out-of-route tool use invalidates the cell; unknown access remains an explicitly non-blind diagnostic limitation. Neither hidden reasoning nor auth/key files are collected by this code.
