# Consumer access boundary for the proposed diagnostic

Automatic input should be one911-byte task prompt, common approved native tools and the current neutral runtime asset. P additionally has the unchanged production HE registration; N does not. Neither arm should automatically receive the manifest, material filenames, old diagnostics, all-task JSON, contracts, truth, recipes, expected answer code or the controller's order/arm metadata. A fresh per-answer working directory and process-scoped Codex configuration are useful to avoid accidental injection, but are not hard file isolation.

Full native Python and ordinary local tools can read files accessible to their process account. The assets and administrative materials coexist on this machine, and arbitrary code can reconstruct paths or use introspection. A hidden directory, fresh context, ephemeral run, fork_none, or `--ignore-user-config` is not an access control. This proposal is an explicitly non-blind engineering diagnostic unless an already available stronger boundary is independently verified. Do not weaken native mathematics or claim hard blinding merely to make this condition appear satisfied.

Public tool source/arguments/results and final answers must be retained. Review every public native script and common-tool command for file, process, import and network access, including dynamic path construction. Allow the live bpy scene, standard/existing mathematical libraries and files created within that answer; reject use of administrative TRUTH/ASSETS/recipes, historical full_RAW/results, condition/order maps, another cell's outputs or HE internal math/implementation as a native substitute. Legitimate general Python and native geometry computation remain available. Any observed prohibited access, answer-key disclosure, automatic HE fact injection into N, or incorrect source/asset binding invalidates the affected paired inference while retaining the cell in the original failure/availability denominator. There is no replacement answer.

Public-call inspection is an audit of visible requests, not exhaustive tracing of every file read from arbitrary Python or a guarantee against deliberate concealment. If available evidence cannot establish the chosen boundary, record it as unknown/invalid for blind or causal claims. Unobservable backend injections and model delivery limits must remain declared conditions, not inferred from launch flags. Save actual effective registration and allowed numeric usage without collecting hidden reasoning, encrypted dispatch bodies, auth/key contents or system prompts.

The root must freeze the actual common tool list before the unique run. Any built-in shell/image/network tool must consume the same action/time/text budgets as native and HE actions. Record actual image capability symmetrically; if the installed host cannot enforce or meter these conditions, report that dependency before launching any answer. A source-only prepared bridge does not prove effective consumer registration or budget enforcement at the Codex layer.
