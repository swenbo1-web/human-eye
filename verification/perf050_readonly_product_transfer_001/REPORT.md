# PERF050 只读迁移诊断

21 对象的合成装配上，原生 N1 得 5/5，插件 P1 得 4/5。两组均定位 M09 倾斜功能面，并输出整件 M09→M03 最短距离 234.375 mm、世界 +Z 和有效表面点对。P1 在第二次工具调用取得可读原图和正确整件量测，最终答复只有“上附为”，缺少原图引用或附件。同等质量通过的配对为 0/1。

## 实际运行

固定候选 `470a36f111cd5e96845569c258f464d4bbcf2824`、143 运行源 `5b2e2ff21b068936b8ab951be585272d9b871a896d7a0a882dfed020896298c7` 和原 wheel `78f9626dc30ace6523f4715512a934d1a42ddca977066a614067f3ed61586eb8`。资产为 21 对象、148 顶点、184 求值三角的合成只读装配，原件和两副本 SHA-256 均为 `f5469ae84503fdad436f2d6dd86efaa6666f1af1fb80ef9b38af15cbc1ece8ce`。

两路使用同一自然题面与普通工具，P1 加载固定候选。普通渲染和读图回包均携带经校验的本机路径和 SHA，并延续原 opaque 引用。两路在封存原件及实际本地入口离线预飞通过后，按 N1→P1 运行各一个新冷槽。独立初末比对及正常关闭均通过。正式模型 2/2、独占 Blender 2/2，产品差分、构建、额外现场资格、替补、重建资产、Google 和新增付费 API 调用均为 0。CLI 0.152.1 请求 `gpt-6.1-sol/medium/default`，两槽均出现本地模型元数据 fallback 警告。后端实际模型身份、图像 token 和账单金额无观测值。

## 原图与量测

- **N1** 第 3 调已经取得可通过的较宽 BACK 图，第 7 调收紧取景后得到最终所用原图，第 8 调核对当前归属。独立复算以全 21 对象证实第 7 调视角无遮挡、四角在画面内、源三角 0–1 可见，实测 8,904 表面和 426 对比边界像素。第 6 调用 NumPy 计算完整求值网格的 28 对三角，给出正确点对。原答直接引用第 7 调原图，闭槽后文件读和图像工具返回同一 1,931 B PNG。
- **P1** 第 1 调读目录，第 2 调主动选用 `active_observation` 并拼接整件量测。实际回包使用作用域内的 3 对象、24 三角，SCENE 为 0/0，LEFT 为 146,797 表面和 1,530 对比边界像素。原冻结评分脚本沿用了全场绘制要求，对两帧保留 `frame_complete_display_domain_unbound`。另用同一封存线包、帧和完整终态核对作用域内的对象身份、几何和像素绑定，LEFT 独立查完整装配后可证明无遮挡。第 2 调嵌套的实际 `task-query-v3` 为 `whole_objects`，两个对象各自的整件网格与独立表面点证一致。第 3 调从普通读图工具取得同一张 2,526 B 原 PNG 和本机路径，未增加构图。最终原始消息与公开文本都缺引用，因此通过最终答复闭槽复读的 P1 分母为 0/1。人工文件核对只用于证据，用户点击两组均未观察。

两路报告的点均为 M09 `(-1.9375, 0.046875, 1.015625)` → M03 `(-1.9375, 0.046875, 1.25)` m。实际表面点取证分别落在 M09 的源三角 0/1 公共边和 M03 的源三角 13。此合成场景的 M09 选区与其整件网格恰好同集，选区和整件的范围区分留给有不同表面的场景。

## 可复现的交付缺口

P1 第 2 调的真实产品简报在 `images` 列中给出 `view_name`、`image_ref`、`image_sha256`、原图块索引和 patch 绑定身份，正文缺本机路径。第 3 调才在同一 PNG 的回包中给出 `local_image_path`，CLI 确实收到。最终原答 827 B 仍只有“上附为”。候选的 `source_region` 成功简报有本机引用，模型在此题自然选择了不同的 `active_observation` 入口。两段真实线包可以独立证明首包交付和最终答复是两个检查点。一次首包路径投影可以减少技术上所需的重读，但最终原答仍要按真实采用与用户可访问的出口单独验收。
