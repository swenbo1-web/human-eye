## 已定位的消费链

三次 P 都在第一次业务调用直接选择普通 `surface_scan`。产品各返回完整 71 对、明确米制数值、覆盖全部 276 对的处置计数、零 unknown 和来源绑定。各响应 **34,754 UTF-8 字节**，业务内容在产品 stdio、owner、薄客户端 RX 与 CLI `item.completed` 中一致。

三次消费者随后都请求 `brief`。源码 `live_spatial_mcp.py` 第 702–710 行对 `surface_scan` 提前返回，brief 投影从第 750 行才开始，因此三次 brief 仍输出同样的 34,754 字节及全部明细。缓存复用有效，第二次请求没有重新执行几何 kernel，但重复大响应仍沿消费链传输。

P1 随后一次请求 23 个 task 候选，P3 同样请求并追加一次 indices 分页尝试，共三次被现有合同准确拒绝。其调用成本和错误正文完整保留。三次 P 最后均原生读取网格、重新编写求解器并全场计算，得到便于呈现的毫米短表。该流程包含重新求解、重新呈现以及消费者自行核验，现有记录无法把这些目的各自的影响分离。

原生侧也有额外工作。N1 先用 AABB 下界产生候选，再做三角精算，最后复用已算距离核对和整理。N2、N3 在完整结果之后又以同一求解器、缓存几何执行无剪枝全量遍历，验证筛选和对称性。它们的额外计算同样计入本批成本。

所有实际工具文本记录合计 N 为 **26,561 B**，P 为 **218,295 B**。薄客户端业务响应信封合计分别为 **28,031 B** 和 **234,507 B**。二者分别表示正文和含转义的 RPC 传输层长度。P 每格两次产品内部采集 stdout 共 238,007 B，第二次复用资源和测量缓存，这些内部字节没有作为模型输入字节重复计数。

## 唯一后续优化假设

下一项可检验假设是 **surface_scan 的完整任务事实紧凑投递**。复用现有响应展示路径，集中呈现全部对象对、明确单位、原始距离、覆盖计数、未知项及全局来源绑定，减少逐对重复标识和见证细节，并保持详细证据可回读、可绑定。

同原件的离线表示探针保留全部名称和未舍入米制数值后为 5,669 B。再保留一次名称到原长 ID 的字典后为 7,554 B，较原响应少约 78.264%，能恢复匹配行中的全部原对象 ID。探针逐项核对六次响应的匹配成员、原始数值和标识恢复。该大小变化仅证明现有字段存在表示压缩空间，实际 token、完整耗时和消费者行为收益尚未测量。

后续应以真实消费输入完整性、答案质量和完整任务成本检验此假设。如果完整事实被证实清晰到达模型后，重复 brief、错误分组请求和全场重算仍然存在，该假设对主要成本的解释力就会下降。具体产品合同与试验需经管理员下一阶段复核确定。
