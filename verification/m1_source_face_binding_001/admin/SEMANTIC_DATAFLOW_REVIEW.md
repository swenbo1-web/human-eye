## 实际源面数据流

| 槽 | 源面关联操作 | 几何反查 | 全见证像素重算 |
|---|---|---|---|
| A1 | tool5 从源顶点求中心/法向，再匹配 region | 发生 | tool5发生 |
| B1 | tool4 将实际 pixel source ID 转为对象局部面号，并在当前 ranges 查表 | 未发生 | tool4逐见证 mask 重算 |
| B2 | tool5 从 ranges 构造 global face→region 表，再定位两个像素 | 未发生 | tool5全图 merge 后重算 |
| A2 | tool4 用源三角形共面与朝向检查恢复 region 源面集合 | 发生 | tool4发生 |
| A3 | tool5 用源顶点共面与朝向检查恢复局部源面集合 | 发生 | tool5发生 |
| B3 | tool4用当前 ranges定位像素，tool5继续构造 source lookup | 未发生 | tool5发生并额外检查 TOP roof |

三个 B 槽均接收实际 v5 字段，并将其用于本轮任务。实际请求、执行成功回复和最终样本结果形成来源闭环。字段出现与字段采用分别核对，旧 A 没有被归一化成新字段采用。

由 center/u/v 正向生成四角属于描述展开。B1 还在范围查找后打印了底座原始顶点以核对描述，该读取与恢复 region 源面 ID 的几何反查分别记录。三个 B 槽的源面关联均通过当前 object_index 与局部 ranges 完成。

六槽仍进行了全见证像素计算。其发生事实已确认，必要性保留未测。本复核不判断完整任务成本收益。
