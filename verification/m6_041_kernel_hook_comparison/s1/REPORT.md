## 质量和绑定

每槽的安装 SHA、正式入口、真实 MCP 解释器 PID、审计 build_id、实际工具运行身份及返回单独绑定。GUI 经自有端口所有权及原版插件 ping 验证；初始几何与冻结 .blend、来源所有可见网格的矩阵、本地顶点与面序绑定，Yanyite 再核既有世界顶点快照。末次实际读回检查未授权变动；真实编辑只发生在对应 G60 副本。

独立 GUI 拥有不同文档实例。18/22 个位置的完整响应在核验 trace/build 后仍有宿主会话绑定差异，逐键记录于 AUDIT_2.json。可比较的完整业务几何、覆盖、unknown、原生 ID、方向、见证均为 22/22 相同。在相邻审计中按请求 ID、trace ID、解释器和当前场景修订绑定，选区查询的对象实例也按实际 GUI 与原生 UID 验证。未从另一个进程的随机文档令牌反推相同宿主。G60 缺失选择器两次均明确 unknown，原业务未执行；没有自动重试。G508 未知保留于实体查询原分母，两次扫描均无未知。

## 计时、恢复与原件

每次业务从客户端写入 stdio 至完整解析响应。D48 的 host.capture 为 130.5 / 154.4ms，observation.surface_nearest 为 4258.8 / 559.5ms。G60 独立 scan 的 host.capture 为 119.7 / 112.4ms，observation.surface_scan 为 3663.7 / 397.1ms。归约器计时包含其内部验证与求解；纯内核独占时间未另行插桩。COSTS.json 逐请求保留 IPC 字节、等待、解码、服务嵌套计时、实际宿主和产品 CPU/工作集及完整建连与退出收据。

包含恢复步骤共启动 21 个私有 GUI 和 21 个 MCP 进程组，所有正常结束并释放端口。所有真实业务响应共 51 个；各槽生命周期算术和 170.146s，完整序列槽合计 124.439s，所有响应业务窗合计 46.996s。业务边界采样的宿主 CPU 合计 3.21875s，MCP 产品 CPU 合计 42.53125s。记录到的逐进程生命周期工作集峰值分别为 682.60 MiB 与 89.34 MiB；整组同时峰值未测。

第一版驱动完成 5 个 G60 首响应后在读取错误的审计身份属性时报错，每个槽均按原路径回收，5 个响应全部经事后独立核验匹配原 040 几何。完整矩阵使用修订冻结 PLAN_recovery_01.json。两份 Yanyite high 首读成功后，审计落盘晚于 stdout 读回；两份原始 high 另验证独立真值。在两个新冷服务按原序高/同盒/低执行，等待审计发生于业务响应计时结束之后，6 次额外验证与等待分别约 6–18ms。FIRST_ATTEMPT_OFFLINE.json、原始 slots、slots_recovery_01 和 slots_recovery_02 全部保留。全程没有 Hook 调度、计时尾部分位或部署变更。
