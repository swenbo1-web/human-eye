# Independent parser adaptation

The first offline audit stopped at line106 with IndexError while examining a synthetic local preparation call. That call was the explicitly registered `execute_python` / `print(6*7)` control and contained only text, so it correctly had no image-delivery rows. The initial parser incorrectly assumed every preparation tool call contained an image.

The initial script is retained as `audit_cost_initial.py`. The corrected script counts image-event bytes only for tool results that actually contain images, and applies the no-Python assertion to real model calls rather than the synthetic preparation control. No author file, test denominator, metric expectation, threshold, or real call changed. This was a failed offline parser execution, not a failed model or transport experiment.

The completed first audit retained 447 passing checks and33 invalid expectations. A separate `clarify_schema.py` checks every retained mismatch against raw files and source: MCP line counters include LF; per-route RESULT lacks two fields added later to the batch record; synthetic fixture emits no actual turn.started and uses spaced JSON rather than the real CLI compact JSON. `SCHEMA_CLARIFICATION.json` records each correction. `FINAL_RESULTS.json` is the final decision; the initial checks/results are not overwritten. These format corrections do not repair or reinterpret the author's experiments.

The second clarification resolved30 but retained3 synthetic stdout-byte mismatches: Windows Python `print` appends CRLF, while that clarification still assumed LF. `finalize.py` separately confirms all3 counters equal spaced JSON plus CRLF. It explicitly distinguishes reconstruction/counter consistency from an exact raw-stdout comparison, because the experiment retains parsed/re-serialized event logs and runtime len(raw) counters, not full raw stdout. `COST_ACCEPTANCE.json` supersedes the intermediate FINAL_RESULTS decision; all earlier outputs remain intact. No real-model metric changed.
