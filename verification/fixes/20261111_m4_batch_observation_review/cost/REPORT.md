## 计量范围与合同强度

读过 `benchmark/run_measurements.py`、`prototype/final.py` 和 `validation/native_projection.py`。计时严格只包围两次投影和两次紧凑UTF-8 JSON编码；预热与固定输入解析发生在开始计时前。世界坐标已在bundle中准备好，关系事实已在两侧共同输入里。

这符合本批“同信息交付层”的限定对照，不能把它扩大成“原生现场免费获得精确关系”或“已经证明插件几何引擎无价值”。当前原生是一个可复用的普通字典批量投影器，获得与插件原型相同的顶点、面、已有关系、选择、精度和来源；不是大模型从原始Blender独立求解全部事实的完整native-only任务。

排除/未测项包括：输入加载与世界坐标准备耗时、原生或插件生成关系成本、Blender采集/三角化/传输、MCP目录和schema、真实缓存命中、模型发现目标与字段选择、模型代码生成、工具轮次、token、费用、完整任务和安装等投入。目录模型侧精简没有消除现有overview采集全场28对象416顶点的内部工作。两次逻辑响应只说明离线接口组织，不能记成两次实测宿主调用。

`MEASUREMENT_CONTRACT`与最终提交/封存摘要绑定；工作单实证固定了实现、输入、请求、manifest和runner。合同声称`frozen_before_projection_measurements=true`，但工作单不含合同或PLAN摘要，当前材料没有独立时间证明这一文档在样本前已冻结。这里确认运行源码/输入身份及其实际计量范围，**不将最终封存自动说成独立证明所有文字事前登记**。这不改变现有负收益结论，也不是重跑性能的理由。

## 按原计划判定出口

原计划要求覆盖不丢失、两响应可行、不用大几何包换轮次，并且有可复核的模型代码或数据传输减少机会；如果只是把同等原生脚本包一层，应判收益不足。根 `7286fac4` 的统一方案同样要求：有结构收益机会才接入口，质量通过不等于净收益通过，不以另开模块维持循环。

| 推进条件 | 当前证据 | 判定 |
|---|---|---|
| 有限输入与字段覆盖 | 作者674断言、4fixture；本子审核对原件，语义由其他子审核查 | 有限工程证据成立 |
| 两响应 | 原型可在目录+选定结果表达固定主请求；活体调用、模型选择与源时效未测 | 离线可行，不能写成真实消除一轮 |
| 相对同信息原生减少数据 | 4/4输出逐字节相同 | 未形成优势 |
| 相对同信息原生降低处理成本 | final中位较慢，少量Python分配优势；OS峰值不一致 | 未形成总体优势 |
| 可复核模型代码减少 | 双方均为复用函数，尚无实际schema/调用脚本/消费者计量 | 未证明 |
| 真实完整任务收益 | 本轮新增消费者0 | 未运行 |

因此应关闭**当前包装原型的产品化推进**，保留原型和账本作后续输入，不因为674通过就进入集成和再一轮模型试答，也不在现有原型继续改循环/字段刷45μs。简化次数已完成，按原停止规则收口。

这不否定“读取同一捕获已有几何而避免下一次补读”的设计位置。若后续继续该方向，应先提出一个具体、与普通原生批量包装有区别且可验证的收益机制，再决定是否新立最小任务；不能将这个潜在位置直接升级为已达推进条件。更不能从本批条件化投影对照得出所有复杂场景、类人眼算法或插件整体均无收益。
