## 建议只做这一项

新增显式单目标的有限六视图观察：请求一个对象，交付该对象现有受支持矩形区域的完整、可读图像见证及未覆盖原因。方向、512 像素、5% 边距、像素门槛和扫视选择沿现实现；不增加任意面选择、自适应相机或曲面能力。它解决目标在复杂场景中被遮挡、需要多视图取证的问题，不把距离、碰撞或最近对象等直接计算问题改造成图像题。

旧 `active_observation` 全场模式保持原义。新输入可沿现 `query.objects` selector 形式限定一个对象，但必须显式表达 target scope；具体命名由实施者遵循既有 schema 选择。它不是静默将全场扫视改为局部扫描。

## 当前代码约束

1. `active_observation_host.freeze_cameras` 不只用 XYZ 紧界。中心来自全场 XYZ 极值，每方向 span 来自全部顶点的 right/up 投影极值；`_attention_camera` 还用方向前后极值确定 eye/far。因此现 `capture_directory` 的 XYZ bbox **不能等价复现旧相机**。

3. `capture_task_scene` 只能采用户指定 1..4 对象，不处理遮挡物；直接使用会删除场景证据。可复用 `_capture(..._acquisition_context...)` 与 resident resource，按已有对象顺序采目标与保留对象。
4. 入口、`source_binding`、`_patch_scope_facts` 和 MCP brief 都强制当前完整场景合同。不是只改一行 selected capture 就能接通。
5. `ActiveObservationImages._patch_mapping` 已将非 ROI 源面初始化为 `-1`，且原始三角和对象 owner 独立保留。遮挡物可以不成为观察目标，无需重建 raster 或新增框架。

## 最小算法

在一次同步主线程读取窗口内解析目标、枚举全场对象和身份，细采目标一次。按目标真实世界顶点拟合沿原六方向的中心与 XY span。全场轻目录只提供保守对象界：已满足现静态三角来源条件者可以复用 `_acquisition_directory_source`/`_acquisition_bounds`；不满足该优化资格的普通可读对象保留详细采集，不能将其误当作场景非法或可删除。原全场明确不支持的实例等仍走已有结果。

每对象对六个**完整目标 viewport**做保守投影区间测试。只有六个视窗全部严格不相交才排除；触边、区间不可靠或未知都保留。第一版不加前后深度排除，不按“看起来不挡住目标”排除。这样位于目标后方、邻接目标边界但影响图像对比的几何也保留，能够比较整个帧，而不只比较 ROI 内部。

将保留对象按原全场 object_id 顺序详细采集；目标复用刚取得的 resident resource，不能重复 `to_mesh`/世界坐标变换。未知界对象采到的真实顶点补充全场前后界。eye/far 同时覆盖已知保守界及未知对象真实几何；不只按目标深度截断遮挡物。最终六相机必须在 full reference 与 selective candidate 中完全相同。全场数量预算先沿可取得的同源 collection 元数据核对，不能通过排除几何意外扩大既有上限；计数无法判定的来源先沿必要采集。

Blender host 是 dependency-free 模块，不能直接导入带 NumPy/Pillow 的 active adapter。固定方向的简单 plan/区间数学应放现 host 或一个最小纯函数位置；返回同一绑定的计划供外部建矩阵。投影舍入包络必须覆盖真正使用的矩阵与 raster 运算；不能把数值边界留给普通浮点 `max < min`。不需要新增调度器、协议服务或缓存。

若决定分两个 RPC 读取目标再取剩余几何，就必须解决跨窗口状态一致性，成本也增加；这不是首选最小实现。建议直接采用现 nearest/scan 一次 host 窗口的组织方式。

## 拆开任务范围与遮挡范围

`partition_regions` 只对目标对象做矩形分区；输入的对象、全部保留三角和渲染顺序保持不变。`build_index_from_parsed` 接收目标 regions，但扫描所有保留三角作为遮挡物。`face_patch_ids=-1` 继续表示非目标面没有 ROI，原始 owner 仍有效。

`patch_scope` 不应把非目标标为 unsupported 或 unknown。目标仍完整分成 supported/unsupported 源面；其他保留对象明确 `occluder_only`，不进入 coverage 分母。新 scope 至少表达目标身份、保留/排除对象数量和按视窗排除的适用范围，完整对象处置证据可放 full 结果。brief 必须真正接入新 scope，不能因旧精确字段校验失败而悄悄退化成大份 full 输出。

绑定同时包含全场目录身份/状态、selector 的实际目标实例、保留对象与原顺序、目录和相机策略摘要、细采几何身份。缓存 key 加目标和新相机策略；不能与旧全场结果或另一目标共享。删除/同名替换、姿态/几何更新、frame/scale、重连、场景切换沿现 state/资源失效机制，不新增另一套状态服务。

## 比较设计及一次追加优化

主要 A/B 应为**同目标范围、同六相机**的 A 全量细采与 B 选择性细采。A 只是这个新能力的工程参考，不等于现默认旧插件；不得把缩小目标/放大目标图像的收益归因于取数算法。A/B 都只分区目标，都使用相同全场粗界与未知对象处理确定深度。

固定一个有明确目标和外围复杂几何的已有授权夹具，再固定一个没有对象可排除的控制。先登记对象/面目标和候选，不在结果后移动外围、扩大目标、换相机或挑下一例。没有可排除工作就给出 not_actionable；不要为了通过构造更多外围物体。

建议正好两版：先实现并冻结可执行的 A“目标 scope + 同固定目标相机 + 完整采集”安装，再实现 B“同 scope/相机 + host 单窗口粗界筛选和必要几何”。B 本身就是要求的一次实质追加优化，不再为凑次数增加第三版。A 走真实公共目标入口，不使用 monkeypatch、只存在于 QA 的特殊适配或伪造采集成本。两版共享相机 plan 的轻量计算，并各自计入实际目录/目标计算成本；A 不能因拥有 full vertices 而另取更紧的 eye/far。目标二次细采/解析、重复角点投影或非目标分区若出现，作为 B 内的具体实现问题处理。不上 BVH、每视图分页或新缓存。

正确性至少核对：近处挡板、目标后方/侧边几何、跨越视窗的大三角、视窗触边、旋转非盒对象、未知/不可用界、unsupported 目标面、自遮挡和等深先后。整个 RGB 与 depth 应相等，owner/triangle_ids 需先还原为同一 host instance 与对象局部源面号再比较；子集全局编号和绑定摘要本来就会不同。保持保留对象相对顺序，才能保持等深 first winner。目标区域集合、六方向分类、完整见证、readability、unknown 原因和实际选视序列也须一致。

不要强制所有生产调用渲染六张：几何资格可检查六相机，帧等价资格在固定预算内检查所需视图；正式业务窗口仍执行当前实际选视序列，失败和额外构造全部入账。现旧全场观察、M1 源面索引及重复视图复用另做定向回归。
