414 行中有 161 个非空锚点与 253 个双 null。SCENE/BACK/LEFT 非空行分别为 68/47/46。每个非空 anchor 均是对应 ROI 的真实获胜像素，bounds 是全部可见 ROI 像素的包含式范围，整数中心距离和 row-major 同距规则完全一致。96 行存在多个同距候选，实际返回均选最早的行优先像素。

三张 PNG 解码后逐像素等于 NPZ RGB，三个 NPZ 的所有数组元信息均与帧描述匹配；新旧三张 PNG/NPZ 原始字节完全相同，RGB/depth/object-owner/patch-owner 均一致。9 个实际 MCP 图片块经 base64 解码与同源 PNG 完全一致，图像序号、view、image_ref、图片摘要、patch mapping 关联正确。默认 cold/hot 均为 v3，414 行无重复或缺项，full 保留同一像素事实。统一 top-left、零基 [x,y]、512×512 约定已交付。

## 代码与测试审查

`active_observation_images.py:146` 对共享 patch-owner 做一次分组 min/max、一次最短整数距离聚合、一次最小平面索引聚合，随后按区域数构造列表，没有逐 ROI 全帧扫描。`surface_ids` 与 `flatnonzero` 同用 C 顺序，分组索引对齐。外层受限于 64–512 方形帧，距离运算使用 int64，在当前域内不溢出。空区域跳过锚点解码；count-only 原接口保持两组计数输出。

`_pixel_rows` 将定位与可读性分别填写，可见但不满足阈值的区域不会丢失 anchor。实际反馈将同一结果写入 session，缓存复用沿已有帧路径，本轮三份 service 原件的图片/数组路径和摘要一致。

作者新合成测试直接检查带孔中心不可作为锚点、分离岛、同距次序、单像素、完全遮挡、背面可见、低对比可见及 adapter 只调用一次聚合。测试期望有实际 owned-pixel 与独立 Python `min` 核验，不仅是输出自比。对 v1/v2 历史和 v3 默认/full 的其余公共语义由世界/语义分工覆盖。
