## 独立工作与分母

从原始 `RESULTS.json` 的起止计时、`product/*/{TX,RX}.bin` 和 `RECEIPT.json`、`native/WIRE/*/{REQUEST,RESPONSE}.bin`、worker 事件及实际初始化结果重新计算。没有使用作者汇总作为计算输入；计算后与汇总逐项比较。

- 三个固定资产，27 个纯目录会话。每输入/路线三个独立应用冷会话，每会话 1 cold + 10 warm：每格冷 n=3、热 n=30；热 p95 是 nearest-rank 第29项。
- 另有9个独立两步会话，每输入/路线只有一次。不能把它们与27个目录会话混池求性能。
- 306次目录请求、9次 selected 请求，共315次业务 host RPC；36次关闭 RPC 另计，实际 wire 共351组。
- 27个实际产品 runtime 的已记录退出为0，36个 Blender 关闭回执与前后状态一致。纯目录 native 的9个会话不启动产品；两步 native 的3个会话启动旧产品。
- 独立读取1862份来源，1861份与固定Git blob核对；剩余为 INDEX 自引用。15047项机械核对通过，包括字节、请求绑定、统计等。这些不是15047个独立场景。
- 三路执行顺序与冻结计划一致；实际使用资产摘要、预实施固定 query、分析源和控制器字节一致；保存记录中无性能替补或重试。

本审第一次脚本把旧工具外层 objects 当作带 bbox 的列表，产生 KeyError；改为读取旧公开 routing.context_text 的对象范围后通过。`RUN_01.txt` 保留该审计脚本错误，`RUN_02.txt` 是成功重算记录，不属于产品性能重跑。

## 基线公平性与不可归因的部分

合理原生目录使用 evaluated 顶点 foreach_get/NumPy，直接返回相同 ID/名称/tight bbox/center；不是故意传全网格的弱基线。原生也加载同源 SceneResidency 并复用不变代；其首次源建立和Python执行包括在实际冷请求中。三个资产的全部3514顶点已有固定 oracle 对应记录，本审另核306份公开目录的范围/中心与该冻结 oracle 一致。通用 Python sum/NumPy逐位等价不从这些输入外推。

仍有两项重要测量边界：

- 三路共同 owned worker 在每次 execute_code 前后运行 `_scene_fingerprint`。其 `_scene_state`（owned_native.py:192–224）完整读取 raw vertices、edges、polygons及其他场景状态；调用处在345、358行。因此**目录分支的暖forward=0、插件三角化=0，不等于整条QA请求没有读取网格**。共同工作成本保留在计时里；本批没有拆出其独立耗时。`host_elapsed_ns` 包含QA检查，也不能称为纯目录算法时间。
- NativeSession.run（477–483）在交换结束后另做客户端资产/保护文件hash；Peer.call（43–63）则有stdio封装、记录与产品层工作，两个外层计时入口并不完全同构。原始记录可区分host事件、Peer receipt和整次调用；没有足够证据把版本差精确分摊为顶点算法、源码检查或系统调度。不能借小毫秒差声称纯算法压倒强原生。

原生同源实际函数的16项失效测试使用fake bpy通知；正式三资产矩阵只做不变热请求。原生完整变更序列的实际Blender证明尚未运行，因此不能把相同缓存机会写成全部实际失效事件均已独立验明。
