# 用户 M4 分析：任务设计与下一步方法复核

日期：2026-11-12。只读审查用户附件 `1-M4_SELECTED_GEOMETRY_TRIAL_REVIEW_ANALYSIS.md`、根 `M2_TIGHT_DIRECTORY_001_REVIEW.md`，并核对当前实施树的 task_query、surface_proximity、surface_geometry。没有启动产品、Blender、消费者、安装或新用户任务。本文件为设计建议，不是派单。

## 判断

采纳“按真实空间任务需要组织证据、减少不必要补查、分别记录交互与完整生命周期”的方向。下一批不宜直接实现附件列出的 Reference Bounds、新多边形协议或固定 1–2KB patch。当前最需要先固定一个独立任务及它实际要求的证据，并检验现有引擎是否覆盖；否则很容易把原题字段微调换成按原生表现选题。

附件的主要工程结论与已封存结果相容：同次 geometry 被自然采用、同域形状补查减少，完整净收益未过；M2 目录只有工程采集收益，尚无模型消费结果。其数值表的全面复算由同轮其他审查负责，本方法审没有将附件自述的“独立算术复核”直接当作自己的验证。

以下三个因果说法只能作为假设，不能用于先保证下一批必胜：

- “少一轮绝对不会被大回包抵消”：九格只有关联，输出信息量、脚本、模型随机性、缓存和轮数共同变化。更大的回包可以超过一轮节省，固定数据没有普适上限。相同两轮的若干格接近，也不构成仅修改 geometry 大小时的配对因果试验。
- “非轴对齐以后原生解析捷径失效”：整体旋转可逆变换到局部坐标；简单构造依旧可能有短解析解。原生也可在宿主内完成几何计算后只回短结果，不必打印全部顶点或手写 O(Fa×Fb) 双循环。
- “局部几何能稳定压到 1–2KB且保持一般任务证据完备”：字节量取决于问题所需的证明、坐标精度、对象数量和未决状态。现在没有相应跨任务数据。

## 当前引擎的实际域，必须先于复杂任务预期收益

当前 `surface_proximity.py:14–15、149–152` 中，`MAX_FACES=4096`、`MAX_TRIANGLE_PAIRS=16384`，`_admit` 在面数总和或两者乘积超限时直接返回 `surface_geometry_work_limit`。这是运行前的面数乘积门，不是先由 BVH 测得的真实相邻对数量。举例：两个各 130 三角面的对象乘积已经为 16900，高于该门。

`surface_geometry.py:9` 另有 4096 顶点/三角面的有限预算，`:226–230` 有闭壳工作/成对/射线预算；`:445–463` 的闭实体关系域是有限、连通、嵌入、可定向闭合三角壳。自交、不闭合、若干边界重合情形可能返回 unknown。由此不能把当前产品说成对任意复杂拓扑都能给通用完备认证。

附件提出两个 2000–20000 顶点、带复杂凹槽/曲面部件时，当前路径很可能先撞支持域/预算，而不是展示质量或时间优势。M2 目录能读取更大 evaluated 范围，不表示 M3 关系内核已经能精测同一规模。不能把这两个模块的域混成一个成功率。

当前 `task_query.py:57–88` 的集合接口为一个目标加最多三个候选，显式 geometry 只从原绑定对象投影；`:216–248` 才按请求生成全顶点、可选三角面。全几何不是默认输出。另一方面，`surface_geometry.py:348–366` 已会交付一对实际交叉三角形、三角索引和局部近似位置。新增“局部证据”设计应先盘点这些现成结果，避免重建同一能力。

## 怎样接受复杂任务方向而不挑有利题

选题依据应是用户希望做出的判断，例如真实装配里“哪些部件有实体穿插、哪处间隙违反规定、应检查哪两个局部位置”，不是“原生不能做什么”。复杂性可以来自凹形、非共轴件、遮挡、近邻干扰和目标歧义，但面数或旋转角本身不是有效难度或插件价值的保证。

任务/资产的选择必须在读取两路消费者答案和性能前固定。选定后保留所有结果，包括原生成功、插件 unknown，以及双方都容易答对；不能只留下插件通过而原生失败的资产。若用合成构造补足独立真值，应将其标成合成资格测试，不能称实际用户任务。原来的简单任务继续作为已封存控制，不移出汇总以提高平均收益。

合理原生须允许与插件相同的可用宿主资源和目标：批量读取、矩阵逆变换、解析计算、已安装原生空间 API、合理缓存、按需短输出；具体 API 的结果仍接受相同独立真值与容差核对。不能人为要求它输出全网格、逐点心算或重写通用内核。下一次真正的全任务原生必须全程走原生；M2 的“原生目录→旧插件 selected”仅是工程工作转移对照，不可复用成原生完整任务成绩。

目标选择、几何关系、间隙数值、局部定位、证据完整性应分别评分。任务不要求证明的细节不强迫两组长篇输出；若用户需要能定位修复位置，不能仅因关系标签正确就算完成。未知需要如实说明，并按固定任务完成标准记为未解决，不能用未知的保守性替代业务成功。

## 1–2KB 应如何使用

附件说的是单次几何增量，而非整个响应。1–2KB 可以是**一个有限局部定位的新增载荷目标**，不能先作为全域合格线；原固定包络、schema 和后续补读还需另计：

- 一次明确横向穿插可能只需对象、关系、一对来源三角形和位置，当前已有接点。
- 一对最近见证点可定位间隙，但这些点本身不证明全局最近；算法覆盖和未决候选仍要准确表达。
- 单个局部 patch 不能证明整个对象没有穿插；一个截面也不能一般性证明三维凹物体整体分离、孔道全程畅通。
- “原始多边形”也不是免费压缩：非平面或凹多边形若改用不同剖分，其空间表面可能改变。当前 evaluated 三角网格合同没有保证原始面边界可以无损替代，须按真实需求单独验证。

所以先按具体任务找最小充分事实和必要局部定位，再测序列化字节与实际消费；超出 2KB 的必要证据不应被截断或降精度来通过预算。完整来源可保留在可追溯位置，但把事实换成引用后若触发补读，该轮成本必须计入。

## 唯一下一步建议：独立任务与证据合同准备

建议下一批限定为“任务定义/来源冻结/支持域预检/独立真值准备”，暂不改产品：

1. 从实际用途选定一个新的装配空间判断任务，固定输入资产、成功条件、容差、需要定位的对象与证据；选择依据写在看到模型结果之前。另保留一个简单控制，不批量造难题搜索胜场。
2. 固定当前 fac9b437 作为可用工程基线，列明目录、已知目标精测、局部证据分别支持什么。用一次有限离线/宿主资格预检核对真实网格规模与当前域，保留所有失败，不按原生输赢换资产。
3. 用独立方法建立真值，先形成最小充分输出合同；允许合法原生捷径。将“只需 bounds”与“必须知道孔洞/截面/局部面”的信息分开，避免为已经在目录里的字段再开 Reference Bounds 入口。
4. 若当前精测因为面数乘积门、拓扑域或数值预算失败，交付一个明确的真实缺口，下一轮只选择那一种 M3 问题；不要同时扩全场候选、图片、专家模型和回包协议。若覆盖成立再准备一次有限消费者对照，不能把引擎资格预检当模型质量成绩。

本批准备的出口应是一份可复核的固定任务/来源/真值/允许原生能力/最小证据/全成本合同，或一个明确支持域失败；不是新的性能优化承诺。之后是否动 Reference Bounds、局部 patch、工具集合或实例启动，依据这份新任务的实际缺口唯一选择。

本方法审仅提出以上收敛，不启动该准备批，更不重新开启原九格或改其门槛。
