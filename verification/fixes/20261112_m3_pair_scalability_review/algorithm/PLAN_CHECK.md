# M3-SUFFICIENT-SEPARATION-001 计划只读复核

总体可执行，显式区分新空间关系与旧 embedded-shell 合同，单一支持方向、全点精确验证、失败fallback、原期限和旧失败保留均合理。无需新实验或算法分支。

测前需补清两处：

1. **支持集合与准备数据一致。** 当前 `surface_proximity._integer_frame` 只遍历 `_admit` 的 face 引用顶点；它不包含 loose/unreferenced 顶点，这些点也可能具有更细的dyadic分母。若新合同是所有实际源顶点凸包，必须从当前已绑定mesh显式检查全部顶点，精确处理其坐标，不能直接套现factor舍入或只用prepared三角坐标。另一种可行合同是全部被引用三角顶点构成的凸包，但须测前明确修改范围；不能发布“全顶点”而实际只检查引用集合。远处未参与最近的反例应至少覆盖一个未引用顶点，以防范围误述。

2. **实际新入口不要被旧请求预热掩盖。** 计划“目录→旧v1→新v2→控制”使旧v1的成功surface事实先进入pair memo；新v2可能仅验到warm路径。无需增加调用数，可改成“目录→新v2→旧v1→新控制”，让新路径首次冷启动并同时验证旧v1不被新事实覆盖；若保留原顺序，必须把实机新v2明确标为warm覆盖/成本，不能当冷链性能。

本批仍不应把新事实视为旧M3通过；根已明确保持失败。支持方向的上游距离/见证成本要计入完整窗口，下界不足以判“不达标”的边界也已在算法报告说明。

## 修订确认

已只读核对根最新计划，两条意见均关闭：

- 支持范围现明确为完整三角引用顶点集合及其凸包，不包括未引用散点或独立线段；与现 `_integer_frame` 的引用集合一致。已增加远处被引用顶点反例和未引用散点的范围反例，没有将部分集合冒称整个原网格。
- 实际序列改为目录→新v2→旧v1→新控制，同样4次业务调用，先验证新冷路径，再核旧合同保持。

另确认计划已测前加入简单穿入、完整包含两个fallback控制，各臂各5次，加上主40次共60次，检查先surface后fallback的成本转移。本次没有新增实验；可按修订计划派发。
