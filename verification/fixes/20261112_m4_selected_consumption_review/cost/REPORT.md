## 全部调用、可见字节与 token 归因

23 次模型工具调用由 CLI start/completed、owner ATTEMPT、原始请求和响应交叉匹配，未将开始/完成事件重复计数。没有失败调用被排除，也未观察到 provider retry 提示；后者不能证明底层 provider 请求次数已知。

共 **50 worker RPC**：23 次模型工具操作、9 次初始校验、9 次最终校验、9 次 close。产品 P/G 另各有 15 条 stdio 记录（每格 4 metadata + 1 relation）；这些 metadata 没有另增 worker RPC。G 比 P 少两次实际工具往返，与 N 总调用相同。机制是否自然正确替代同类补查由独立机制审判断，不能仅凭调用数推断。

`tools/list` 原始响应每格分别是 N **575 B**、P **2,688 B**、G **3,251 B**。G 比 N 多 2,676 B/格，三格共多 8,028 B；G 的工具结果三格比 N 多 19,548 B。其中 G 原生结果 22,823 B、relation 结果 36,201 B；P 分别为 16,488 B、20,763 B。详见 [VISIBLE_BYTES.json](VISIBLE_BYTES.json) 及 [derive_visible_bytes.py](derive_visible_bytes.py)。

因此能确认 **schema 和结果两侧都扩大了可见数据**。不能把 G 比 N 多出的 9,328 个总 token 精确拆给二者：只有整 turn usage，没有按 schema/各次工具响应分段的 provider usage；重复上下文、调用次数、回答和 cache 命中也不同。wire 字节不能直接当 provider prompt 字节或 token。G 相比 P 的总 token 虽下降，但 cached input 也从 114,944 降至 84,352；无实际价格账单，不能据此宣称费用同比下降。

G 工具处理三格合计只占其完整时间约 0.31%。最后一次工具完成至最终回答的中位间隔 N/P/G 分别为 **29.774 / 27.629 / 31.485 秒**；这是公开事件之间的墙钟间隔，包含模型/传输/调度等未分解因素，不能称为纯推理耗时或插件传输耗时。

## 生命周期与成本范围

九格 `cell_ended_ns` 均在 `finish()` 等待 owner launcher 退出并核对 CLOSE 之后。native 原有 Popen 句柄 exit0/reap、WORKER_CLOSED、原期限及终态指纹通过；P/G 的产品 Peer launcher exit0/reap、reader 停止和 CLOSE 早于 cell end。完整 cell 计时确实包含这些已观测的终态步骤，未在答案生成时提前截断。

正式历史运行器没有单独保留 `PRODUCT_RUNTIME_PROOF`，因此只报告 **owner/native 关闭回执、actor/product launcher exit0**；不扩展为每个内部 runtime PID 都有独立退出见证。九格 thin-client 缺少 EXIT 回执，`confirmed=null` 全部保留；不能把未知薄连接退出改写成已测成功，也不能给未知的尾部资源成本填 0。

本轮是同一场景的每组 3 个新消费者；不据此声称跨场景普遍优势。按一次性合同收口，保留质量和部分时间收益，同时明确整体收益门槛未过，不在同题上追加样本或放宽门槛。下一方向应依据机制审的真实缺口决定，而不是把“差一点”改写为通过。
