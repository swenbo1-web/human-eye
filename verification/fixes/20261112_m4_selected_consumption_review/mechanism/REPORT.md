# 正式九格：同次 geometry 机制独立复核

**机制成立：G 三格都自然请求并正确使用同次几何，关系集合内的局部形状补查由 P 的3次降至0次。实际工具往返由9次降至7次，只有两格省掉一整次调用；G 与原生 N 都是7次。机制通过不等于完整净收益通过。**

固定实施证据 `de35ceda1f5e3f5af2c9ec02f0e4646808f417c2`。根与新独立评分者的9/9质量已在 `QUALITY_SEAL.json` 封存，本审不按工具路线重新打分。执行依据包括已冻结的 MECHANISM_CLASSIFICATION、BENEFIT 和根 PREP_REVIEW/GO 的补查解释。

## 本轮独立工作

逐格阅读原始请求、响应、实际公开完成事件和最终答案。离线脚本 `audit_records.py` 核116份来源记录摘要；23条 owner 结果的 content 与模型侧 completed 事件逐值相同、请求参数相同、无业务错误；按计时与序号绑定实际 worker 调用。原件前后未变。没有运行消费者代码、模型、Blender 或产品。

六条插件关系均绑定 N16 与 N13/N08/N28；P实际响应来源为53db，G为4eb。G三条均主动设置四对象 `geometry` 且 `include_triangles=true`；每条真实返回56个世界顶点、100个捕获三角面，对象ID与同响应关系绑定一致。不是给G追加说明或强制选择后的表现。

G03 的第三次 `bounds(objs['N16'])` 内部确实再次读取顶点以算中心。因此“没有同域局部形状补查”不等于“没有任何集合内数据重读”或“没有新采集”。按GO，重复中心/简单距离是单列类别；其调用和内部工作没有从成本中删除。

P三条后补形状均是先前未完整向模型交付的形状信息，不宜统称无用的“冗余验证”。本轮未发现插件路线在获得关系结果后再次运行三对完整碰撞/最近距离求解。P04从已有程序缓存打印几何与G的同次交付之差，是模型获得信息的时点和一次调用，不是新场景采集次数。

## 如何确认 G 确实用了附件

三格的首次原生返回均只有全场范围/中心及少量相机信息，未向模型交付N16完整顶点/连通关系。随后geometry实际包含N16孔内 X约[0.135,0.225]、Z约[0.325,0.395]，右框材及贯通厚度，并带N28实际截面和三角面。

三份答案都用这些孔与实体区间解释探杆处于空隙，并给出右框材共同内部点约(0.245,0.100,0.360)；也正确采用闭合体分类、边界交叉和间隙见证。该形状解释不是仅抄“separated”，也不只来自最初N16外包围范围。sgc05/07没有后续读取可提供这些局部形状，sgc03后续读取只增加参照形状/中心。与已封存的质量核验共同支持三格正确采用附件。

这支持完整局部几何信息的实际使用，不意味着56顶点、100三角面每一项都必不可少；不能从最终答案反推模型内部读取了每个三角。原生程序中暂存过数组也不自动等于模型已见数组。

原始证据在每格 `owner/tool_02/{REQUEST,RESPONSE}.json`、`events.jsonl` 与 `PUBLIC_FINAL.txt`；三条P补查和G03残余调用在对应 `owner/tool_03`。RESULTS逐格保留完整指针、源码上下文、几何计数、形状值和分类。

## 冻结门槛与成本含义

- 自然正确采用并避免同域补查：G **3/3**，达到至少2/3。
- 同域补查：G **0**，P **3**；严格下降，机制门槛通过。
- 总工具调用：N **7**、P **9**、G **7**。G对P在三轮分别少0/1/1次，合计少2；对N分别多1/少1/相同，合计没有减少。
- 物理worker RPC含初终snapshot和close：N **16**、P **18**、G **16**，共50。三个口径不能互换。

成本子审 `cost/RESULTS.json` 的正式结果为：G完整中位67.174秒，相对P低8.91%、相对N低11.55%；实际input+output总量G157270、P167637、N147942。故对P改善没有达到预定10%，对N时间改善伴随token增加6.31%，两个冻结净收益比较均未通过。这里引用成本独立结论，不把机制通过覆盖它。

本审自行重算的完整工具响应字节为N39476、P37251、G59024。G比N多19548B（约49.52%）；成本子审另核单格工具目录线缆字节为N575、P2688、G3251。可见构成是G仍做一次原生全场范围读取，再交付关系/来源/见证和完整geometry，并携带两个额外工具定义；N可在这个规则几何任务里用短原生程序、顶点/多边形与解析推导直接完成。G03还选择了较展开的首轮JSON和一次参照补读。

这些是实际可见的字节/路线构成，不是provider逐字段token归因。G相对P虽然响应字节更多，少两轮后实际token仍下降6.18%，说明只看线缆压缩会漏掉重复上下文和调用轮次成本。没有分段provider usage，不能把相对N多出的9328 token精确归因给schema、geometry或某次模型推理；缓存子集也不能从既定总token门槛中事后扣掉。
