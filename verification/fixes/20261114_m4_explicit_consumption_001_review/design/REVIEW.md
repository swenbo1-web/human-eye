## 本次已证实什么

首包文本 42049 B，其中 regions 20114 B、pixels 16863 B。主要信息是 138 行区域表和 414 行像素表。模型收到后公开说 “The first pass leaves gaps”，随后先检查 geometry/cameras 和 Python globals，再从原始网格重新发现所有区域并请求六视图。

覆盖数组已经给出 115 covered、23 unresolved；23 unresolved 与 candidate_pool_uncovered 完全相同，因此仍具有几何完整候选但未观察的区域数为0。这个事实需要消费者理解两组名称、求差并理解有限池语义才能得到。产品的顶层 `status=complete` 只说明此次请求完成，不能说明全部区域均观察；区域又全部使用 `unknown / finite_camera_pool_uncovered`，没有直接输出当前有限池的具体停止理由。

真实剩余是22个没有正面视角、1个在六视角中受遮挡。23个仍然是未观察区域，域外 triangle 48 仍是未支持组件。不能把这些状态改成已观察或一般意义的任务完全完成。

模型最终错误归入剩余的源面1133..1644，在产品表中为region index 7，世界中心 `[0.3515625,0,0]`，朝+Z。它的首个实际覆盖见证为BACK；首包像素行已有468表面像素、84边界像素、owned anchor `[263,224]`。该事实没有消失于传输，而是在后续原生重新计算和组表时没有正确合并。

## 交付中确实存在的语义缺口

`active_observation_images.py` 中像素 `readable` 的定义是正面且达到16/4阈值。`CoverageState.observe` 才将该集合与 `index.view_masks[view]` 相交，计入几何完整且可读的覆盖。

`ActiveObservationSession.short_facts` 输出 aggregate covered 和各视图 readable，但没有输出相应 `index.classifications` 或逐区域的完整视图见证。`live_spatial_mcp.project_active_observation_brief` 进一步使用区域、图像和像素三套局部索引。消费者可以看到结果，却需要自己理解“覆盖”与“像素可读”的关系，才能正确关联证据。

这个缺口不能冒称本次已有像素误放行：将当前414像素行映射到已独立核验的同源几何表后，161个readable=true在本场景全部也是complete，实际反例数为0。本次主要能观察到的是整体重算、证据关联丢失和最后答案缺失。后续可以用一个离线语义用例证明新投影不会把readable直接当complete，无需再跑真实消费者来制造反例。

## 唯一建议：消费接口组合修复

产品级目标是一个**已有判定与见证的投影**，复用现成 index、coverage state 和实际 receipt，不改发现算法、遮挡算法、选视角、像素阈值或观察次数，不增加独立框架。

1. 首包先给简短检查状态：支持区域数、已观察数、未观察数、仍有几何完整候选的未观察数、有限池停止理由，以及所指的相机池名称。当前应该是138、115、23、0和有限池已无几何完整候选；不要输出无限定的“全场景完成”。
2. 每个covered区域直接绑定一个确定的实际完整且可读见证：view/image index、表面/边界像素、owned anchor。见证从 `index.view_masks[view] & readable_mask` 取得，或在实际observe更新时记录首次覆盖视图；不要从readable单独猜。共用图像引用表，避免重复长哈希。
3. 未观察区域带有限池分类理由。直接读取已有 `index.classifications`，把无正面、遮挡、出视锥、缺像素等状态区分；各视角原因可用短状态组表示。保留unknown和原世界/像素定位事实，不从任务题面注入位置答案。

这些内容都已存在于本次引擎计算中，工作量只是有限表连接与集合统计。无需再次采集、渲染、构造网格或计算遮挡。先明确字段语义，再控制字节；不以删掉定位或未知信息换取压缩率，也不加长篇“相信工具”的提示。

当前共同Python命名空间没有产品fact对象，实际tool2也证实了这一点；bridge只把产品PNG加入image_files。`SERVICE_RESULT.json`虽然未向模型说明路径，但源码文件规则允许本槽output读取，因此不能说它被权限禁止。也不应把含内部诊断的full结果直接拿来补公有响应。

题面允许完整覆盖由actual tool facts承载，所以新JSON读取接口不是理论上的完成前提。但为避免模型为了程序化操作138行而重新录入或重建，建议同时做一个极小夹具桥接：将**已实际返回的public text block原文**作为不可变字符串 `last_observation_json` 放入已有Python namespace，工具说明用一句话告知可 `json.loads`。不新增工具、Store或文件协议，不提供任何未返回的解答、索引内部对象或额外几何API。调用成功时更新，失败不得伪装成新事实。

将这项明确登记为测试夹具的消费可用性变化，与产品投影分别记录源码、字节和处理成本。这一批如果同时通过，只能说明消费接口组合改善，不能宣称已经独立识别投影与namespace桥接各自的因果收益。它不等同正式MCP已自动获得Python结果记忆能力；正式宿主接入需另有证据。
