## 5. SAT 准入：真实去重可以降成本，但公式还不完整

`geometry_safety.py:29–34` 确实取 `max(显式边数, 3F)`。`84–97` 同时预算 VF、EE、FF、SAT 及 total；不能只把 SAT 估计缩小，便宣称整个几何对已经被正确计量。

`submodule_1_4_spatial_sniffer.py:347–356` 按主绝对分量统一轴符号，再 round(10) 去重；`359–435` 的 `_convex_shells` 同时完成拓扑、体积、凸性资格。`416–418` 仍需 `points @ normals.T`，实际有 `V × 唯一平面数` 成本。`422–427` 通过相邻面法向排掉共面三角剖分内部边，因此**经该准备路径的细分平面盒 Ue=3 可以成立**；若直接对原始 mesh.edges 求方向，斜对角线方向仍会出现。

`443–445` 再合并面法向及两壳边方向叉积。`Uf_a + Uf_b + Ue_a*Ue_b` 是投影轴数的上界，包含零叉积和重复方向，不能称精确实际轴数；多个凸壳还必须按壳对累计。边估计 `E=1.5F` 只适用于已证实的闭合三角流形边关联关系，不能提前替换对开放/非法/非流形输入的上界。

合理方案是分阶段准备、分项计量，并让精确准备结果直接供后续求解消费，避免“为了便宜准入先求解一遍”。预算要包含拓扑/凸性准备、VF/EE/FF、实际轴生成投影以及数值困难回退；原高坐标精度 unknown 不能被较低轴数自动解除。所谓 <0.25ms/O(F) 需要输入与完整计时边界支持，本轮未验证。

## 6. 浮点 Morton 剪枝：否定证明，不反对优化

报告 P0-3 的 `lower_sq*(1-1e-14)>best_sq` 只放松了下界比较。它没有证明 primitive 距离核在整个输入域内的舍入误差、上界属性或坐标消去误差。完整论证要同时约束下界和 incumbent；Morton 排序本身不提供这种保证。

离线例子已在共同局部坐标内：点 x=0，线段 [-1e16,-1]，原始二进输入的精确距离平方为 1。按旧点段残差形式，`delta=end-start`、`offset=p-start` 都舍入为 1e16，参数为 1，残差平方变为 0。AABB 下界平方仍为 1；若另一候选 incumbent=0.25，报告规则会剪去该候选，结果无法与旧残差值逐位相同。

**此例仅推翻固定松弛能证明旧核 0 ULP 的论证，不声称产品入口会接受该几何，也不把它登记为产品缺陷。新实现应服从真实几何与输出契约，而不是保存旧核的错误 0。** 可选择精确整数/有理下界、经证明的误差区间及困难情况精确求值；不要追加更多经验 epsilon。

另外：

- `geometry_safety.py:228–249` 的普通 `_surface_distance` 当前没有公共原点预减；`252–257` 的 witness 版有。报告“保留二者现有公共原点”的前提并不准确。给普通版新增原点本身就是数值行为改变，应单独说明。
- witness 的 `remember` 在 `261–268` 使用 `argmin` 和严格 `<`，相等时保留先遇到的特征。Morton 及优先队列重排会改变相同距离的见证；需要规范化 feature tie 或保持旧特征序。不应该把“距离相同”误报为“完整输出字节相同”。
- 当前 exact `surface_proximity.py:305–316` 的整数比较已有明确的等号不剪枝行为，可作为后续层级结构的基础，不需要经验松弛。
- 面数 384 门限是待复验候选，不是理论保证。“小场景零退化”应以同字节基线配对测量与预先声明噪声/回归界定义，不能从一次 0.25ms 四舍五入值推导真实 p95 必然不变。

## 8. 缓存与采集算术：保留最小有效约束

`blender_mcp_host.py:159–186` 已冻结实际源字节及 hash；`432–460` 首次传送源、后续复用同代 resident host。因而报告描述的每次 capture/apply 重编译不适用于当前普通采集路径。其他独立 helper 仍有重复读取/编译，可按各入口实测，不应再套一个跨路径 metadata 缓存。

mtime、size、路径、旧 expected hash 都可以保持相同而字节改变；lstat 不会证明内容。安全且更简洁的选择是明确 connector/source generation，缓存同份核验字节和编译对象；若接口承诺检查当前磁盘内容，仍需读取并比较。`verified_source_loader.py:116–125` 要求实际执行核验快照，`132–146` 检查加载身份，不能用新缓存顺便改变该承诺。

`live_service.py:681–710` 仍有按请求身份路径及 host source 检查：同一次读到的字节/摘要可以共享，**条件是同一来源、同一快照且不再次偷偷加载磁盘文件**；“同一 inode/路径所以旧哈希仍新鲜”不成立。

`blender_host.py:859–873` 的 scalar 世界坐标使用 `sum(...)`，随后生成排序边。无向边 `u<<32|v` 在顶点下标小于 2^32 且先转 unsigned64、避免 shift 溢出的条件下有直接整数等价依据，np.unique 顺序也能还原 lexicographic 顺序。批量 faces/coordinates 读取本身是有前景的优化。

但是坐标算术是另一问题。离线环境 Python 3.12.14 中 `sum([1e16,1,-1e16])` 是 1，而三项左结合是 0。即使某个实际 Blender Python 使用旧求和实现，负零也会令 `sum([-0.,-0.,-0.])+(-0.)` 的 JSON 为 `0.0`，直接左结合为 `-0.0`。因此必须固定实际宿主解释器并验证运算序、负零、异常值、变换/scale 和最终 revision，而不是依据 `foreach_get` 正确便推导变换字节相同。

`scene_rendering.py:168` 原表达式本身已经左结合 `projection @ view`；把该固定矩阵移到物体循环外是独立小优化。随后把 N×4 齐次矩阵乘换成三项 dot+平移，会改变 BLAS/归约/融合行为。即使视觉结果通常相近，也不是无需论证的 0 ULP 改动；需要验证 owner rectangle、裁剪、深度及像素结果，或者明确视觉误差契约。
