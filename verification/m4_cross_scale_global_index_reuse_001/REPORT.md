# 同代全场覆盖索引复用的三对工程验收

三个真实 Blender 配对全部达到质量与性能验收。每轮「有图简报 → 无图全量预测 → 重读首条」的全场索引构建次数从 **2 次降至 1 次**。无图预测的服务端 RPC 配对中位数缩短 **332.716 ms**，三请求整个窗口缩短 **329.622 ms**，完整独占窗口缩短 **379.678 ms**。

## 缓存范围与有效性

候选从已接受的局部首视角产品 `1dd2f77ecf19d51ba52aa5757e861ed930a58135` 直接分出。候选 `0802a532b4bce6465dd7647c0d68dcb2246c5ed3` 的 143 项运行来源直接与 Git 和 wheel 校验，139 项与基线逐字节相同。两边实际加载的工具目录相同。 [安装与字节核验](install/BUILD_INSTALL.json)

仅完整场景的 `region_task` 在可靠捕获代下用 `ReadContext.prepared` 保留一条私有 `CoverageIndex`。固定条目由当前读取上下文的文档、版本、对象实例与顺序、场景来源、选择和相机策略隔离。新版复用索引、分类和分区数据，共用的构建函数直接返回这份索引。区域任务继续解析当前几何、转换当前网格、生成当前相机，并在每次结果未命中时创建独立的观察状态。缓存命中还检查当前几何和相机标识。阶段时钟只记录当次实际发生的索引构建。

离线验证了两种请求顺序、筛选条件改变，以及场景重读、换代、同名替换、网格／姿态／顺序／相机或文档变化、选区和无版本。注入的工厂异常和索引计算期截止错误均在准备提交前被拒，随后重试会重建。已有的热结果和观察帧仍按原结果缓存合同使用。 [离线控制与 CPU](checks/INDEX_CONTROLS.json)

## 真实请求质量

六个独占 Blender 副本依预登记顺序完成 18 次公开请求和 18 次实际栅格。每端冷请求构造三帧，交付全场 `SCENE`、M02 `SCENE`、M09 `LEFT` 的相同三张原始 PNG。各自的当前帧引用、内容索引与原图可解析，独立重算得 M02 50,557／926、M09 146,797／1,530 个目标表面／对比边界像素。M06 保留六方向正面积遮挡的未知原因。

无图 `full` 的独立标准化输出逐对一致，均为 `prediction_only`，实际零图、零构图、零已有见证。两端都重新采集当前场景。基线重建全场索引，候选命中当前准备。第三条热读各自重用首条的原三个引用与 PNG，双方均新增零索引和零栅格。 [逐对质量与原回包绑定](checks/PAIR_REVIEW.json)
