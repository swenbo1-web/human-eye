# Installed integration and service-cost plan

This registry belongs to M4-VIEW-REUSE-001. The previous routed comparison is closed. Its product installation, frozen adapters, answers and measurements remain read-only. This batch runs no model consumer, GUI or Blender capture.

## Owners and denominators

The product author owns the focused ownership/readback matrix and affected unit tests. Its independent raw-ID raster oracle covers multiple objects, multi-triangle patches, unsupported/background, near/far, depth ties and clipped fans. This controller reads those first-run receipts and does not rerun that matrix.

The installed integration has twelve registered checks. Related checks share four fresh owners and their actual construction ledgers. The first owner uses the real installed product/adapter public observation entry. The native owner uses the same adapter's public render/read entry. Legacy-capability and publication-failure controls use separate owners. Expected actual rasters are 3, 3, 1 and 2 respectively, nine in total. Every failed construction is included. A genuine defect may justify a recorded correction and repeat of affected integration work, with all prior attempts retained. This is separate from the fixed cost sample.

1. Verify installed source binding and the first product observation's three actual frames and buffers.
2. Read SCENE three times after that observation. SCENE construction stays one and total product constructions stay three.
3. Verify cached array identity, stable references, unchanged PNG/NPZ publication and actual repeated image attachment accounting.
4. Construct native SCENE first, then repeat it through the ordinary public entry.
5. Request duplicate SCENE names in one batch, including explicit fresh mode. Each distinct requested view is constructed at most once in that batch.
6. Mix cached SCENE with BACK twice. Only the missing BACK is constructed.
7. Force fresh SCENE. Latest-by-view changes while the previous by-ref frame/buffer still denotes its original generation.
8. Verify raw-to-patch/object consistency and the installed first-frame buffers, using the focused independent ownership receipt as the separate kernel oracle.
9. Exercise existing source/pose/projection/size/object-order/owner-schema/mapping cache-validity gates. A rejected or invalidated old frame cannot be a hit. These are validity-gate controls without extra raster calls. Product rebind/size controls remain in the product owner's focused matrix. The fixed immutable replay adapter is not claimed to add a source-edit API.
10. Read an actual old raw-incapable frame without claiming raw availability. The adapter records capability miss, constructs one complete native SCENE, then reuses it.
11. Inject one publication failure after a real raster. The attempt remains charged, the incomplete frame is absent from the successful cache, and the next normal request recovers. A further read reuses that recovered frame.
12. Verify retained process/owner closure, source readback and all construction/publication/delivery ledgers.

The precise existing validity and legacy-registration methods are locked with the adapter author before source freezing. If that requires a new source-update or cache platform, the controller reports the missing contract and retains the bounded checks already supported. It does not fabricate a frame or mutate historical evidence to obtain a pass.

## Fixed paired measurement

There are five blocks, in order old/new, new/old, old/new, new/old, old/new. Each arm uses a separate process, owner, cache, manifest and construction ledger. The old arm uses the accepted routed adapter from the old checkout and the unchanged installed source6d4f at D:/he_consume_001/product. The new arm uses this batch's pinned adapter and isolated candidate installation supplied by the root.

Every arm performs exactly the same workflow. It creates the owner, calls active_observation with images, then requests SCENE with images three times. The new arm uses its default fresh=false contract. The old arm retains its original fresh contract. Expected actual rasters per arm are old6/new3. The 45 expected benchmark rasters are ten independent owner-ledger samples. They are not entered into one inherited44-entry ledger. Every owner retains its six-attempt limit. The controller separately totals actual task attempts and includes integration and failed attempts.

The first clock starts before bridge/native imports, owner construction, mesh/face arrays, raw-ID arrays or mapping preparation. Each checkpoint ends after the real owner tool handling, response encoding, actual local socket send/receive, observation-delivery callback and transport receipt. The worker and its parent also retain process-start/finish and cleanup clocks. Module/bootstrap and interpreter boundaries are labelled explicitly. No new array or cache may be prepared before the first window.

The transport is a product-free controller around the actual Owner.handle, encoder, complete_observation_delivery and record_transport methods. A local socket pair carries the actual encoded reply bytes. This measures local service/delivery work and does not claim a real model/CLI or provider reception. If the implementation instead uses the unmodified actor server, the source freeze records that exact entry and retains the same checkpoint boundaries.

For every raw sample record first, first-plus-one-repeat and first-plus-three-repeat cumulative windows, all individual request windows, raster/PNG/NPZ counts, published array payloads, unique array objects where observable, raw int32 bytes, compressed files, image/base64/JSON/wire bytes, source guard and cleanup. Encoding and reattachment count on hits even when raster/file publication is zero. Existing construction costs never decrease after failure.

The added raw buffer has 512*512*4 bytes per frame. That is one MiB for an array and three MiB for a three-frame observation. Actual in-memory copies/shared references, compressed files and transient memory are reported separately. RSS and allocator peak are unknown unless a reliable existing counter exposes them.

## Selection and stop rules

All five blocks and both arms stay in the denominator. No warmup, extra sample, best-subset selection, model request or silent retry is allowed. A common-source/interface failure or unknown real process state stops later work and records it as not_run. Ordinary failed work retains its elapsed window and original exception. A fixed cost sample is not replaced after failure.

Report the complete first-cost table before cumulative results. Report first tax, all five paired raw values, median and sum, and any reverse sample. Report whether one repeat and three repeats amortize the observed first tax. The engineering condition is lower cumulative service cost for the repeated workflow, with correctness and memory costs disclosed. No p95, significance, complete-model latency, token or cash saving is inferred. No product is installed as the default by this controller.

Root freezes the candidate commit, installed binding, input bytes, this plan, all executable helpers and the pre-measurement source map before the sole measurement. This file registers design and does not authorize an early run.
