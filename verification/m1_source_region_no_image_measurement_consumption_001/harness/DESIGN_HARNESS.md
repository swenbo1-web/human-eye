# Same live launcher, two installed evidence endpoints

The implementation reuses the accepted witness-consumption live chain. The
public command remains `run_slot.py QA|QB|A1|B1`; `--dispatch-smoke` prepares only
the module dispatch and reports its paths. Root owns admission, preparation
execution, qualification, orchestration, source freeze and actual slots.

Both arms are group P. A uses installed 1535d08a / cdee3254, B uses installed
34372f04 / 338f4841. Both actual production processes receive
`--region-task-evidence`. Each arm checks its original binding, 143-source
identity, actual tools/list and common observe input schema. Separate A/B
catalogue snapshots preserve the candidate's real description intervention.

Eight harness files are copied narrowly from
`m1_region_task_witness_image_path_consumption_001`. Seven preserve the original
bytes; common.py changes the new run root, exact A/B identities and per-arm
catalogues. The literal consumer thin transport is unchanged. The consumer
driver changes only its task proof label, episode label and fixed prompt hash.
It retains the actual CLI 0.152.1 / gpt-6.1-sol / medium / default loop, the
shared 12-business-call limit and original 450/600-second deadlines.

The prior dense launcher calls the current Runtime, Owner and diagnostic via
the same established injected module paths. Runtime captures each initial and
terminal source from its fresh owned read-only Blender copy. Parent performs
the only actual launch. Nothing here starts a Blender or a model during source
preparation. An installed formatter wrapper saves the very same service result
object before formatting; Runtime forwards original arguments and replies and
correlates the archived result to each original wire request. No tool call,
scope, detail choice, result or answer is rewritten.

Evidence layout is unchanged under the new external root:

- `slots/<label>/product_calls/call_NNN/{REQUEST,RESPONSE,RECEIPT}.json`
- `slots/<label>/product_full/call_NNN/{SERVICE_RESULT,READ_CONTEXT}.json`
- `slots/<label>/mcp/rpc_XX/{TX.bin,RX.bin,RECEIPT.json}`
- `slots/<label>/mcp_io/{RUNTIME,EOF,WORKER_EXIT}.json`
- `slots/<label>/owner/tool_XX/` original requests, replies and product binding
- `slots/<label>/consumer/{CONSUMER,BUSINESS_SOURCE_BINDING}.json` and original
  transport, attachments, events and `PUBLIC_FINAL.txt`
- original `SLOT_RESULT.json`, `SLOT_PUBLICATION.json`, runtime/native proofs,
  current source captures, read-only audit, frame-device and budget records

Cost summaries are post-run root/trace work and are not generated by a launch
adapter. No public answer or truth is placed in the model workspace. Existing
ordinary-Python read scope still permits only its scratch and reviewed runtime
dependencies; native Blender scope similarly restricts source and writes.

Production close preserves the held process's exit, reader termination, closed
pipes/handle and raw stdout EOF. It separately requires same-PID installed
source evidence, input EOF, original service/host close and returned production
exit code 0. Missing or bad receipts do not become successful closure.

Preparation to this point is static AST/hash/diff only: zero product processes,
zero business calls, zero Blender, zero raster and zero model consumers. Root's
subsequent dispatch/closed-worker preflight and actual qualification must be
recorded separately.
