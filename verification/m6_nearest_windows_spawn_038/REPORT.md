## 两道准入门与真实进程控制

原 `pair_measurement` 按源、算法、配对次序、参数和当前读绑定构造真实键。正常命中提升 LRU，有效结果原序写回，同时受条目及字节额度约束。实测反例证明前一对 P 的写回可逐出预查时仍在缓存的 Q。即使 P、Q 初始互异且均缺失，原 `surface_nearest_result` 在 P 写回后的检查或 Q 的前置检查仍可按同一绝对期限退出；P 计算异常也会使 Q 从未获准。缓存必要性不能证明未来求解已获准，固定前缀下只能跟随原串行。逐出、unknown、不缓存、绕过、来源版本、等距和原预算控制均通过。 [准入证明与反例](admission_proof.md)

单 Worker 仅在原同步计算真正发生后派发，同一请求最多一个在途对。父进程握手验证子进程使用同一 Windows QPC 时钟域，将原绝对期限和源、读代、配对键绑定至不可变字节。子进程调用原内核，没有可变共享缓存。主样本共实际派发、开工、完成、接受各 104 次，丢弃 0，三个请求各自启动并回收一个进程。两次暖查均未启动进程。

实测 Worker 进程小型控制覆盖派发前余量不足、计算异常、核内到期、晚收、来源失配和有效接收。通过 stock MCP 对 D48 第二对施加真实进程故障、来源失配、成功但晚到时，每个请求的首对仍在缓存，第二对均被丢弃且不入缓存，第三对及以后未派发，无自动重算或成功发布。所有拥有的 Worker 关闭 IPC、退出码 0 并被回收。全场阈值扫描另外通过原串行的配额、unknown／deferred、续查、字节交付和截止回归，扫描 Worker 为 0。
