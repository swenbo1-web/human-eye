## 为什么保留串行

原缓存的条目和字节逐出可令晚一点的候选从命中变为未命中。独立原始反例还显示，即使 P/Q 的初始键互异且均缺失，P 写回后到期、Q 前置到期或 P 异常都会让 Q 从未进入原串行求解。按序接收无法撤回提前开工。原阈值扫描的六个预算、`unknown/deferred` 和续查控制保持串行、零 Worker。[准入证明与反例](admission_proof.md)

三种故障通过原 MCP stdio 处理器的内存流和真实 Windows Worker Pipe 注入。每例两对派发、首对保留、次对丢弃，后续零派发且无自动重算，原终态为两个 `error` 和一个 `expired`。迟到结果在清理时才收到且未写入。IPC 和进程均回收。控制覆盖所测故障，不构成任意半帧、挂死或真实客户端取消的保证。首主槽的 CPU API 问题及首故障评分误读均保留在原件。复核仅检查原件和重算账本，未启动新 Worker 或 Blender。

本轮到此暂停。普通 Blender 原型、真实宿主编辑失效计时、正式六轮、移交和部署均未开展。
