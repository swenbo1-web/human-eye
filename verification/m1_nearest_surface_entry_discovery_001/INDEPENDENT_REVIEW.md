## 改动和可用性

A 为 `4225256485a82a9ddbdeeca61e1bbd3275574a6e`，B 为其直接子提交 `2f7f492d7d0fd1af2ff956228d31bd57b5e31ddc`。分别将 146 个运行源与该提交、wheel 和安装文件逐一核对。替换已有观察工具顶层说明的单个字符串常量后，两版源文件语法树相同。两次正式配对各自收到的五项工具目录也仅此处不同。新说明从 3,448 增至 3,893 个 UTF-8 字节，新增可直接解析的 JSON 调用示例及例子适用的证据范围。

在两版已安装端点的无模型预飞原件中，各用示例代入目标和参照。对 Module C，第一幅 SCENE 图含较近矩形片 84,109 个像素；对 Module D，第一幅 SCENE 图含较近三角片 25,165 个像素。每题的 A/B 原 PNG 同字节，例中锚点与 NPZ 的所有者及源三角相符，求距命中源对分别为 3/0 和 2/0。示例能交付全局最近距离、一个合法命中面和它的图，比较另一片需要相应数据。

## 后续问题

这次两道题都要求两个数，而主动取景的一份回包只直接证明较近片的数。模型选择逐片量测与题目契合；本批无法据此区分入口的可发现性与任务对第二个距离的需求各占多大影响。

建议下一项先固定安装和顶层说明，用新几何做最小自然对照。一个题面只要求找到最近片并用首图、可查像素作证；另一个只增加“分别报告两片间隙”。比较首次定位是否在读取源三角前发生、同帧是否进入最终答案，以及另一次量测补足了什么。如果只有比较题需要先枚举，再评估增加按需逐连通片量测的价值。当前结果未达到合入此文案的采用门槛。
