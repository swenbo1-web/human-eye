# 公开请求与生产者归档关联修复候选

原关联逻辑漏掉了 MCP 前置校验拒绝这一分支。A1 的 `observe-2` 被原产品拒绝，随后两个有效回复已到达内部 MCP 客户端。公开请求序号继续递增，service 归档序号保持独立，冻结 harness 的等值检查把两个有效回复替换成了归档错误。

本目录复制冻结运行器，只修改外部归档关联。原产品、冻结 harness、原始记录及本批样本保持原字节。

## 候选行为

- 分别保留公开请求序号和实际 service 归档序号。
- 读取调用前后的原始 INDEX 字节，核对原前缀保持及本次新增条目。
- 一个有效回复须关联一条新增条目，生产者始末须落在本次原客户端调用窗口内。
- 核对实际归档路径、独立 service 索引及内容 SHA。服务异常造成的索引空缺可以保留。
- 前置拒绝且无新增归档时，原错误照常返回，生产者索引记为 null。
- 缺失、重复、新增多条、跨请求、跨槽、内容改变或不完整 INDEX 明确退出。有效的 observed 和 partial 回复保留原对象及内容。
- 保存每次关联的前后字节快照、实际生产者索引和关联错误，供后续审计追溯。

## 保存层验证

`PURE_01/RESULT.json` 的 19 项检查通过。A1 原件回放得到 `observe-1 → 1`、`observe-2 → null`、`observe-3 → 2`、`observe-4 → 3`。完整运行器 mock 覆盖前置拒绝、后续 observed、后续 partial，以及原错误和原有效回复的透明返回。

上述回放的 INDEX 快照由原始最终 INDEX 的精确字节前缀派生，并按原请求窗口选择。原件保持原位置和内容。测试执行保护记录为零次实际 Blender、MCP、模型和 raster 启动。

## 本批停止记录

根代理保留当前在途槽并让其正常关闭，在 B3 的独占输出目录放置停止记录。正式驱动据此记录 B3 的 `FileExistsError` 和 dispatchfailed，结果与发布路径均为 null。B3 的预算 claim、owned 启动和模型消费者均为 0。

`PROCESS_CLOSURE_CHECK.json` 核验了两次资格与五次正式的七个 owned 闭包。五个 CLI 的 Popen exit 均为 0。五个薄 Python 适配器的持有退出均为 1，EXIT 回执缺失，两类进程证据分别保留。Actor、产品 MCP、Blender 的持有关闭和全场终态恢复检查通过。
